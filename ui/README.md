# recon-ui — local web control plane

A single-operator web UI for the recon pipeline. FastAPI backend (WSL) + React SPA,
served on `http://localhost:8787`. It **wraps** the existing surface — shells out to
`recon_ctl.sh` / `engine/state.py`, reads `findings.db` + ES `recon_alive` + the
`~/recon` files — and adds **no** pipeline logic. The CLI/daemon stay the source of truth.

## Run — always-on service (recommended)

Installed once as a **systemd user service**: auto-starts on WSL boot (linger is on),
auto-restarts on crash. You never start a server by hand.

```bash
recon ui install     # generate token, build SPA, enable + start the service (boot-persistent)
recon ui status
recon ui logs [N]
recon ui restart
recon ui token       # print the access token to paste into the UI once
recon ui uninstall   # disable + remove the service
```

Then open **http://localhost:8787** from the Windows browser (WSL2 localhostForwarding
carries `127.0.0.1:8787` to the WSL backend under `nat` networking). Paste the token once
(stored in the browser); the UI stays unlocked.

Unit: `ui/systemd/recon-ui.service` → `~/.config/systemd/user/recon-ui.service`. If the
service isn't installed, `recon ui start|stop` fall back to a detached `setsid` process.

## Layout

- `backend/` — FastAPI app (`app.py`) + data access: `runner.py` (CLI), `findings.py`
  (SQLite ro), `es.py` (recon_alive), `files.py` (briefings/notes), `daemon.py` (status),
  `safety.py` (token + confirm + fail-closed VPN gate), `config.py` (paths/auth).
- `frontend/` — Vite + React + TS + Tailwind SPA. `npm run dev` proxies `/api` → `:8787`;
  `npm run build` emits `dist/`, which uvicorn serves (single origin, no CORS).

## Security

Threat model for a loopback control plane is DNS-rebinding and CSRF-from-a-tab. Layers:

- **Loopback bind only** (`127.0.0.1`), never a routable interface.
- **Host-header allowlist** — only `localhost:8787` / `127.0.0.1:8787` are served (a
  rebinding page can't forge the Host header) → 403 otherwise.
- **Token on every `/api` route** (reads included). Token in `~/recon/state/ui_token`
  (chmod 600, generated by the launcher outside the service sandbox). The static SPA
  loads without it, then prompts once and stores it in the browser. WebSocket carries
  the token as a query param (browsers can't set WS headers).
- **CSRF-proof mutations** — the `X-Recon-Token` custom header forces a CORS preflight
  we never grant, plus an explicit `Origin` allowlist check and a `{"confirm": true}` body.
- **Fail-closed VPN gate** — target-facing actions are refused when `~/recon/state/vpn_down`
  exists (same rule the daemon uses).
- **Hardened headers** — CSP `default-src 'self'`, `X-Frame-Options: DENY`, nosniff,
  `Referrer-Policy: no-referrer`, COOP; uvicorn version banner stripped.
- **Sandboxed process** — systemd user unit runs as `d0k` with `NoNewPrivileges`, all
  capabilities dropped, `ProtectSystem=full`, `PrivateTmp`, `RestrictAddressFamilies`,
  `MemoryMax=1G`. The web process **never escalates**; P4 hunt lanes (which need
  `reconrun`) are dispatched via the daemon queue, not by the web process sudo-ing.
- Secrets (ES password, API keys) never leave the backend; ES `_source` is field-whitelisted.
- The backend never touches egress/nftables/VPN.
