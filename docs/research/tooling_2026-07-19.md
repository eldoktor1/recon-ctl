# Research digest — tooling — 2026-07-19

## Tooling Watch — 2026-07-19

**Context:** in-flight work on `engine/recon_cognito_apks.py` (APK-based Cognito recon) makes this run's two strongest hits directly actionable right now.

### 1. Titus (praetorian-inc/titus) — **EVALUATE, high priority**
CLI/Go-lib/Burp-ext/Chrome-ext secrets scanner, 487 rules (derived from NoseyParker + Kingfisher), Apache 2.0, 638★, last release **2026-07-15** (4 days ago). Natively extracts+scans secrets from **APK/IPA, Office docs, PDFs, archives** — trufflehog has no binary/mobile-extraction step, so today that gap is filled by hand-rolled unzip+grep. `--validate` does live-credential verification (read-only, confirms/denies/unknown) — same semantics as our `trufflehog --only-verified` gate, so it slots into the CONFIRMED-secret pipeline without a new FP model.
- Fits doctrine: unauth-safe (validation is read-only outbound calls to the credential's own API, not the target), dup-resistant (few crowd hunters run binary-extraction secret scanning on mobile clients).
- Verdict: **EVALUATE now** — run it over the APKs already being pulled for the Cognito lane before hand-building extraction in `recon_cognito_apks.py`; keep trufflehog for the git-history/GH-leaks lane (different corpus, no reason to replace it there).

### 2. OpenFirebase (Icex0/OpenFirebase) — **EVALUATE**
Extracts Firebase config from APK (DEX string pool + resources)/IPA (`GoogleService-Info.plist` + Mach-O scan)/web, then probes Firestore/RTDB/Storage/RemoteConfig/CloudFunctions for unauthenticated read+write and hardcoded service-account-key leaks (incl. PEM private-key recovery from iOS binaries). 55★, last release **2026-04-29**, Python.
- We have `class-firebase.md` in KB but no dedicated extraction+probe tool — this is a genuine gap-fill, and it lands right on top of the APK recon work already underway.
- Write-access checks use a benign marker payload (`OpenFirebase_write_check`), same non-destructive pattern as our bucket-scanner `writecheck` — per doctrine that write path should be **operator-on-demand**, not folded into the autonomous unattended loop; read-only probes are fine autonomous.
- **Caveat:** license is custom **NC (non-commercial) 1.0.0** — confirm this doesn't create friction before wiring it into automated/for-profit bounty workflows (likely fine for personal research use, but flag it, don't assume).
- Verdict: EVALUATE — trial read-only mode against Firebase-backed APKs first; gate write-checks behind operator confirmation like `recon-buckets confirm`.

### Checked, no genuine upgrade found (SKIP)
- **API route discovery**: nothing beats kiterunner in open-source form — 2026 alternatives (StackHawk, Levo, Akto) are closed-source SaaS, not a fit.
- **IDOR/BOLA scanners** (Auto-IDOR-Hunter, IDOR-Forge, IDORD, apidor): all are blind ID-swap/pattern tools requiring either a live Burp session or guessed-ID enumeration — conflicts with our 2-owned-account human-confirm hard line, low-adoption/unclear maintenance. praetorian-inc/hadrian is more credible (role-based YAML authz testing, REST/GraphQL/gRPC) but requires configured multi-role auth.yaml — i.e. it's an **authenticated, human-in-the-loop tool**, not an autonomous-lane fit; possible future candidate for the Claude-in-Chrome authed-testing flow, not adopting now.
- **Subdomain takeover**: no new tool with concrete evidence of being better than our current fingerprint-based confirm primitive; results were mostly stale/low-star forks.
- **GraphQL scanners** (InQL, graphql-cop, davidfortytwo/graphql-scanner): all just flag introspection-enabled/DoS-style issues — exactly the Info/dup-FP our reasoning-based `recon_graphql.sh` worklist already solved; no upgrade.
