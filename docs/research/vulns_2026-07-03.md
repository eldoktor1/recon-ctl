**CVE-2026-34908 / 34909 / 34910 — Ubiquiti UniFi OS Triple RCE Chain (KEV Jun 23)**
- **What:** Auth-bypass (34908) + path traversal arbitrary file read/write (34909) + OS command injection (34910) chain → unauthenticated root RCE on all UniFi OS-powered devices (Cloud Gateways, Network Controllers, Protect NVRs, Access Hubs).
- **Affected:** All UniFi OS firmware before June 2026 patch.
- **Detect unauth:** Bishop Fox released `BishopFox/CVE-2026-34908-check` — single GET probe to the vulnerable nginx-routed path; response pattern confirms vulnerable / patched / inconclusive. No exploit required for detection.
- **In-range-verifiable unauth:** YES — detection script is safe/read-only.
- **Pipeline:** CRITICAL. We have 4,600+ UniFi consoles in ES. This is **NOT** the fanout-suppressed product-class IDOR lane — it is device-level RCE. Run against in-scope+paying UniFi OS hosts immediately via `recon-nday`. Shared-tenant hard line still applies; operator-owned or directly-accessible consoles are the target.
- **Sources:** https://bishopfox.com/blog/popping-root-on-unifi-os-server-unauthenticated-rce-chain-detection-analysis · https://github.com/BishopFox/CVE-2026-34908-check

**CVE-2026-48907 — Joomla JCE Extension Unauthenticated RCE (KEV Jun 16, CVSS 10.0)**
- **What:** JCE editor profile-import endpoint accepts unauthenticated POST; 3-step chain (CSRF token → POST malicious .xml.php → GET webshell path) achieves PHP code execution.
- **Affected:** JCE 1.0.0 – 2.9.99.4; fixed in 2.9.99.5.
- **Detect unauth:** GET `/index.php?option=com_jce` → 200 with editor UI confirms JCE present. Version via admin manifest. Nuclei template submitted to projectdiscovery #16379.
- **In-range-verifiable unauth:** YES.
- **Pipeline:** Query ES for any Joomla hosts. If found, race-window item — KEV + CVSS 10 + public PoC (`ywh-jfellus/CVE-2026-48907`).
- **Sources:** https://www.yeswehack.com/news/rce-joomla-content-editor-extension · https://github.com/ywh-jfellus/CVE-2026-48907

**CVE-2026-1357 — WPvivid Backup & Migration ≤0.9.123, Unauthenticated RCE (CVSS 9.8, ~900k installs)**
- **What:** `openssl_private_decrypt()` fail-open (returns `false` → treated as null AES key) + unsanitized path traversal → arbitrary PHP file write into `wp-content/uploads/` via unauthenticated POST. Requires "receive backup from remote site" feature enabled (default in many backup setups).
- **Affected:** ≤ 0.9.123; fixed in 0.9.124.
- **Detect unauth:** Plugin version at `/wp-content/plugins/wpvivid-backuprestore/readme.txt`. Nuclei template at `halilkirazkaya/CVE-2026-1357`.
- **In-range-verifiable unauth:** YES.
- **Sources:** https://www.bleepingcomputer.com/news/security/wordpress-plugin-with-900k-installs-vulnerable-to-critical-rce-flaw/ · https://github.com/halilkirazkaya/CVE-2026-1357

### TIER 2 — CRITICAL / UNAUTH / CONFIG-DEPENDENT OR NARROW VERSION

---

**CVE-2026-42945 ("NGINX Rift") — Heap Overflow in ngx_http_rewrite_module (Exploited in Wild)**
- **What:** 18-year-old heap buffer overflow via crafted URI when `rewrite` uses unnamed PCRE captures (`$1`/`$2`) with `?` replacement followed by another `rewrite`/`if`/`set`. Trivial DoS; RCE demonstrated on x86_64/ASLR-off.
- **Affected:** NGINX 0.6.27 – 1.30.0; Plus R32–R36. Fixed in 1.31.0 / 1.30.1.
- **Detect unauth:** `Server: nginx/<version>` header — any version ≤ 1.30.0 is in range. **Config dependency:** only exploitable when a `rewrite` with unnamed capture + `?` is present — version fingerprint = LEAD, not CONFIRMED until config known.
- **In-range-verifiable unauth:** PARTIAL — version is unauth; exploitability requires config knowledge.
- **Sources:** https://nginx.org/en/security_advisories.html · https://github.com/depthfirstdisclosures/nginx-rift

**CVE-2026-9256 — NGINX Buffer Overflow, ngx_http_rewrite_module (broader range)**
- **Affected:** 0.1.17 – 1.31.0; fixed in 1.31.1 / 1.30.2. Same config-dependency caveat.

**CVE-2026-42530 — NGINX HTTP/3 Use-After-Free**
- **Affected:** 1.31.0 – 1.31.1 only; fixed in 1.31.2. Detect: `Alt-Svc: h3` header.
- **Source:** https://nginx.org/en/security_advisories.html

**CVE-2026-23918 — Apache HTTP Server 2.4.66, HTTP/2 Double-Free (DoS/RCE)**
- **What:** Double-free in `mod_http2` on HEADERS+RST_STREAM sequence. RCE demonstrated on Debian (mmap default). **Very narrow range: 2.4.66 ONLY.** Requires multi-threaded MPM + mod_http2 enabled.
- **Detect unauth:** `Server: Apache/2.4.66` header — exact version only.
- **In-range-verifiable unauth:** YES — version in Server header if not suppressed.
- **Sources:** https://thehackernews.com/2026/05/critical-apache-http2-flaw-cve-2026.html · https://security.berkeley.edu/news/critical-apache-2466-http2-flaw-allows-rce-dos-cve-2026-23918

**CVE-2026-6722 — PHP SOAP Extension Use-After-Free (CVSS 9.5)**
- **What:** UAF in SOAP extension's object deduplication on `apache:Map` duplicate keys → unauthenticated RCE against any exposed SOAP endpoint.
- **Affected:** PHP 8.2.x < 8.2.31, 8.3.x < 8.3.31, 8.4.x < 8.4.21, 8.5.x < 8.5.6. NOT 7.x or 8.1.x.
- **Detect unauth:** `X-Powered-By: PHP/8.2–8.5` + GET `?wsdl` endpoint returning XML. PoC circulating.
- **In-range-verifiable unauth:** PARTIAL — version unauth; requires publicly-accessible SOAP endpoint. Treat as LEAD until `?wsdl` confirmed.
- **Sources:** https://securityonline.info/php-security-patch-rce-soap-cve-2026-6722/ · https://pinaka.sh/blog/cve-2026-6722-php-soap-use-after-free-rce/

**CVE-2026-34475 — Varnish Cache < 8.0.1, URL Mishandling → Cache Poisoning / Auth Bypass**
- **What:** Mishandled root-path `/` requests in `unchecked req.url` scenarios → cache poisoning or auth-boundary bypass. CVSS 5.4 — lower severity but directly intersects our WCD lane.
- **Detect unauth:** `Via: 1.1 varnish` + `X-Varnish:` headers confirm presence. Version ≤ 8.0.0 in range.
- **In-range-verifiable unauth:** YES — Varnish headers reveal version in some configs.
- **Source:** https://security.glexia.com/cves/CVE-2026-34475
