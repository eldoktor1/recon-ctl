# Research digest — vulns — 2026-09-17

## 1. NEW — Web Cache Deception against APIs: concrete CDN normalization matrix + 2-request test — directly extends our WCD lane, matches our top-tech CDNs ★★★
- **What:** Published research (Rxkov, blog.mago.team, 2026-09-06) documents which CDNs normalize URL paths *before* evaluating cache rules vs which don't. **Cloudflare, Fastly, and Google Cloud do NOT normalize** (Azure/CloudFront do) — this is the exact gap that makes a delimiter-confusion path cacheable when the origin still routes it to a sensitive/authenticated handler. **Cloudflare + Google Cloud CDN are both on our own top-tech list** — this isn't generic, it targets our actual fronting infra.
- **Delimiters demonstrated:** `;.css` (matrix-param, e.g. `/api/profile;.css` — Spring MVC-style routing ignores the `;param`, CDN caches by `.css` suffix), `%23.css` (encoded fragment), and a real ChatGPT-ATO-class vector `/share/%2F..%2Fapi/auth/session` (CDN wildcard-caches pre-decode, origin decodes post-cache).
- **Also cited:** CVE-2025-61598 (Pingora, CVSS 8.4) — default cache key was URI-path-only, excluding the Host header, so responses from *different origins* landed in the same shared cache. Fixed in Pingora v0.8.0; worth a version check if any in-scope host fronts through Pingora.
- **Safe detect method (fits our SAFE-only WCD doctrine directly):** two-request diff, no poisoning of the real cache (own cache-buster per our existing `recon_wcd.sh` design): (1) authenticated request to a sensitive endpoint + delimiter suffix (`.css`, `;.css`, `%23.css`), record `Cache-Control`; (2) unauthenticated replay of the *same* URL — `X-Cache: HIT` (or `Age > 0`) on a user-specific endpoint confirms the deception without ever serving the poisoned response to a real user.
- **Action:** extend `recon_wcd.sh`'s delimiter set to include `;.css` and `%23.css` (currently likely just extension-suffix probes — verify), and weight Cloudflare/Fastly/GCP-CDN-fronted hosts higher than Azure/CloudFront since they're confirmed non-normalizing.
- **Source:** [DEV Community — Web Cache Deception Against APIs](https://dev.to/roxdavirox/web-cache-deception-against-apis-cdns-cache-what-backends-serve-privately-339c)

## 2. WATCH — Optimole (WP plugin, HMAC-"protected" REST endpoint) — 3 chained unauth stored-XSS CVEs, different bug shape than this month's file-upload run
- CVE-2026-5217 / CVE-2026-77365 / CVE-2026-84829 — unauthenticated stored XSS in `/wp-json/optimole/v1/optimizations` via unescaped `s`/`a` params and image-tag-attribute injection. Notable pattern: the endpoint is HMAC-signature-gated, but the signature+timestamp are exposed in the frontend HTML, so the "auth" is bypassable by any visitor — a reusable lesson for any REST endpoint we see gated by a client-visible HMAC. Low priority to chase (self-XSS-adjacent, stored-XSS payload needs a visitor to view the poisoned image), but cheap fingerprint: `optimole`/`optml` in jsintel + version <4.2.12.
- **Sources:** [SentinelOne CVE-2026-5217](https://www.sentinelone.com/vulnerability-database/cve-2026-5217/), [strix.ai CVE-2026-84829](https://www.strix.ai/cve/CVE-2026-84829)
