# Research digest — vulns — 2026-07-11

## Vuln/CVE + Writeup Watch — 2026-07-11 (last ~7-14 days)

### 1. NGINX Rift — CVE-2026-42945 (unauth heap overflow, ngx_http_rewrite_module) — **directly hits our fingerprinted tech**
- **What:** 18-year-old heap buffer overflow in `ngx_http_rewrite_module`, triggered by unauthenticated crafted HTTP requests. Root cause: inconsistent length-computation vs. copy logic when a rewrite directive uses an unnamed PCRE capture (`$1`/`$2`) with a `?` in the replacement string, followed by another `rewrite`/`if`/`set` in the same scope. CVSSv4 9.2. Public exploit PoC exists (`depthfirstdisclosures/nginx-rift`), and it has been seen under active exploitation days after disclosure.
- **Affected versions:** NGINX Open Source **1.0.0 – 1.30.0** (fixed in 1.30.1 / 1.31.0); NGINX Plus R32–R36 (fixed R32 P6 / R36 P4). Versions 0.6.27–0.9.7 have no fix planned.
- **Why it matters to us:** our own tech corpus lists a fingerprinted **`Nginx:1.29.7`** — that's inside the vulnerable 1.0.0–1.30.0 range. This is a genuine version-in-range n-day candidate, not just a tech-class match.
- **Detect:** version from `Server:`/error-page banner if `server_tokens` isn't disabled (many hosts hide it — treat absence as unknown, not clean). Exploitability additionally requires the specific vulnerable `rewrite`+`?`+chained-directive config server-side, which is **not remotely fingerprintable** — so per KEV doctrine this is version-range LEAD, not P0, until a live probe (crash/DoS signal, non-destructive) or config leak confirms the pattern. RCE is possible but harder to trigger than DoS.
- **Source:** [The Hacker News](https://thehackernews.com/2026/05/18-year-old-nginx-rewrite-module-flaw.html), [F5/NGINX advisory K000161019](https://my.f5.com/manage/s/article/K000161019), [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-42945), [Axonius](https://www.axonius.com/blog/cve-2026-42945-nginx-rift)

Two more NGINX Open Source CVEs from the same May 2026 F5 patch round, HTTP/2 & HTTP/3-specific (only relevant if QUIC/h3 is enabled): **CVE-2026-42530** (use-after-free in `ngx_http_v3_module`, CVSSv4 9.2, unauth, HTTP/3-only) and **CVE-2026-42055** (heap overflow via attacker-controlled HPACK data in HTTP/2, unauth). Detect via `Alt-Svc`/HTTP/3 support or HTTP/2 negotiation. Source: [The Hacker News](https://thehackernews.com/2026/06/f5-patches-two-critical-nginx-open.html).

### 2. Varnish Cache — CVE-2026-34475 (auth bypass / cache poisoning via `req.url`) — **maps straight to our web-cache-deception lane**
- **What:** Varnish mishandles certain HTTP/1.1 requests whose path is `/` in unchecked `req.url` scenarios, leading to cache poisoning or **authentication bypass**. CVSSv3.1 5.4 (remote, unauth-reachable, high attack complexity).
- **Affected versions:** Varnish Cache **before 8.0.1**; Varnish Enterprise **before 6.0.16r12**.
- **Detect:** `Via`/`X-Varnish` headers reveal Varnish presence; version usually not directly banner-exposed — infer via VCL-behavior probing (our existing WCD/WCP methodology) rather than a version string. Treat as LEAD until our safe cache-key probe reproduces an actual auth-bypass/poison on a path-`/` request.
- **Why it matters:** Varnish is in our in-scope top-tech list and we already run `recon_wcd.sh` — this CVE gives a concrete, non-generic variant (root-path request confusion) to add to the WCD probe set beyond the generic path-confusion pattern.
- **Also:** CVE-2026-40396 — Varnish 9.0.0 DoS via HTTP/1 pipelining workspace overflow (crash only, no poisoning value — skip for our IDOR/cache lanes).
- **Source:** [SentinelOne](https://www.sentinelone.com/vulnerability-database/cve-2026-34475/), [GitHub Advisory GHSA-m9gq-cmcj-p62x](https://github.com/advisories/GHSA-m9gq-cmcj-p62x)

### 3. WordPress plugin unauth vulns (July 2026) — version-reasoned candidates
- **Hide My WP Lite ≤1.3 — CVE-2026-13347** (CVSS 7.5, published 2026-07-10): unauthenticated **arbitrary file read** via `he_wrapper_js`/`he_wrapper_css` query params — can read `wp-config.php` (DB creds). Detect: plugin present (`wp-content/plugins/hide-my-wp/`) + version ≤1.3 → probe the two params for file-read (safe, GET-only, read `wp-config.php` marker string, don't dump). Source: [Atlas Cybersecurity](https://atlas-cybersecurity.com/high-cve-2026-13347-cvss-7-5-july-10-2026/).
- **Kirki (theme customizer framework) — CVE-2026-8206** (CVSS 9.8): unauth privesc via flawed password-reset flow, ~500K sites. Detect plugin `wp-content/plugins/kirki/`. Source: [Orca Security](https://orca.security/resources/blog/kirki-wordpress-plugin-vulnerability-cve-2026-8206/).
- **WPvivid Backup & Migration — CVE-2026-1357** (CVSS 9.8): unauth arbitrary file upload → RCE. Detect `wp-content/plugins/wpvivid-backuprestore/`. Source: [CybersecurityNews](https://cybersecuritynews.com/wordpress-backup-plugin-vulnerability/).
- These are exactly our KEV-doctrine pattern: tech-class alone is worthless (WordPress is huge in our corpus) — only the plugin-slug + version-in-range match is actionable. Worth a pass of `recon-mood wordpress` cross-referenced against these three plugin slugs/versions via jsintel/wappalyzer/plugin-path fingerprints.

### 5. PHP-ecosystem RCE (lower priority — need SOAP/Twig usage confirmed)
- **CVE-2026-6722** — PHP SOAP extension use-after-free (object-dedup pointer bug in `apache:Map` duplicate-key handling) → RCE for apps exposing a SOAP endpoint that accepts attacker-controlled request bodies. Only relevant if we find `.wsdl`/SOAP endpoints in jsintel/params corpus. Source: PHP 8.5.6/8.4.21/8.3.31/8.2.31 release notes.
- **CVE-2026-46633** — Twig `{% use %}` template-name PHP code injection, bypasses Twig sandbox, RCE on first cache load. Symfony/Twig <3.26.0. Detect: `X-Powered-By`/error pages revealing Symfony, or template-injection-style params. Source: [Symfony blog](https://symfony.com/blog/cve-2026-46633-php-code-injection-via-use-template-name).
