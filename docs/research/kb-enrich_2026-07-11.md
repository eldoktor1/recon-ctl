### 2. `_entities` — direct subgraph impersonation (if a subgraph is reachable un-fronted)
`_entities(representations: [_Any!]!)` is how the Apollo Router resolves cross-subgraph references. If a
subgraph endpoint is directly internet-reachable (not solely behind the router — common when a subgraph
also serves a public path, or DNS/CT surfaces an internal-looking `*-subgraph.`/`*-federation.` host),
an attacker can craft `_entities` calls that skip the router's auth/composition boundary entirely and
fetch arbitrary entity keys. This is an **architecture assumption failure** (teams treat subgraphs as
"internal, so unauthenticated is fine" because "the router already authorized it") — read-only probe:
send a benign `_entities` query with a guessed `__typename`+key; a populated response with no auth header
proves the subgraph is directly exposed. LEAD only — human confirms actual data sensitivity.

### 3. Composition-logic access-control bypass CVEs (Apollo Federation, disclosed ~late 2025)
- **GHSA-mx7m-j9xf-62hw** — `@authenticated`/`@requiresScopes`/`@policy` directives placed on an
  **interface type** are NOT inherited by implementing object types (GraphQL spec defines no directive
  inheritance from interfaces). Query the protected data through an inline/named fragment on the
  concrete implementing type instead of the interface — the access-control directive never fires.
  Affected: Federation composition prior to 2.9.5 / 2.10.4 / 2.11.5 / 2.12.1.
- **GHSA-m8jr-fxqx-8xx6** — fields decorated with `@requires`/`@fromContext` don't enforce their OWN
  access-control requirement when accessed only as a transitive dependency of another field — silently
  ignored authz on a "supporting" field.
- **CVE-2025-32032** — Apollo Router recursive-fragment DoS (query-planner-side unbounded fragment
  expansion) prior to 1.61.2 / 2.1.1. DoS-class, keep as LEAD per existing DoS discipline (most programs
  don't pay DoS; never auto-fire).

**Ranking signal:** when introspection/SDL reveals `interface` types with `@authenticated`/`@requiresScopes`
directives, always retest the SAME data path via an inline fragment on each concrete type implementing
that interface — a 200 there vs a 401/403 on the interface query is the tell.

### 4. Mass assignment / BOPLA in mutation input types (OWASP API3:2023 applied to GraphQL)
A distinct class from the existing IDOR object-ref-arg ranking: instead of an id swap, the vulnerable
surface is a mutation's **input type** accepting client-controllable fields it shouldn't (`role`,
`isAdmin`, `permissions`, `tier`, `verified`, `balance`, `internalFlags`) because the resolver binds the
whole input object to the backend model without an allowlist.
**Ranking addition:** when parsing an introspected/recovered schema, flag any `input` type on a
`create*`/`update*` mutation whose fields include privilege/state terms (`role`, `admin`, `permission`,
`scope`, `tier`, `status`, `verified`, `balance`, `credit`, `flag`) — these are BOPLA candidates distinct
from the existing IDOR-arg scoring. Test (human, 2 owned accounts): send the full input object as a
low-priv account, add the privileged field, observe if it's accepted/persisted.

## Digest — KB enrichment, 2026-07-11

**Checked first:** `class-idor.md` and `class-graphql.md` already contain dense, current coverage —
alias/batch-query abuse, GraphQL-over-WS IDOR→SQLi chains, array-wrapping/param-pollution IDOR bypass,
JWT `sub`-claim IDOR, UI/API divergence, filter-object IDOR, mass-tooling additions — most of what a
generic 2026 search surfaces is already applied here. Rather than re-file duplicate material, this run
targeted the one genuinely uncovered angle: **Apollo Federation**, which is architecturally distinct
from the single-schema GraphQL surface the existing doc models.

### New: Apollo Federation attack surface (kb-proposal above)
1. **`_service{sdl}` bypasses introspection-off** — a federation-layer field, not core GraphQL, so
   disabling `__schema` doesn't stop schema disclosure. Cheap, unauth-safe, should be tried before the
   existing Clairvoyance field-suggestion fallback.
2. **`_entities` direct-subgraph exposure** — if a subgraph is reachable without going through the
   router, `_entities` lets a caller impersonate the router and pull arbitrary entity keys — a broken
   architectural assumption ("subgraphs are internal, so unauth is fine"), not a code bug. Read-only
   LEAD probe.
3. **Composition-logic CVEs (Apollo Federation, disclosed ~late 2025):** `@authenticated`/
   `@requiresScopes`/`@policy` on interface types isn't inherited by implementing object types
   (GHSA-mx7m-j9xf-62hw) — query via a fragment on the concrete type to skip the directive;
   `@requires`/`@fromContext` fields lose their own access check when reached transitively
   (GHSA-m8jr-fxqx-8xx6); CVE-2025-32032 recursive-fragment DoS in Apollo Router (<1.61.2/2.1.1, keep
   as LEAD per existing DoS discipline).
4. **Mass assignment / BOPLA on mutation input types** — a class distinct from existing IDOR-arg
   ranking: flag `input` types on `create*`/`update*` mutations exposing `role`/`isAdmin`/`tier`/
   `balance`-style fields the resolver may bind without an allowlist.

Nothing new found for `class-idor.md` this run — the existing doc already covers every technique
(array-wrapping, HTTP parameter pollution, method-switching, UUID→SQLi escalation, multi-session
body-hash confirm primitive) that current writeups surface. Not re-proposing to avoid duplication.
