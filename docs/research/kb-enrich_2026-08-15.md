# Research digest — kb-enrich — 2026-08-15

## 1. BOLA/IDOR — empirical taxonomy from 100+ bug bounty disclosures (class-idor)
New academic taxonomy (84 confirmed HackerOne/GitLab/etc cases, 2023–2026) sharpens *what to actually test for* beyond simple ID-swap — notably that **state-changing BOLA now outnumbers read-path BOLA**, which cuts against our current unauth-only IDOR-detection bias.
Source: [arxiv.org/abs/2605.25865](https://arxiv.org/abs/2605.25865)

## 2. GraphQL global-ID decode→increment→re-encode (class-graphql)
Real disclosed pattern (Shopify H1 #2207248, $5k; also GitLab): base64 "opaque" GraphQL node IDs are just `base64("Gid://App/ModelName/123")` — decoding reveals a sequential backend integer. Directly actionable for our GraphQL-schema-worklist lane: any query/mutation taking a `Node`/`ID!` arg should have that ID base64-decoded and checked for a decodable sequential integer before being deprioritized as "opaque."
Source: [infosecwriteups.com](https://infosecwriteups.com/graphql-security-how-i-found-and-exploited-critical-idor-and-authorization-bypass-in-a-42ab78e13642)

## 3. GraphQL alias/batch overloading — rate-limit bypass amplification (class-graphql)
Confirms and quantifies a technique our GraphQL lane doesn't currently probe for: aliasing the same field N times in one query, or array-batching N operations in one POST, turns a "5 req/min" limiter into 5,000+ effective ops/min because most rate limiters count *HTTP requests*, not *GraphQL operations*. CVE-2024-39895 (Directus alias DoS) is the reference CVE. Concrete for us: OTP/login-brute-force and object-enumeration targets that look rate-limited over plain REST may be wide open via GraphQL alias batching on the same backend.
Sources: [payloadplayground.com](https://payloadplayground.com/blog/graphql-batching-and-aliasing-attacks), [github.com/3ls3if/Cybersecurity-Notes](https://github.com/3ls3if/Cybersecurity-Notes/blob/main/readme/web-app-pentesting-notes/graphql-api-vulnerabilities/bypassing-rate-limiting-using-aliases/README.md)

## 4. SSRF — DNS-rebinding TOCTOU is the live 2026 CVE pattern (class-ssrf)
Two fresh CVEs (Craft CMS CVE-2026-27127, MCP Atlassian CVE-2026-27826) both fail the same way: the SSRF guard resolves DNS once to validate, then the HTTP client resolves again to connect — attacker's rebinding DNS returns a public IP for the check, private/metadata IP for the real fetch. This is the pattern to specifically test on any of our SSRF interactsh-OOB targets that *do* have an allowlist/validator (most guard bypasses assume no revalidation on connect). Full concrete payload set (decimal/octal/hex IP encoding, IPv6-mapped, `nip.io`/`sslip.io`, userinfo `@`, fragment-confusion, `evil.com.allowed.com` suffix bypass, redirect-chain, gopher/dict raw-socket) captured below for the KB.
Sources: [github.com/craftcms/cms/security/advisories/GHSA-gp2f-7wcm-5fhx](https://github.com/craftcms/cms/security/advisories/GHSA-gp2f-7wcm-5fhx), [github.com/advisories/GHSA-489g-7rxv-6c8q](https://github.com/advisories/GHSA-489g-7rxv-6c8q), [intruderlabs.com.br](https://intruderlabs.com.br/en/blog/ssrf-bypass-techniques/)
