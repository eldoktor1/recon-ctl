## 2. GraphQL APQ is not a safelist — new bypass class for `class-graphql.md`
"APQ enabled" gets misread by devs as access control (only pre-approved hashes execute); it's actually a cache optimization that will run and cache ANY full query on a hash-miss. Distinct from every bypass already documented (fragment obfuscation, whitespace-mangling, field suggestions, federation `_service{sdl}`) — this one lets you register net-new operations, not just recover schema.




If step 2 executes, the target is running APQ-as-if-it-were-security — introspection, deep/aliased
queries, or any mutation the schema exposes can be submitted this way even if the client app's bundled
JS only ever sends hashes (i.e. even if grepping the SPA JS shows no raw query strings — don't treat
that as "queries are locked down").

**WAF/monitoring blind spot:** some clients send hash-only APQ lookups via **GET** and only fall back
to POST with the full query on a miss — logging/WAF rules tuned to the common hash-only GET pattern can
miss the dangerous full-query POST retry entirely.

### What real safelisting looks like (don't flag as a bypass)
Apollo's actual safelist feature is **persisted operations / operation safelisting** — a pre-registered
list built at deploy time where the server REJECTS any raw `query` string outright (APQ explicitly
disabled or superseded). If step 2 above 400s/403s with something like "operation not registered" /
"unpersisted operation," that's the hardened configuration — note as secure-FP, don't re-test.

### Fit into our lane
Feeds directly into the existing `recon_graphql.sh`/`recon_graphql.py` introspection-recovery step —
if standard `{__schema{...}}` is blocked at the top level, try it via the APQ hash-miss→full-query path
before falling back to Clairvoyance-style suggestion mining (cheaper, one request pair vs. the bounded
~140-probe suggestion loop). Read-only, unauth-safe, same LEAD tier as every other schema-recovery
technique here — a recovered schema via this path still needs the same sensitive-op/IDOR-arg/injectable-
arg ranking pass before anything is worklisted.
