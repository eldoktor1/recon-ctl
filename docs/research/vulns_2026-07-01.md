### CVE-2026-34908 / 34909 / 34910 — Ubiquiti UniFi OS Triple (CVSS 10.0 × 3) — **KEV, actively exploited**

**What:** Three chained unauth vulns: improper access control (auth bypass) + path traversal (arbitrary file read/write) + improper input validation (OS command injection). Exploited in the wild — attackers created rogue admin accounts named "John Sim" in automated recon. Added to KEV 2026-06-23.

**Affected versions:** UniFi OS Server < 5.0.8 (patched 2026-05-21).

**Why this hits us hard:** Our pipeline already has 27+ UniFi-OS consoles in scope. The fanout-suppressor correctly kills the product-class IDOR endpoint dups (`/proxy/users/...`), but **this is a different class** — an OS-level unauth chain, not per-endpoint IDOR. These are independently reportable n-day findings.

**Detection fingerprint (unauth):**
- `/api/self` — UniFi always returns JSON with software version unauthenticated. Version < 5.0.8 → LEAD.
- `/proxy/network/integration/v1/sites` — typically 401 on patched, may 200 on CVE-2026-34908-vulnerable hosts.
- Port 443 or 8443; login page title: `UniFi OS`.
- `X-CSRF-Token` header absent on vulnerable hosts (auth bypass bypasses token checks).

**In-range verifiable unauth:** YES — version probe via `/api/self` is safe GET, no auth, no state change.

**Sources:** [threat-modeling.com](https://threat-modeling.com/cve-2026-34908-34909-34910-ubiquiti-unifi-os-triple-kev/) · [securityonline.info KEV](https://securityonline.info/cisa-kev-catalog-exploited-flaws/) · [beazley.security](https://beazley.security/alerts-advisories/critical-vulnerability-in-ubiquiti-network-application-under-active-exploitation-cve-2026-34908-cve-2026--34909-cve-2026-34910)

**Action:** Run `recon-nday` / `recon-mood KEV` targeting UniFi-OS hosts. For any hit on version < 5.0.8: `GET /api/self` → confirm software version in response → LEAD (version-confirmed, not yet exploited by us → human triage). Do NOT auto-probe the path traversal (CVE-34909 reads files → exploitation, not detection).

### CVE-2026-42945 "NGINX Rift" — Heap Buffer Overflow in ngx_http_rewrite_module (CVSS 9.2) — **PoC public**

**What:** 18-year-old heap overflow in `ngx_http_rewrite_module`, triggered by a crafted HTTP request. **Our detected version `Nginx:1.29.7` is IN THE VULNERABLE RANGE (0.6.27–1.30.0).** Patched in 1.30.1 / 1.31.0. Unauthenticated DoS is reliable. RCE requires specific rewrite config + ASLR-disabled (less common on hardened hosts but a PoC ASLR-bypass chain via same-host LFI is published).

**Vulnerable config pattern** (very common — WordPress permalinks, PHP front controllers, API gateways):
```nginx
rewrite ^/(.*)$ /index.php?$1 last;  # unnamed capture + ? = VULNERABLE
```
Named captures (`(?P<name>...)`) are NOT vulnerable.

**Detection:**
- `Server: nginx/X.Y.Z` header where X.Y.Z < 1.30.1 → version-confirmed LEAD.
- Our ES already has `Nginx:1.29.7` tagged — query `tech:nginx AND NOT version:[1.30.1 TO *]` to get full in-scope hit list.
- Config-dependency means not all 1.29.7 hosts are exploitable for RCE, but DoS is universal for the version range.

**Sources:** [THN](https://thehackernews.com/2026/05/nginx-cve-2026-42945-exploited-in-wild.html) · [socprime](https://socprime.com/blog/cve-2026-42945-critical-nginx-rewrite-flaw/) · [orca](https://orca.security/resources/blog/nginx-rewrite-module-vulnerability-cve-2026-42945/) · [f5 advisory](https://my.f5.com/manage/s/article/K000161019)

**Action:** `recon-nday` pull of Nginx < 1.30.1 in-scope+paying hosts. Version-match → LEAD. For programs that pay on DoS-class or critical-exposure n-days, this is submittable with version-confirmed PoC. Note: pure-version report without config confirmation = LEAD-not-CONFIRMED (per our KEV doctrine). Check if programs have Nginx version disclosed in headers; some strip it.

### CVE-2026-6722 — PHP SOAP Extension Use-After-Free RCE (CVSS 9.5)

**What:** Use-after-free in PHP's SOAP extension object deduplication. Attacker sends crafted SOAP request body to any PHP endpoint using the SOAP extension. **Unauthenticated** when the SOAP endpoint is public. CVSS 9.5.

**Affected:** PHP < 8.2.31, < 8.3.31, < 8.4.21, < 8.5.6. Patched across all active branches.

**Detection fingerprint:**
- Look for `/?wsdl`, `/soap`, `/api/soap`, `/services/*.php?wsdl` endpoints in jsintel / params catalog.
- PHP version in `X-Powered-By: PHP/X.Y.Z` header or error pages — confirm < patched branch version.
- SOAP endpoints often appear in JS as `soapClient` / `SoapClient` references or in jsintel endpoint output.

**In-range verifiable unauth:** Version confirmed via header + SOAP endpoint exists = LEAD. Don't send malformed SOAP (exploitation, not detection).

**Sources:** [cybersecuritynews](https://cybersecuritynews.com/php-soap-extension-vulnerabilities/) · [securityonline](https://securityonline.info/php-security-patch-rce-soap-cve-2026-6722/) · [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-6722)

**Action:** Add `wsdl` and `SoapClient` to jsintel keyword scan. For any PHP host with SOAP endpoint + unpatched version → LEAD for `recon-nday`.
