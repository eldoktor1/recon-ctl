### WORDPRESS PLUGINS — three unauth criticals, all high-install-count

**CVE-2026-10795 · UpdraftPlus ≤ 1.26.4 — Unauth admin RCE** *(3M+ installs, actively exploited as of ~June 11)*
- Vector: unauthenticated RPC handler `UpdraftPlus_Remote_Communications_V2::wp_loaded` → code exec as WP admin
- Detect: `GET /wp-content/plugins/updraftplus/readme.txt` → `Stable tag:` ≤ 1.26.4 = LEAD. Also look for `action=updraftplus_` in `endpoints.jsonl` (jsintel lane)
- Patch: 1.26.5
- Sources: [Wordfence](https://www.wordfence.com/blog/2026/06/critical-unauthenticated-authentication-bypass-vulnerability-patched-in-updraftplus-wordpress-plugin/) · [Falcon Internet](https://www.falconinternet.net/blog/updraftplus-cve-2026-10795-authentication-bypass-wordpress)

**CVE-2026-1357 · WPvivid Backup & Migration — Unauth arbitrary PHP upload** *(900K installs)*
- Vector: unauthenticated PHP file upload via backup/migration endpoint → RCE
- Detect: `/wp-content/plugins/wpvivid-backuprestore/readme.txt`. Look for `wpvivid` in jsintel ajax actions
- Source: [Indusface](https://www.indusface.com/blog/cve-2026-1357-wordpress-rce-wpvivid-plugin/)

**CVE-2026-8206 · Kirki Page Builder — Unauth admin takeover** *(~150K installs)*
- Vector: `handle_forgot_password()` accepts attacker-controlled email → full admin reset
- Detect: `/wp-content/plugins/kirki/readme.txt`; `kirki` in page source/bundled JS paths
- Source: [Orca Security](https://orca.security/resources/blog/kirki-wordpress-plugin-vulnerability-cve-2026-8206/)

**Action:** Query ES for WordPress hosts → run these three readme.txt checks as n-day candidates via `recon-nday`. High-install plugins = low dup-risk (each site independently vulnerable, crowd doesn't mass-hunt plugin-specific n-days well).

### NGINX — two HTTP/2-and-3 criticals, version-specific

**CVE-2026-42530 · NGINX 1.31.0–1.31.1 — HTTP/3 UAF, potential unauth RCE**
- Vector: UAF in `ngx_http_v3_module` on QUIC session QPACK encoder stream reopening
- Fingerprint: `Server: nginx/1.31.x` **+** `Alt-Svc: h3=":443"` response header (both required — HTTP/3 must be active)
- Patch: 1.31.2
- Unauth verifiable: version + `Alt-Svc` check = LEAD. RCE requires ASLR bypass so real-world severity may be DoS on most targets
- Source: [The Hacker News](https://thehackernews.com/2026/06/f5-patches-two-critical-nginx-open.html) · [SOC Prime](https://socprime.com/blog/cve-2026-42530-critical-nginx-http-3-flaw-can-trigger-dos-and-possible-rce/)

**CVE-2026-42055 · NGINX 1.30.0–1.30.2, 1.31.1 / Plus R33–R37.0.1 — HTTP/2 heap overflow**
- Vector: `ngx_http_proxy_v2_module` / `ngx_http_grpc_module` heap overflow via oversized HPACK data
- **Config triple required (all three):** `proxy_http_version 2` or `grpc_pass` active; `ignore_invalid_headers off`; `large_client_header_buffers > 2MB` — this is non-default, sharply limits real exposure
- Fingerprint: version in `Server:` header + `content-type: application/grpc` responses (gRPC backend = higher-probability config hit). Our ES has HTTP/3 in top tech which correlates with newer nginx
- Patch: Open Source 1.30.3 / 1.31.2; Plus R36 P6 / 37.0.2.1
- Source: [The Hacker News](https://thehackernews.com/2026/06/f5-patches-two-critical-nginx-open.html)

**⚠️ UNVERIFIED — NGINX rewrite module RCE (no confirmed CVE):** headline claims "18-year-old" rewrite flaw; no version range confirmed. Do NOT act until NVD/advisory confirms. Source: [THN](https://thehackernews.com/2026/05/18-year-old-nginx-rewrite-module-flaw.html)

**Action:** ES query for `Server: nginx/1.31.` AND `Alt-Svc` header containing `h3` → small universe, high-value if unpatched.

### GRAPHQL — type coercion auth bypass (technique, no CVE)

Fresh disclosed pattern (April–June 2026): `password: null` or `password: [...]` returns a valid session token on ORM-backed GraphQL sign-in mutations (lenient input type coercion in the ORM, not GraphQL itself).

- Detect unauth: `POST /graphql {"query":"{__schema{types{name}}}"}` → enumerate mutations → look for `signIn`/`login`/`createSession` with a `password` arg → test `null` and array coercion
- Financial transaction IDOR via batch query object-ID swapping is still the #1 paid GraphQL class — $12.5K payout documented
- Source: [InfoSec Writeups](https://infosecwriteups.com/graphql-security-how-i-found-and-exploited-critical-idor-and-authorization-bypass-in-a-42ab78e13642) · [HackerOne blog](https://www.hackerone.com/blog/how-graphql-bug-resulted-authentication-bypass)

**Action:** Add `password: null` coercion test to the GraphQL worklist generator (`recon_graphql.sh`) as a mutation-level probe hint.
