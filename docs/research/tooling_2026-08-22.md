# Research digest — tooling — 2026-08-22

## Bottom line
Three solid finds this pass: a **battle-tested smuggling tool** that supersedes the obscure one flagged 2026-07-28, a **takeover tool with built-in validation modules** (fits our claimability-confirm doctrine), and a **GraphQL engine-fingerprinter** from the same author as graphql-cop (already adopted) that pairs naturally with it. IDOR-scanner search turned up nothing beyond AuthProbe (already flagged 2026-08-15) — the rest are low-star single-author toys, skipped.

---

### 1. ADOPT (supersedes prior pick) — `defparam/smuggler`
- **What it is:** Python 3 HTTP request-smuggling/desync tester (CL.TE/CL.CL/TE.TE), built directly on James Kettle's research. 2.1k★, referenced in PayloadsAllTheThings as the canonical tool, still getting issues/commits through 2026.
- **Why it beats last pick:** 2026-07-28 flagged `Smugglex` (single-author, unverified traction) for the smuggling-lane gap. `smuggler` is the actually-established, widely-cited tool for this — same detection shape (differential/timing desync probing, no exploitation), far more battle-tested.
- **Doctrine fit:** unauth-safe ✅ (detects desync capability, doesn't need to complete an exploit to flag it), dup-resistant ✅ (crowd rarely runs dedicated smuggling scans), non-destructive when rate-limited like our other active-probe lanes.
- **Verdict: ADOPT** in place of Smugglex — wire into the same `recon_smuggling.sh` shape previously proposed (LEAD surfacer; careful rate-limited confirm step, never a destructive replay against prod).
- Source: [defparam/smuggler](https://github.com/defparam/smuggler)

### 2. EVALUATE — `Stratus-Security/Subdominator`
- **What it is:** ~290★, actively released takeover scanner. Vetted fingerprint schema (dynamically pulled from can-i-take-over-xyz + own additions), A/AAAA/CNAME + nested-record resolution, and — the differentiator — a `--validation` mode that actually checks a flagged domain against the provider's claim mechanism instead of stopping at a fingerprint match.
- **Why it matters:** our own doctrine (`takeover:confirmed` vs `cname-lead`, [[feedback_takeover_claimability_primitive]]) already hand-builds this claimability check; Subdominator ships a maintained, multi-provider version of exactly that logic. Could reduce custom-code surface / catch providers we haven't coded a check for.
- **vs. badDNS (in use):** badDNS's edge is breadth (Nuclei+dnsReaper-sourced signatures, plus second-order takeover via referenced client-side JS/CSS domains — genuinely complementary, not redundant). Subdominator's edge is the validation step. Not a replacement for badDNS — a potential confirmation-stage companion.
- **Verdict: EVALUATE** — trial `--validation` against a few known cname-lead hosts in `ignored.jsonl`/host_notes to see if it correctly claims/rejects vs. our manual provider-check code; adopt only if it covers providers our current confirm step doesn't.
- Sources: [Subdominator](https://github.com/Stratus-Security/Subdominator), [badDNS](https://github.com/blacklanternsecurity/baddns)

### 3. EVALUATE (companion to graphql-cop) — `dolevf/graphw00f`
- **What it is:** GraphQL engine-fingerprinting tool (845★, same author as graphql-cop, adopted 2026-08-18), maintained through April 2026 releases. Sends benign+malformed queries to identify the exact GraphQL server engine, then cross-references the **GraphQL Threat Matrix** to report which security defenses that engine has on/off by default (batching limits, introspection-off-by-default, query-depth limiting, etc.).
- **Why it's useful, not redundant:** `recon_graphql.sh` currently harvests schema and reasons over it; graphw00f adds a pre-step that tells us *which defenses to expect* before we run graphql-cop's misconfig battery — e.g. an engine known to disable batching by default makes a batch-query DoS-primitive hit more suspicious (possible misconfig) rather than routine.
- **Doctrine fit:** unauth-safe ✅, read-only fingerprint probes only, dup-resistant (crowd stops at introspection-enabled).
- **Verdict: EVALUATE** — bolt on as an optional pre-step in `recon_graphql.sh` before the graphql-cop pass; low integration cost given shared authorship/tooling conventions.
- Source: [graphw00f](https://github.com/dolevf/graphw00f)
