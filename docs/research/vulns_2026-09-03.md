# Research digest — vulns — 2026-09-03

## 1. NEW — CVE-2026-48710 "BadHost", Starlette (FastAPI's underlying ASGI framework) — unauth auth-bypass via Host header, **added to CISA KEV this week** ★★★
- **What:** Starlette rebuilds `request.url` by string-concatenating the raw `Host` header with the request path and re-parsing it **without validating the header against RFC 9112/3986 grammar**. Injecting `/`, `?`, or `#` into the `Host` header shifts where the path/query/fragment boundaries land. Any app that uses `request.url.path` inside auth/path-based middleware (a common FastAPI pattern — allowlist/denylist middleware checking `request.url.path` before letting a request through) evaluates a **forged path** while the routing layer still dispatches to the **real, unforged** path underneath — i.e. the middleware "sees" a safe path and the actual protected route executes anyway. Zero auth, single malformed header.
- **Affected:** Starlette **0.8.3 – 1.0.0** (all releases in that range). Fixed in **1.0.1** — validates the Host header grammar, falls back to `scope["server"]` on malformed input. Hits the whole Starlette-dependent ecosystem: **FastAPI**, vLLM, LiteLLM, MCP servers.
- **Why it's KEV now:** CISA added it to the Known Exploited Vulnerabilities catalog in the past few days — this is being actively exploited in the wild, not theoretical.
- **Detect/confirm (unauth, SAFE, directly fits our doctrine):** find any FastAPI/Starlette host with a protected path (401/403/redirect without a crafted request), then resend with a malformed `Host` header (`X-Forwarded-Host`/`Host: victim.com/../protected` style path-injection per the advisory) and diff the response — if the protected content is served, that's a genuine confirmed auth-bypass primitive, not a version-match LEAD. This is a real safe-probe candidate (GET only, header manipulation, no state change) — worth adding to `recon_safe_probe.sh`'s repertoire for any host fingerprinted as FastAPI/Starlette/uvicorn (`Server: uvicorn`, FastAPI's default `/docs`/`/openapi.json`, or `X-Process-Time` header some FastAPI apps expose).
- **Action:** fingerprint FastAPI/Starlette across our corpus (Server header, `/openapi.json`, jsintel), then this is directly probe-able per our unauth-safe-probe doctrine — higher-confidence than most n-day leads because the confirm step doesn't require crashing anything.
- **Sources:** [OSTIF disclosure](https://ostif.org/disclosing-the-badhost-vulnerability-in-starlette/), [IONIX](https://www.ionix.io/threat-center/cve-2026-48710/), [CCB Belgium advisory](https://ccb.belgium.be/advisories/warning-vulnerability-starlette-framework-and-related-frameworks-fastapi-exposes), [Snyk](https://security.snyk.io/vuln/SNYK-PYTHON-STARLETTE-16881242)

## 2. NEW — CVE-2026-34356, Apache HTTP Server `mod_proxy_http` heap overflow (ProxyPassReverseCookie) — top-tech, LEAD-only
- **What:** Heap buffer overflow in the cookie-rewriting logic used by `ProxyPassReverseCookieDomain`/`ProxyPassReverseCookiePath` — a **malicious/compromised backend** sends an oversized `Set-Cookie` `Domain`/`Path` attribute and httpd's rewrite routine miscalculates buffer boundaries → out-of-bounds write. CVSS 7.5.
- **Affected:** Apache HTTP Server **2.4.0 – 2.4.67**. Fixed in **2.4.68**.
- **Why this matters:** Apache HTTP Server is our #1 detected in-scope tech — but note the attack surface here is the **backend**, not a directly attacker-controlled external request; exploitability requires influence over what the reverse-proxied backend returns (compromised origin, or a chained SSRF/response-injection into the backend). Not a direct unauth external primitive on its own.
- **Detect:** `Server: Apache/2.4.x` header or jsintel version string, version-in-range check only — **no safe remote way to confirm exploitability** (would require crashing a worker). Per our KEV/version doctrine: version-match ⇒ LEAD, note only, don't fire.
- **Source:** [SentinelOne](https://www.sentinelone.com/vulnerability-database/cve-2026-34356/)
