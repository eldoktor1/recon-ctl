## 1. NEW — CVE-2026-1357, WPvivid Backup & Migration — unauthenticated RCE via file upload, 900k+ installs ★★
- **What:** `wpvivid_action=send_to_site` handler decrypts an RSA session key with `openssl_private_decrypt()`; on a malformed/attacker-controlled RSA key the call returns `false`, which the plugin passes uncheck to phpseclib v1's `Crypt_Rijndael` — phpseclib silently treats `false` as a 16-byte null key + null IV (predictable AES-CBC). The decrypted JSON payload's `name` field is not sanitized, so a crafted payload uploads an arbitrary (`.php`) file → RCE. **Fully unauthenticated** — no plugin API token needed to hit the endpoint, though some writeups note the remote-backup feature must have an `wpvivid_api_token` configured/active for the transfer flow to be reachable (not remotely visible, treat as LEAD-narrowing factor like the WooCommerce-HPOS pattern from 2026-08-16).
- **Affected:** WPvivid Backup & Migration ≤ 0.9.123. Fixed in **0.9.124**. CVSS 9.8.
- **Detect (unauth, in-range-verifiable):** `GET /wp-content/plugins/wpvivid-backuprestore/readme.txt` → `Stable tag`; also `wpvivid` string in jsintel JS bundles on any WordPress-fingerprinted host. A public PoC (`halilkirazkaya/CVE-2026-1357`) ships a `-c` "check mode" that uploads a harmless `.txt` (not `.php`) to confirm the primitive without RCE — worth adopting as our safe-probe pattern if we ever gate this behind operator authorization.
- **Action:** version-match (≤0.9.123) = LEAD; do not fire the upload autonomously (crosses into exploitation/RCE). Add to `recon-mood wordpress`/`wpvivid` sweep.
- **Pattern note:** this is the **third** WP-plugin unauth-file-upload-bypass this month (Elementor Pro CVE-2026-32475 8/20, Forminator CVE-2026-15748 8/22, now WPvivid) — worth treating as a standing watch-class, not one-offs (see KB proposal below).
- **Sources:** [Indusface](https://www.indusface.com/blog/cve-2026-1357-wordpress-rce-wpvivid-plugin/), [SentinelOne](https://www.sentinelone.com/vulnerability-database/cve-2026-1357/), [Ostorlab](https://blog.ostorlab.co/cve-2026-1357-unauthenticated-rce-wpvivid.html)

## 2. WATCH — CVE-2026-82329, JFrog Artifactory — unauth admin-token forgery, added to CISA KEV 2026-09-02, actively exploited
- **What:** Under **default configuration** (no explicit federation/join key set), Artifactory generates a predictable "phantom" join key that lets a network-adjacent, unauthenticated attacker forge admin-level access tokens — full instance compromise (CVSS 9.8). watchTowr observed in-the-wild exploitation (token forging + user/group/credential enumeration) within days of JFrog's 2026-08-28 disclosure.
- **Affected:** self-hosted Artifactory 7.111.4–7.161.19 (JFrog-hosted cloud already patched). Fixed per branch: 7.111.21 / 7.117.28 / 7.125.20 / 7.133.29 / 7.146.38 / 7.161.20.
- **Why WATCH not ACTION:** not in our top-tech list, and no public source discloses a safe unauth fingerprint/probe for the "default config" precondition — writeups explicitly withhold exploitation mechanics. Relevance is only if a program's scope includes exposed dev/CI infra running Artifactory.
- **Detect if encountered:** Artifactory login page / `X-JFrog-*` headers / `/artifactory/webapp/`; version via the (normally unauth-reachable) `/artifactory/api/system/ping` or version banner — version-in-range ⇒ LEAD only per KEV-tech-class doctrine, hand to operator, don't attempt token forgery.
- **Sources:** [SecurityWeek](https://www.securityweek.com/critical-jfrog-artifactory-vulnerability-reportedly-exploited-in-the-wild/), [IONIX](https://www.ionix.io/threat-center/cve-2026-82329/), [DarkReading](https://www.darkreading.com/application-security/attackers-pounce-critical-artifactory-flaw-disclosure)

## 3. WATCH — CVE-2026-19806, WordPress "Support Genix" helpdesk plugin — Subscriber→Admin takeover
- **What:** `guest_ticket_login()`'s `p` parameter accepts a forgeable token. The plugin's AES-256-CBC site key is derived from only three `wp_rand(10,99)` values + a Unix timestamp via `md5()` (~19.5 bits of entropy) — an attacker who already holds **Subscriber-level** access (or one legitimate guest ticket token as a known-plaintext oracle) can brute the ~729k keyspace offline, forge a token bound to an admin-owned ticket, and get `wp_set_auth_cookie()` called for that admin. CVSS 8.8, disclosed 2026-09-01.
- **Caveat vs. our fully-unauth doctrine:** requires a low-priv account first — only actionable where the target WP site has open self-registration (common on membership/support sites) or a guest-ticket flow that itself creates a usable token oracle.
- **Affected:** ≤1.4.52. Fixed in 1.4.53.
- **Detect:** `wp-content/plugins/support-genix/readme.txt` Stable tag on any WP host; note if self-registration is open (visible in the DOM/wp-login.php `?action=register`).
- **Action:** LEAD only, note as requiring an owned low-priv account first — fits our 2-account authed-testing doctrine, not autonomous.
- **Source:** [cvefeed.io](https://cvefeed.io/vuln/detail/CVE-2026-19806)
