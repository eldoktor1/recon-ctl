# Research digest — vulns — 2026-09-04

## 1. NEW — CVE-2026-42945 "NGINX Rift" — heap overflow, **directly matches our real in-scope version (nginx 1.29.7)** ★★★
- **What:** 18-year-old heap buffer overflow in `ngx_http_rewrite_module`. Triggered by a specific config pattern — a `rewrite` directive with an **unnamed PCRE capture** (`$1`/`$2`) whose replacement string contains a `?`, followed by another `rewrite`/`if`/`set` directive in the same scope — reachable via a crafted, unauthenticated HTTP request. CVSS **9.2 (v4)**.
- **Affected:** NGINX Open Source **0.6.27 – 1.30.0**, NGINX Plus R32–R36. Fixed in **1.30.1 / 1.31.0** (NGINX Plus R32 P6 / R36 P4). Disclosed 2026-05-13 — no confirmed in-the-wild exploitation at disclosure, but this is our **first time surfacing it**; the earlier 2026-08-29 digest covered a *different* nginx CVE (CVE-2026-42533, `map` directive).
- **Why this matters to us specifically:** our own detected in-scope tech list carries `Nginx:1.29.7` — that version falls squarely in the vulnerable range (0.6.27–1.30.0), a genuine match against our real corpus, not hypothetical.
- **Detect (unauth, fingerprint-only):** `Server: nginx/1.29.7` header or jsintel/Wappalyzer version string confirms the binary; **exploitability is config-dependent** (the specific rewrite-directive pattern above is not remotely visible) — same clamp as the 08-29 nginx item. Version-in-range ⇒ **LEAD only**.
- **Action — DO NOT PROBE:** triggering it crashes a worker (DoS primitive; RCE only without ASLR) — destructive, not a safe unauth confirm. Flag any host running nginx in the 0.6.27–1.30.0 range (our 1.29.7 fingerprint included) for the operator to note/report the exposure; don't fire it.
- **Sources:** [SOCPrime](https://socprime.com/blog/cve-2026-42945-critical-nginx-rewrite-flaw/), [The Hacker News](https://thehackernews.com/2026/07/critical-nginx-vulnerability-can-crash.html), [Red Hat](https://access.redhat.com/security/cve/cve-2026-42945)

## 2. NEW — CVE-2026-19949, All-in-One WP Migration & Backup — unauth 2nd-order SQLi → site takeover, 3.2M installs ★★
- **What:** Unauthenticated **second-order SQL injection** in the archive-restore path (CVSS 8.8). An attacker plants a malicious payload via a **crafted trackback on a public post** — it sits inert in the DB until an admin later exports/imports the site with the plugin; on restore, URL/table-prefix rewriting runs the planted data as SQL, letting the attacker steal the `ai1wm_secret_key` and escalate to RCE by uploading a malicious `.wpress` archive. Distinct pattern from the Aug-20/22/09-03 file-upload-blocklist-bypass family — worth tracking both as recurring WP-plugin classes this cycle.
- **Affected:** All-in-One WP Migration and Backup ≤ **7.109**. Fixed in **7.110** (released ~2026-08-29); only ~35% of the install base patched as of 2026-09-03 — wide live window.
- **Detect (unauth, in-range-verifiable):** `/wp-content/plugins/all-in-one-wp-migration/readme.txt` → `Stable tag`; also `ai1wm`/`all-in-one-wp-migration` string in jsintel JS bundles on any WordPress host.
- **Action:** version-match (≤7.109) = LEAD. The exploit chain requires planting a trackback THEN waiting for an admin-triggered restore — not a same-session unauth probe, and the RCE step is exploitation-grade; don't fire. Add to a `recon-mood wordpress` sweep alongside Elementor Pro / Forminator / WPvivid.
- **Sources:** [dev.to writeup](https://dev.to/anoymask/all-in-one-wp-migration-cve-2026-19949-from-second-order-sql-injection-on-restore-to-site-takeover-21be), [SecurityWeek](https://www.securityweek.com/over-3-million-wordpress-sites-affected-by-migration-plugin-vulnerability/), [SentinelOne](https://www.sentinelone.com/vulnerability-database/cve-2026-19949/)
