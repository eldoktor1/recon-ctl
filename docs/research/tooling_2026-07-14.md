# Research digest — tooling — 2026-07-14

## Tooling Watch — 2026-07-14

**Bottom line: nothing displaces what we run. One genuine gap-filler for the authed IDOR/BOLA confirm step; the rest are stale, unvalidated, or dead.**

### 1. Hadrian (praetorian-inc) — EVALUATE
Go-based, Apache-2.0, **v1.0.0 released 2026-03-26**, active (144 commits, 8 open PRs). Automates exactly the workflow our SOP does by hand: define roles/credentials once, then it cross-tests every role combination against every endpoint using a **setup → attack → verify** pattern (victim creates a resource, attacker tries to access/modify it, tool confirms the unauthorized action actually succeeded — not just a status-code guess). Covers BOLA + BFLA across REST/GraphQL/gRPC.
- **Fits our gap, not our autonomous pipeline**: it performs real create/modify mutations, so it's a **human-in-the-loop, operator-run tool against owned/staging resources only** — same posture as our existing 2-owned-account IDOR SOP, not something the unauth daemon should ever invoke. `--dry-run` preview exists; still recommend staging-first.
- Weak spots: fewer GraphQL/gRPC templates than REST, no SSRF coverage — doesn't replace our interactsh-based SSRF lane or `recon_graphql.sh`.
- Verdict: **EVALUATE for on-demand authed-confirm use** (paired with Claude-in-Chrome authed recon), not a pipeline swap.

### 2. Auto-IDOR-Hunter (Burp extension) — SKIP
0 stars, 6 commits, no tagged release — effectively unvalidated. Despite being called "passive," it fires 12 bypass-variant requests per identified object reference, i.e. real background traffic volume, which is exactly the kind of thing that risks a 429/403 cascade and burns the Mullvad exit. Doesn't beat manual Burp Repeater work our SOP already does, and quality is unproven. **Skip.**

### 3. GraphCrawler — dead, no action needed
Archived (read-only) as of 2025-08-23; last real release was 2022. It already used the same Clairvoyance-style introspection-suggestion-recovery trick we independently built into `recon_graphql.sh` — confirms our approach was the right call, nothing to backfill.

### 4. Graphinder (Escape Technologies) — SKIP
Latest release Nov 2022, unmaintained. Its JS-mining + directory-bruteforce endpoint discovery is already subsumed by our jsintel pipeline + native GraphQL lane. No upgrade.

### 5. TruffleHog alternatives (Gitleaks/GitGuardian/detect-secrets) — no change
Comparisons this cycle confirm Gitleaks is *faster* but TruffleHog remains the only one doing live credential **verification**, which is why we mint only on `--only-verified`. Faster-but-unverified would reintroduce the token-shaped-noise FP class we already fought off. **Keep TruffleHog.**

### 6. ProjectDiscovery core (subfinder/httpx/nuclei/katana) — no change
No material new releases changing our workflow this cycle; "recon0" (badchars) is a competing all-in-one single-binary pipeline with an LLM layer — a competitor to our whole system's shape, not a lane component to bolt on. Not adopting.
