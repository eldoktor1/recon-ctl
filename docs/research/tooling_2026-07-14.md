# Research digest — tooling — 2026-07-14

## Tooling Watch — 2026-07-14

**Bottom line:** no clear ADOPT this run. Two EVALUATE-worthy items for the authed/on-demand side of the IDOR pillar and GraphQL discovery; everything else is either a dup-trap, doesn't fit our unauth-safe autonomous doctrine, or couldn't be verified to exist.

### 1. Hadrian (praetorian-inc) — EVALUATE (on-demand authed BOLA confirm only, NOT autonomous)
API authz-testing framework for REST/GraphQL/gRPC: define roles (admin/user/guest) with per-role creds in YAML, it cross-tests role access automatically against an OpenAPI/GraphQL-SDL/protobuf spec. v1.0.0 released 2026-03-26, actively maintained, has a Claude Code integration that auto-generates `auth.yaml`/`roles.yaml` from a spec.
- Fit check: this is literally our 2-owned-account IDOR/BOLA swap methodology, automated — could speed up the human-confirm step once the operator has 2 owned accounts on a target.
- **Caveat (real one):** it performs **mutating requests** — its own docs warn "mutation tests create temporary resources... may attempt to modify or delete them, always test against staging first." That conflicts with our MINIMAL/reversible/non-destructive PoC hard line on live bounty targets. Only usable if scoped to read-only/GET checks manually, never let it run its full mutation suite against production. Not autonomous-pipeline material either way — IDOR stays human-in-the-loop per doctrine.
- Verdict: **EVALUATE**, operator-run only, read-only-scoped, against staging/owned test resources first — do not wire into the autonomous hunter.

### 2. GraphCrawler + Graphinder (Escape Technologies / gsmith257-cyber) — EVALUATE for discovery
GraphCrawler chains Escape's `graphinder` (finds GraphQL endpoints across a target's surface) into schema-crawl + auth-testing. The endpoint-discovery half (graphinder) is unauth-safe and could widen `recon_graphql.sh`'s intake beyond our current jsintel/common-path guesses. graphql-cop (dolevf) is a lightweight unauth Python checker (batching-attack / introspection / field-suggestion) that's read-only and could sanity-check our Clairvoyance-style field-suggestion recovery against a maintained baseline.
- Verdict: **EVALUATE** graphinder as an additional unauth GraphQL-endpoint-discovery source; graphql-cop as a cross-check, not a replacement, for our native introspection/suggestion miner (our KB'd version already does the ranked-worklist reasoning these tools don't).

### 3. Betterleaks (Gitleaks successor, early 2026) — SKIP
New MIT-licensed fork/successor to Gitleaks by a former TruffleHog dev, independently governed, sponsored by Aikido. Fast unverified pattern-scan (150+ patterns, ms-speed) vs. our trufflehog `--only-verified` which already solves the exact FP problem (the documented 53%-token-shaped-noise pattern) by verifying liveness, not just shape.
- Verdict: **SKIP** — an unverified fast-scanner adds noise upstream of a pipeline that already gates on verification; no upgrade to our precision.

### 4. "doppel" (Rust BOLA/IDOR detector) — UNVERIFIED, do not act on
Search results repeatedly describe a "blazing fast zero-config BOLA/IDOR detector, Rust, session-swapping, mutational fuzzing, local AI via Ollama" but two separate searches never surfaced an actual repo URL — this pattern (confident description, no resolvable link) is consistent with a search-summarizer hallucination, not a confirmed real tool.
- Verdict: **DO NOT ADOPT** until a real repo URL is found and independently verified next run.

### 5. SubdomainSleuth (Yahoo) — SKIP for our use case
Reads BIND/RFC1035 **zone files** directly (plus NS/SOA and fingerprint-based HTTP checks derived from subjack) to find dangling records. Zone-file access implies you control/receive the target's authoritative DNS zone — not something available to an external bug-bounty hunter. Our CNAME+NXDOMAIN+unclaimed-fingerprint pattern (the reference-pattern lane) already covers what's usable of this externally.
- Verdict: **SKIP** — wrong threat model for us (defender tool, not external recon).

No genuinely new tool category surfaced for JS-intel, IDOR ranking, XSS/SQLi confirm, buckets, permutation-DNS, kiterunner-style route discovery, cache-deception, or blind-XSS this run — our existing stack still leads there.
