# Research digest — vulns — 2026-07-17

## Vuln/CVE + Writeup Watch — 2026-07-17 (last ~7-14 days)

### 1. WordPress miniOrange OAuth SSO — CVE-2026-57807 — Unauth Full Site Takeover, CVSS 9.8, **NO PATCH YET** ★ HIGH PRIORITY
- **What:** Auth bypass (CWE-288) in the miniOrange "OAuth Single Sign-On – SSO (OAuth Client)" plugin's password-recovery flow — an alternate path that skips authentication lets a remote unauthenticated attacker log in as any user, including admin, with no password/account/interaction.
- **Affected:** Enterprise builds ≤ 38.5.8. Free repo build is at 6.26.x — vulnerability applicability to the free branch is unconfirmed in current reporting; verify per-instance.
- **Patch status:** None from vendor as of 2026-07-13 (8 days post-disclosure). Only mitigation is disabling the plugin. Patchstack shipped a virtual patch for their customers only.
- **Detect (unauth, safe):** presence via `/wp-content/plugins/miniorange-oauth-2.0-single-sign-on/readme.txt` → `Stable tag`; also fingerprint via login page injected SSO button/JS bundle (`miniorange` string in jsintel). WordPress is a top-tech hit for us — this is worth a pass over in-scope WP hosts.
- **Action:** version-match = LEAD (no patched version exists yet, so match = in-range by default); do not exercise the password-recovery bypass without operator authorization — this is full account takeover, escalate per the hunt-flow "authed/exploit" gate before any live test.
- **Source:** [Orca Security](https://orca.security/resources/blog/kirki-wordpress-plugin-vulnerability-cve-2026-8206/) *(note: this URL slug is mislabeled Kirki but content covers the miniOrange flaw per search excerpt — verify article match before citing)*, [GBHackers](https://gbhackers.com/critical-wordpress-oauth-sso-plugin-flaw/), [NVD CVE-2026-57807](https://nvd.nist.gov/vuln/detail/CVE-2026-57807), [TheHackerWire](https://www.thehackerwire.com/cve-2026-57807-authentication-bypass-using-an-alternate-path-or-channel/)

### 2. WordPress Loco Translate — CVE-2026-15005 — CSRF-chained RCE, CVSS 8.8
- **What:** CSRF weakness combined with RCE in Loco Translate, disclosed by Wordfence 2026-07-15.
- **Affected:** all releases ≤ 2.8.5.
- **Caveat:** requires CSRF (a logged-in privileged user clicking a crafted link) — not directly unauth; treat as a LEAD needing the CSRF delivery vector, not a bare version match.
- **Detect:** `/wp-content/plugins/loco-translate/readme.txt` → `Stable tag` ≤ 2.8.5.
- **Source:** [Wordfence disclosure referenced via search](https://wp-safety.org/vulnerabilities) *(primary Wordfence advisory URL not directly captured — verify at wordfence.com/threat-intel before minting)*
