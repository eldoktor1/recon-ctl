# Research digest — vulns — 2026-08-18

## 1. NEW — Next.js July 2026 security release, CVE-2026-64642 + CVE-2026-64645 — both DIRECTLY testable unauth primitives, not just version-match ★★
Nine CVEs total; two are exactly the kind of thing our doctrine calls for — a **confirm primitive**, not a KEV tech-class match, because the bypass/SSRF is verifiable by direct probe regardless of exact patch version:

- **CVE-2026-64642 — middleware/proxy auth-bypass (High, GHSA-6gpp-xcg3-4w24).** App Router apps built with **Turbopack** + a **single entry in `config.i18n.locales`** let a crafted request skip the middleware entirely — any auth/security check the middleware performs is bypassed. Affected: Next.js **16.0.0–16.2.10**, fixed in **16.2.11** (also 15.5.21 LTS line, 16.3.0-canary.92+). **Detect/confirm (unauth, safe):** find a route that should require middleware-enforced auth (redirect to login / 401) on an in-scope Next.js host, then request it via the documented bypass pattern (locale-prefixed path manipulation) and check whether the protected response is served instead of the auth redirect — a genuine unauth-testable primitive, fits our "confirm not detect" doctrine directly.
- **CVE-2026-64645 — SSRF/open-redirect via `rewrites()`/`redirects()` (High, CVSS 8.3, GHSA-p9j2-gv94-2wf4).** A rewrite/redirect rule that builds its external destination hostname from **request-controlled input** can be pointed at an arbitrary host, ignoring the configured hostname suffix. Affected ranges go back to **12.0.0**; fixed in 16.2.11/15.5.21. **Detect/confirm:** exactly our SSRF/interactsh lane — find a Next.js rewrite/redirect route whose destination is influenced by a query param/path segment, point it at our interactsh canary, and check for the OOB callback. This is a real, safe, high-value addition to `recon_wcd.sh`/interactsh SSRF probing on any in-scope Next.js host.
- Also in the same release (lower priority for us — DoS-only or needs specific config, not our safe-probe scope): CVE-2026-64641 (Server Action CPU-exhaustion DoS), CVE-2026-64649 (Server Action SSRF via Host header on custom servers), CVE-2026-64644 (SVG image-optimization DoS, requires remote-image config), CVE-2026-64646 (Edge runtime memory-exhaustion DoS), CVE-2026-64643 (Server Function endpoint-ID disclosure — recon-value, feeds jsintel-style endpoint mining), CVE-2026-64648/64647 (fetch cache-confusion — narrow trigger shape).
- **Fingerprint:** `x-powered-by: Next.js` header (often stripped) or `/_next/static/<BUILD_ID>/_buildManifest.js` presence confirms Next.js; exact semver isn't remotely disclosed, so version-range alone stays a LEAD per doctrine — but 64642/64645 are probe-confirmable independent of exact version, which is the exception worth acting on.
- Sources: [Next.js official release](https://nextjs.org/blog/july-2026-security-release), [SentinelOne CVE-2026-64642](https://www.sentinelone.com/vulnerability-database/cve-2026-64642/), [HeroDevs CVE-2026-64645](https://www.herodevs.com/blog-posts/cve-2026-64645-next-js-ssrf-vulnerability-in-rewrites-and-redirects-explained-and-how-to-fix-it)
