## 1. GraphQL Automatic Persisted Queries (APQ) registration bypass — new confirm primitive that defeats "introspection disabled + allowlist-only" prod configs (HIGH PRIORITY, feeds `recon_graphql.sh` + `class-graphql.md`)

Distinct from the field-suggestion/Clairvoyance technique we already run: this targets APQ (Apollo/most GraphQL servers), a caching optimization that most ops teams don't realize is a second, unguarded execution path alongside the "locked-down" main endpoint.

- **Mechanism:** APQ is a 2-phase protocol. (1) client sends only `{"extensions":{"persistedQuery":{"version":1,"sha256Hash":"<hash>"}}}` — no `query` field; server replies `PERSISTED_QUERY_NOT_FOUND` if unseen. (2) client resends the SAME hash **plus the full query string**. Many servers accept and cache whatever query arrives in step 2 as long as its SHA-256 matches the hash — the registration step does not re-apply the allowlist/introspection-disabled checks the main endpoint enforces, so it becomes an attacker-controlled query registration channel.
- **Detection (safe, read-only, unauthenticated):** compute SHA-256 of `{__schema{queryType{name}}}` (or any harmless introspection query) locally, POST the hash-only probe, confirm `PERSISTED_QUERY_NOT_FOUND`, then POST hash+query. If the schema data comes back, the endpoint (a) supports APQ and (b) doesn't gate registration — introspection-disabled and allowlist-only claims are both bypassed via this side door. This is exactly `{__typename}`-tier read-only per our GraphQL doctrine — no mutation, no data query, just schema recon — so it fits the existing unauth-safe primitive set.
- **Actionable for `recon_graphql.sh`:** add as a fallback step when direct introspection is refused: try the APQ two-step with an introspection query as the "full query" payload. A success is a stronger LEAD than field-suggestion alone (it proves the allowlist itself is bypassable, not just that schema names leak) — still schema-disclosure only, never escalate to a sensitive query/mutation without the existing 2-owned-account gate.
- **Source:** [dev.to/roxdavirox — GraphQL APQ Registration Bypasses Query Allowlists and Introspection Controls](https://dev.to/roxdavirox/graphql-apq-registration-bypasses-query-allowlists-and-introspection-controls-20p2), related CVE pattern: CVE-2025-32034 (Apollo Router persisted-query bypass), CVE-2026-32594 (Parse Server WS variant, already tracked in our 2026-08-31 digest).
