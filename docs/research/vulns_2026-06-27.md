### UniFi OS Trio (CVE-2026-34908 / 34909 / 34910) | CISA KEV added 2026-06-23

**What:** Three KEV-listed vulns in UniFi OS — improper access control, path traversal, improper input validation. Actively exploited in the wild.

**Why it matters:** UniFi hosts dominate our IDOR surface. These are OS-level path traversal and access-control bypasses — distinct from the endpoint-IDOR we fan-out-suppressed — potentially reportable per-host if version-unpatched.

**Detection (unauthenticated):** Fingerprint via `/api/system` (returns `{data:{version:...}}`); look for UniFi login page at root or `X-Backend: UniFi`; version field exposed pre-auth. Compare version against patched ranges once Ubiquiti publishes them.

**Action:** Run `recon-nday` on UniFi-fingerprinted ES hosts. Version-confirm before escalating to anything beyond LEAD.

Source: [CISA KEV 2026-06-23](https://www.cisa.gov/news-events/alerts/2026/06/23/cisa-adds-four-known-exploited-vulnerabilities-catalog)

### Drupal Core SQLi on PostgreSQL (CVE-2026-9082) | CISA KEV | UNAUTH | Drupal "Highly Critical"

**What:** User-controlled PHP array keys reach SQL placeholder construction unsanitized. **PostgreSQL backend ONLY — MySQL/MariaDB/SQLite unaffected.**

**Auth required:** NO — unauthenticated exploitation confirmed.

**Affected:** Drupal 10.4.0–10.4.9, 10.5.0–10.5.9, 10.6.0–10.6.8, 11.0–11.1.9, 11.2.0–11.2.11, 11.3.0–11.3.9

**Fixed:** 10.4.10, 10.5.10, 10.6.9, 11.1.10, 11.2.12, 11.3.10

**Detection (unauthenticated):**
- Fingerprint: `/CHANGELOG.txt` or `/core/CHANGELOG.txt`, `X-Generator: Drupal` header, `X-Drupal-Cache` / `X-Drupal-Dynamic-Cache`
- Then confirm PostgreSQL backend (Drupal admin → Reports → Status, or probe for PG-specific error messages with intentional bad input)
- `recon-mood drupal` to pull matched ES hosts

**Action:** Pull Drupal hosts from ES → version-check → confirm PostgreSQL → if in range = real n-day candidate. LEAD until both version + DB engine confirmed.

Source: [Tenable](https://www.tenable.com/blog/cve-2026-9082-highly-critical-sql-injection-vulnerability-in-drupal-core-sa-core-2026-004)

## PRIORITY 2 — UNAUTH, EXPLOIT PUBLIC

### NGINX Critical Pair (CVE-2026-42530 + CVE-2026-42055) | CVSS 9.2 | F5 advisory June 2026

**CVE-2026-42530 — HTTP/3 use-after-free (`ngx_http_v3_module`):**
- Affected: NGINX Open Source 1.31.0–1.31.1; Plus R33–R37; Gateway Fabric / Ingress Controller variants
- RCE if ASLR disabled; otherwise DoS (worker crash)
- Detection: `Server: nginx/1.31.x`; `Alt-Svc: h3` or QUIC on UDP/443; probe with `curl --http3`

**CVE-2026-42055 — Heap overflow in proxy_v2 + gRPC modules:**
- Affected: NGINX Open Source 1.30.0–1.30.2 and 1.31.1; Plus R33–R37
- Triggered via oversized `large_client_header_buffers` (≥2MB) through gRPC or HTTP/2 proxy paths
- Detection: `Server: nginx/1.30.x`; look for `Content-Type: application/grpc` in responses

**Also:** CVE-2026-33032 — NGINX UI management tool (third-party admin UI, not core), reportedly exploited in the wild. Fingerprint: admin login at `:9000` or `/dashboard` with "Nginx UI" branding.

**Action:** ES query NGINX 1.30.x/1.31.x hosts. Confirm HTTP/3 (`Alt-Svc`) for 42530; gRPC endpoints for 42055. NGINX UI on exposed ports = immediate n-day candidate.

Sources: [BleepingComputer](https://www.bleepingcomputer.com/news/security/f5-issues-out-of-band-patches-for-critical-nginx-vulnerabilities/) | [SecurityWeek](https://www.securityweek.com/f5-patches-critical-high-severity-nginx-vulnerabilities/) | [CSA AL-2026-080](https://www.csa.gov.sg/alerts-and-advisories/alerts/al-2026-080/)

### Twig PHP Code Injection (CVE-2026-46633) — Symfony / Drupal / Craft CMS | UNAUTH if user controls template names

**What:** `Compiler::string()` fails to escape single quotes in `{% use 'name' %}` template names → breaks out of the surrounding PHP single-quoted string in the compiled Twig cache file → arbitrary PHP RCE on cache load. **Sandbox bypass: `SecurityPolicy` unconditionally allows `{% use %}` even in sandboxed templates — sandbox provides no protection.**

**Affected:** Twig < 3.26.0 (Symfony, Drupal, Craft CMS, Statamic, optionally Laravel)

**Auth required:** Only if the app allows user-controlled template names. Common vectors: CMS template editors, mail-template customization, page-builder tools with user-editable templates.

**Detection:** Error stack traces showing `Twig\`, `X-Powered-By: Twig`, Twig syntax in error messages, or `composer.json` exposure listing `twig/twig` < 3.26.0. Then look for any feature accepting user-supplied template names.

**Fixed:** Twig 3.26.0

Source: [Symfony Blog](https://symfony.com/blog/cve-2026-46633-php-code-injection-via-use-template-name)

## PRIORITY 3 — TECHNIQUE UPDATES (apply to existing lanes)

### GraphQL WebSocket Blind Spot + Two-Stage IDOR→SQLi (writeup April 2026, $2k Critical)

**Source:** [Medium — Ahmed Ghadban](https://medium.com/@DarkyOS/sql-injection-in-graphql-websocket-escalated-to-pii-document-leak-09ba7ad2800a)

**New angle:** WebSocket-based GraphQL endpoints (`/graphql-ws`, `/subscriptions`, `/ws`) are hidden from standard HTTP introspection probes and most scanners. They carry the same resolver logic but often lack WAF coverage.

**Kill chain:**
1. JS analysis → hidden `/graphql-ws` endpoint (not in HTTP schema)
2. IDOR on object-ref args — no ownership check, but 25-digit numeric IDs (not bruteforceable alone)
3. Type-mismatch input (alpha where numeric expected) → verbose PostgreSQL error → leaks table/column names
4. Error-based injection via type-cast failures → extract valid high-entropy IDs
5. Extracted IDs fed back into IDOR → access other orgs' legal documents + PII

**Key insight:** Neither the IDOR nor the SQLi alone was critical. Chained = critical. The injection point was the *ID type constraint*, not a string arg.

**Action:** When jsintel or `recon-kr` surfaces a WebSocket endpoint, probe independently from the HTTP GraphQL schema: (a) test object-ref arg ownership, (b) send type-mismatched inputs and watch for verbose DB errors.

### GraphQL Batch Query Abuse for IDOR Rate-Limit Bypass ($12,500 / CVSS 9.1, April 2026)

**Source:** [InfoSec Writeups — fintech GraphQL IDOR](https://infosecwriteups.com/graphql-security-how-i-found-and-exploited-critical-idor-and-authorization-bypass-in-a-42ab78e13642)

**Technique:** GraphQL batching (POST body as a JSON array of operations: `[{query:...},{query:...}]`) bypasses per-request rate limits. Auth existed at session level but was missing at object-ownership level on financial transaction mutations (`transactionId`, `accountId`).

**What's new:** Batching as the enumeration primitive for high-value IDOR when per-request rate limits would otherwise block it.

**Action:** When the hunter finds a GraphQL endpoint with ID-bearing mutations, test if it accepts batched operations. If yes, it's a more viable IDOR enumeration path. Note in the 2IC hunter's app model.

### Cache Deception via Framework-Specific Path Delimiters (PortSwigger Research 2026)

**Source:** [PortSwigger — "Gotta Cache 'Em All"](https://portswigger.net/research/gotta-cache-em-all)

**What's new vs prior WCD:** Prior technique appended `.js`/`.css` and hoped the CDN cached. This maps framework-specific path terminators the CDN doesn't recognize but the origin strips:

| Framework | Delimiter | Probe |
|---|---|---|
| Spring (Java) | `;` | `/account;.js` |
| Ruby on Rails | `.` (format) | `/account.css` |
| OpenLiteSpeed | `%00` | `/account%00.js` |
| Nginx | `%0a` (newline) | `/account%0a.js` |

CDN sees static extension → caches. Origin strips delimiter → serves dynamic auth'd response. Cache stores it under an attacker-accessible key.

**Normalization poisoning (WCP):** `%3F`/`%2F` combined with dot-segment traversal to make CDN cache path B while origin served path A.

**Cloudflare Armor bypass:** `.avif` and other non-standard extensions bypassed Cache Deception Armor at time of research.

**Affected CDNs in our scope:** Cloudflare, CloudFront, Google Cloud CDN.

**Action:** Add `;.js`, `%00.js`, `.css`, `%0a.js` delimiters to `recon_wcd.sh` probe list. Particularly relevant for Nginx+CloudFront and Spring+CloudFlare stacks.

### Rocket.Chat Post-Resolution SSRF / DNS Rebinding (H1 #3393664, ~June 2026)

**Source:** [HackerOne #3393664](https://hackerone.com/reports/3393664)

**Pattern:** Link-preview / webhook-fetch features that validate the hostname for local IPs *before* DNS resolution but *not after* are vulnerable. Register a domain resolving to 127.0.0.1 → server fetches it → internal network response leaked in preview.

**Not Rocket.Chat-specific** — any server-side URL fetch with this pre/post-resolution gap. Relevant for our SSRF probes on link-preview, image-proxy, and webhook-fetch features.
