# Research digest — tooling — 2026-07-17

## Tooling Watch — 2026-07-17

Spent 6 searches + 3 fetches (verified star counts / last-release dates directly on GitHub rather than trusting search snippets — two of three "actively maintained" claims from search summaries were wrong). Net: **1 EVALUATE**, rest SKIP or no action. Nothing here is an ADOPT — the honest read is our stack is still solid; most "new" hits are unmaintained/immature clones of tools we already run or gate-incompatible.

### 1. Hadrian (praetorian-inc) — API authz testing framework — **EVALUATE**
[github.com/praetorian-inc/hadrian](https://github.com/praetorian-inc/hadrian) — REST/GraphQL/gRPC, YAML-driven role definitions, v1.0.0 released 2026-03-26, 67★, 91.6% Go.
- Detects BOLA/BFLA via a **three-phase mutation proof**: Setup (role A creates+stores a resource ID) → Attack (role B attempts unauthorized modify/delete) → Verify (confirms the object actually changed). This kills the "200 OK but silently no-op'd" false-positive that status-code-only IDOR scanners produce.
- **Requires our own multi-role auth config** (`auth.yaml`/`roles.yaml`) — not unauth-safe, not autonomous-pipeline-eligible. But its shape is *exactly* our doctrine's "2 owned accounts, minimal PoC, prove impact then stop" — it's a candidate to **speed up the human-in-the-loop authed IDOR confirm step** (operator/Claude-in-Chrome currently does this by hand).
- Caveat: young (67★, first release 4 months ago), actively does state-changing modify/delete for proof — needs the same minimality discipline we already apply (test only owned objects, stop after proof). Worth a supervised trial run on one owned-2-account target before trusting it broadly.
- Verdict: **EVALUATE** — not autonomous-pipeline material, but a possible accelerant for the manual authed-IDOR swap workflow. Don't wire into the daemon.

### 2. Auto-IDOR-Hunter (Burp extension) — **SKIP**
[github.com/SecureByChaos/Auto-IDOR-Hunter](https://github.com/SecureByChaos/Auto-IDOR-Hunter) — passive proxy listener, mutates any object reference it observes (URLs/headers/cookies/JSON) across 12 bypass techniques, MIT license.
- 0★, no verifiable commit history, and — more importantly — it **auto-mutates every object ref it sees in live proxy traffic without confirming ownership**, which risks tripping our hard line (never enumerate/guess third-party IDs). Doesn't fit doctrine even ignoring immaturity.
- Verdict: **SKIP** — immature + doctrine-incompatible by design.

### 3. Subdominator (Stratus-Security) — takeover scanner — **SKIP (stale)**
[github.com/Stratus-Security/Subdominator](https://github.com/Stratus-Security/Subdominator) — 311★, 97 CanITakeOverXYZ-sourced fingerprints (vs subjack's 35), claims ~8x subjack's scan speed (19min vs 2.5hr for 100k subdomains).
- Technically ahead of subjack on paper, but **last release is Sept 2024 — 22 months stale as of today**, meaning fingerprint freshness (the whole value prop of a takeover tool) is unverified and likely behind CanITakeOverXYZ's current list. Not "active in the last 6-12 months" per our own bar.
- Verdict: **SKIP for now** — re-check in a future run if it resumes releases; not worth swapping our confirmed takeover primitive for a dormant repo.

### 4. GraphQL tooling landscape — no action
Search surfaced mostly commercial SaaS (Escape, StackHawk, Invicti, Bright) and a PortSwigger Burp extension (`graphql-security-tester`, AI-query-gen via Montoya) — the latter is a plausible *human-confirm* aid for authed GraphQL mutation testing but unverified maturity/star count; not pursuing this run given budget. `praetorian-inc/hadrian` above also covers GraphQL BOLA under the same framework. Our native introspection→worklist lane (`recon_graphql.sh`) remains correct for the unauth-safe autonomous side — nothing here replaces it.

### 5. jsluice / nuclei — confirmed still best-in-class
No credible alternative to jsluice for AST-based JS endpoint mining surfaced (search explicitly returned none). No credible open-source nuclei replacement for our exposure-template lane (alternatives suggested are full commercial DAST suites, wrong shape for us). No action needed — reinforces current stack, not a gap.
