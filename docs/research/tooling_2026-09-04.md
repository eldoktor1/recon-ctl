# Research digest — tooling — 2026-09-04

## 1. ADOPT — `ticarpi/jwt_tool` (fills a real gap: we have no JWT tool)
- **What it is:** The field-standard JWT testing toolkit (6.8k★, Python). Covers the full class-jwt-attacks.md attack surface in one tool: `alg:none` bypass, RS256→HS256 confusion (public-key-as-HMAC-secret), `kid`-header injection (SQLi/path-traversal/command-injection payloads), `jku`/`x5u` JWKS spoofing (built-in rogue JWKS server), high-speed HMAC-secret dictionary attack, claim fuzzing/scan mode, and timestamp tampering.
- **Why it matters:** we already have `docs/knowledge/class-jwt-attacks.md` but no tool anywhere in our stack (checked "ALREADY IN USE" list) actually exercises those attacks — it's currently manual curl/Burp work. jwt_tool mechanizes the whole class in one CLI pass against a captured token.
- **Doctrine fit:** this is explicitly **authenticated-testing territory** (you need a real token to tamper with) — same human-in-the-loop gate as our IDOR/authed flow, not an autonomous-daemon addition. Fits directly into the Program Workspace WSTG walk (ATHN/SESS categories) as an on-demand operator tool, same posture as Burp MCP.
- **Verdict: ADOPT** as the standard JWT tool inside the authed/Program-Workspace flow — not wired into any unauth daemon lane.

## 2. EVALUATE — `nxenon/h2spacex` (HTTP/2 single-packet race-condition CLI)
- **What it is:** Scapy-based Python library/CLI implementing James Kettle's "Last-Frame-Sync" single-packet attack for HTTP/2 (send N requests as one TCP packet, all arrive server-side simultaneously — turns remote race conditions into reliably-winnable local-race odds). 230★/19 forks, actively developed (pyproject.toml modernization, merged PRs on header parsing/connection setup, added `CONTRIBUTING.md` — real repo hygiene, not abandonware).
- **Why it matters to us:** we have `docs/knowledge/class-race-conditions.md` but, like JWT, **no tool** in our stack executes the primitive — and the one comparable tool surfaced previously (`PacketSprinter`, 2026-08-23 line) is a **Burp GUI extension**, which doesn't fit our headless/CLI pipeline. h2spacex is a scriptable library, so it composes with our existing automation model. It also **complements, not duplicates**, the already-EVALUATE'd `QuicDrawH3` (2026-08-23): QuicDrawH3 covers HTTP/3/QUIC races, h2spacex covers HTTP/2 — together that's protocol-version coverage for the whole race-condition class instead of the current zero.
- **Doctrine fit:** race-condition PoCs are inherently active/state-changing (e.g., double-redeem a coupon, double-apply a discount) — this is `feedback_active_poc_doctrine` territory: allowed on the operator's OWN account, minimal, confirm-then-stop. Not autonomous-daemon material.
- **Caveats:** young/low-traction relative to jwt_tool; verify it actually completes real HTTP/2 handshakes against our CDN-fronted estate (Cloudflare H2 front-ends can reorder/normalize frames) before trusting a negative result.
- **Verdict: EVALUATE** — trial against one BUSL-category WSTG test (e.g. a coupon/limited-use-code endpoint) on a program where we already have an owned account, alongside QuicDrawH3 for H3-terminating hosts.
