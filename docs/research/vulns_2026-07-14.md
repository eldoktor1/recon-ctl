# Research digest — vulns — 2026-07-14

## Vuln/CVE + Writeup Watch — 2026-07-14 (window: last ~30-60d visible in search index, most recent items surfaced)

### 1. W3 Total Cache — CVE-2025-9501 — unauth pre-auth RCE (HIGH VALUE, matches our top tech: WordPress+PHP)
- **What**: `PgCache_ContentGrabber::_parse_dynamic_mfunc()` runs `eval()` on comment-embedded `mfunc` tags found in cached pages. Regex sanitization uses `\s+` (requires spaces) but the parser uses `\s*` (allows none) → bypass persists **past the 2.8.13 patch, through 2.8.15**.
- **Affected**: W3 Total Cache ≤ 2.9.1 (1M+ active installs).
- **Prereqs**: comments enabled for unauth users on the target post, Page Cache feature active, and the site's `W3TC_DYNAMIC_SECURITY` constant value (usually secret — the real barrier; some configs leak it or use defaults).
- **Detect**: `/wp-content/plugins/w3-total-cache/` reachable, `readme.txt` version string, W3TC cache-control headers on responses. This is a real fingerprint we can pull from our jsintel/fulltext ES corpus (path + header), not just Wappalyzer `tech:`.
- **In-range-verifiable unauth**: YES — version fingerprint alone is a LEAD per doctrine (KEV-tech-class-without-verified-version rule applies the same way here); the security-constant requirement makes blind exploitation unlikely without further recon (comment-post + observe cache), so still human-verify before any injection attempt.
- Source: [RCE Security — full writeup + payload](https://www.rcesecurity.com/2025/11/exploiting-a-pre-auth-rce-in-w3-total-cache-for-wordpress-cve-2025-9501/), [NVD CVE-2025-9501](https://nvd.nist.gov/vuln/detail/CVE-2025-9501), [BleepingComputer](https://www.bleepingcomputer.com/news/security/w3-total-cache-wordpress-plugin-vulnerable-to-php-command-injection/)

### 2. New parser-discrepancy cache poisoning/deception techniques (PortSwigger Research, 2025) — directly extends our `recon_wcd.sh` lane
- Delimiter discrepancies between origin frameworks and front-end caches (`;` Spring/Java, `.` Rails, `%00` OpenLiteSpeed, `%0a` Nginx-rewrite, `#`) let a dynamic path get miscached as static, or let cache keys get poisoned via unresolved `../` traversal.
- Confirmed affected CDNs/proxies in our stack: **Cloudflare, CloudFront, Google Cloud** (all in our top-tech list) plus Akamai/Azure/Imperva/Fastly; origin servers **Nginx, Apache** (our top tech) plus IIS/OpenLiteSpeed/Spring/Rails.
- Concrete detect steps given (baseline vs delimiter-suffixed request diff) — directly pluggable into `recon_wcd.sh`'s existing cache-buster methodology as new probe variants.
- Source: [PortSwigger — Gotta Cache 'Em All](https://portswigger.net/research/gotta-cache-em-all)
