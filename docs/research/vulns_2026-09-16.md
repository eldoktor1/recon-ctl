# Research digest — vulns — 2026-09-16

## 1. NEW — CVE-2026-82923, "AI Website Builder" WP plugin — unauth RCE, **NO PATCH EXISTS** (remove-only) ★★
- **What:** REST API endpoints perform privileged actions (install plugins/themes, import content, write to `uploads/`, delete site content) with **zero caller-authorization or nonce check**. Writing an arbitrary file into `uploads/` → PHP execution → full compromise.
- **Affected:** v1.0.0 and earlier, **GitHub-distributed build only** (the WordPress.org repo build is unaffected — matters for fingerprinting, since two builds share a name).
- **CVSS:** 9.8. **No fix available** — vendor guidance is uninstall + manual must-use-plugin cleanup, so any live instance is exploitable indefinitely until removed.
- **Detect (unauth, safe):** `/wp-content/plugins/ai-website-builder/` present in page source/asset paths. Confirms plugin presence only — provenance of GitHub vs WP.org build isn't remotely visible, so treat as strong LEAD not auto-CONFIRMED.
- **Action:** rare plugin, low hit-rate expected on our corpus, but zero-patch + trivial REST-endpoint check makes it cheap to add to the WordPress fingerprint sweep (`recon-mood wordpress`). Don't fire the install/write primitive autonomously (state-changing/destructive).
- **Source:** [IONIX](https://www.ionix.io/threat-center/cve-2026-82923/)

## 2. WATCH — CVE-2026-75604, Next.js Windows-path-traversal RCE — companion to the AVIF RCE already in our 2026-09-01 digest, Windows-only
- Same Aug 25 security release as the AVIF/libheif RCE we already logged. Percent-encoded backslash in the URL isn't normalized before hitting the Next.js router; on a **Windows-hosted** deployment the backslash resolves as a path separator → traversal → RCE. Affects Pages Router + App Router (non–Cache-Components) on Next.js 13.4–15.5.23 and 16.0–16.3.2; fixed 15.5.24/16.3.3.
- **Relevance to us:** low — nearly all our targets are Linux/container-hosted (Vercel/Docker), and Linux/macOS are explicitly unaffected. Only worth checking if a target's `Server`/response fingerprinting suggests IIS/Windows behind Next.js (rare). No safe unauth detection primitive beyond version + OS-fingerprint; not worth an active probe.
- **Sources:** [The Hacker News](https://thehackernews.com/2026/08/nextjs-patches-critical-avif-and.html), [CyCognito](https://www.cycognito.com/blog/emerging-threat-cve-2026-75604-next-js-remote-code-execution-via-windows-path-traversal/)

No new movement this run on our core in-scope tech (Apache, Nginx, Varnish, Cloudflare, AWS/S3, jQuery) beyond what's already logged in the last 30 days — this week's CISA KEV additions (Sangoma Switchvox, Kestra, LiteLLM, JFrog Artifactory, SonicWall SMA1000, Cisco ISE/Email-Gateway/Firewall) don't map to our top-tech list or in-scope corpus. GraphQL/Cloudflare/S3-misconfig searches surfaced only evergreen guides, nothing new to log.
