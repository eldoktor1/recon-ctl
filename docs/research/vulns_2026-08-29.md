# Research digest — vulns — 2026-08-29

## 1. NEW — CVE-2026-42533, NGINX `map` directive heap buffer overflow — directly matches OUR detected in-scope version (nginx **1.29.7**) ★★
- **What:** Heap-based buffer overflow (CWE-122) in NGINX's `map` directive regex handling. Triggered when a `map` block uses **regex matching with unnamed/numbered captures (`$1`/`$2`)** and a later string expression references those captures after an earlier regex match changes capture state — a crafted HTTP request can overflow the allocated buffer. CVSS v4.0 9.2 / v3.1 8.1.
- **Affected:** NGINX Open Source **0.9.6 – 1.31.2**, NGINX Plus equivalent lines. Fixed in **1.31.3** (mainline) / **1.30.4** (stable), NGINX Plus 37.0.3.1 / R36 P7. Disclosed by nginx.org, patched **2026-07-15**.
- **Why this matters to us specifically:** our own detected in-scope tech list includes `Nginx:1.29.7` — that version falls squarely inside the vulnerable range (0.9.6–1.31.2). This is a genuine version-in-range match against our real corpus, not a hypothetical.
- **Detect (unauth, fingerprint-only):** `Server: nginx/1.29.7` header (or jsintel/Wappalyzer version string) confirms the binary version, but **exploitability is config-dependent** — it requires the target's `nginx.conf` to use a regex `map` with unnamed captures, which is NOT visible remotely. Version-in-range ⇒ LEAD only, per our KEV-tech-class-without-confirmed-config doctrine (same logic as the actuator/KEV clamp).
- **Action — DO NOT PROBE:** the only way to trigger this is a crafted request that causes a **worker crash (DoS)**, with RCE only achievable if ASLR is disabled/bypassed — this is a destructive primitive, not a safe unauth confirm, and firing it would crash a production nginx worker. Treat as version-match LEAD: flag any host actually running 1.29.7 (or any 0.9.6–1.31.2 build) for the operator to note the exposure and recommend the patch bump if it's our own infra, or file as an honest LEAD (unverified config) if it's a bounty target — never fire the crash trigger.
- **Sources:** [nginx.org security advisories](https://nginx.org/en/security_advisories.html), [SOC Prime analysis](https://socprime.com/blog/cve-2026-42533-analysis/), [Orca Security](https://orca.security/resources/blog/cve-2026-42533-nginx-heap-buffer-overflow/)
