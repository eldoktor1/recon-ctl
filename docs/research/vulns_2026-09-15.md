# Research digest — vulns — 2026-09-15

## 1. NEW — CVE-2026-78006 + CVE-2026-78159, The Events Calendar (WP plugin, 600k+ installs) — unauth chain to RCE/admin takeover, disclosed **yesterday (2026-09-14)** ★★★
- **Entry point is unauth and requires zero registration**: attacker submits a crafted **comment on an event page** (only requires comments enabled + "Show comments on event pages" active — common default).
- **CVE-2026-78006** (≤6.17.4, CVSS 9.8): PHP object-injection — plugin's deserialization safety check runs *after* `__unserialize()`/`__wakeup()` magic methods already fire; gadget chain via `Lazy_Post_Collection`/`array_map()` reaches OS command execution.
- **CVE-2026-78159** (≤6.17.3, CVSS 9.8): attacker plants malicious Gutenberg block markup inside a comment (WP comment sanitization preserves HTML comment delimiters Gutenberg parses as blocks); via preview-URL activation before moderation, `Element_Classes::parse_array()` reaches `wp_update_user()` with no capability check → **resets the admin password** → login as admin → upload plugin → RCE.
- **Fixed:** 6.17.4.1.
- **Detect (unauth, safe):** fingerprint via `the-events-calendar`/`tribe-events` in jsintel JS bundles or plugin asset paths; version via readme.txt stable tag. Confirms LEAD status (in-range = worth flagging), same as our other WP-plugin n-day pattern this month.
- **Don't auto-fire:** the actual PoC requires posting a comment that triggers deserialization/password-reset on a real site — that's an active, state-changing primitive (mutates the target's admin account), same authorization gate as WPvivid/Forminator/AI1WM this month. Flag for `recon-mood wordpress` sweep, operator confirm-then-stop only.
- **Sources:** [GBHackers](https://gbhackers.com/wordpress-events-calendar-vulnerabilities/), [Vulners CVE-2026-78006](https://vulners.com/cvelist/CVELIST:CVE-2026-78006), [cybersecuritynews.com](https://cybersecuritynews.com/critical-wordpress-plugin-flaws/)
