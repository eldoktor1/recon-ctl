### CRITICAL NGINX — Three in-range CVEs, all unauth-detectable

**CVE-2026-42945 — Heap Buffer Overflow in `ngx_http_rewrite_module` (CVSS 9.2, KEV-exploitation confirmed)**
- Versions affected: Nginx 0.6.27–1.30.0 (rewrite module is default-enabled; patched in 1.30.1+)
- Fingerprint: `Server: nginx/1.30.0` or earlier in response headers — any instance in that range is a candidate, no config uncertainty
- Unauth-verifiable: Yes — version string via HEAD is unauth safe. Actual exploitation is destructive so pipeline stops at LEAD from version detect
- **Action:** n-day lane — ES filter `Server: nginx` + version parse < 1.30.1; flag as n-day LEAD
- Source: [THN](https://thehackernews.com/2026/05/nginx-cve-2026-42945-exploited-in-wild.html), [nginx advisories](https://nginx.org/en/security_advisories.html)

**CVE-2026-42530 — HTTP/3 Use-After-Free in `ngx_http_v3_module` (Critical, RCE possible)**
- Versions affected: Nginx < 1.31.2 **with HTTP/3 enabled** (non-default; only hosts advertising `alt-svc: h3` are in range)
- Fingerprint: `alt-svc: h3=":443"` response header + `Server: nginx/1.30.x` or earlier. HTTP/3-enabled Nginx is rare → very low dup density
- Unauth-verifiable: Presence probe is a safe GET/HEAD. Actual trigger destructive — LEAD only
- **Action:** ES filter on `alt-svc` field containing `h3` + nginx < 1.31.2; high-value low-volume
- Source: [SOC Prime](https://socprime.com/blog/cve-2026-42530-critical-nginx-http-3-flaw-can-trigger-dos-and-possible-rce/)

**CVE-2026-49975 — HTTP/2 Bomb (HPACK amplification, affects Nginx + Apache, CVSS 7.5+)**
- Versions affected: Nginx < 1.29.8; Apache mod_http2 < 2.0.41; Cloudflare Pingora unaffected (architecture)
- Fingerprint: HTTP/2 active (`HTTP/2` in response line via curl `--http2`) + `Server: nginx/1.28.x` or `Apache/2.4.x` unpatched. 880k+ public servers exposed at disclosure
- Unauth-verifiable: HTTP/2 existence check is safe GET. DoS trigger is destructive → pipeline stops at LEAD; some programs pay for DoS-class n-days
- **Action:** n-day lane — ES HTTP/2 field + version range; NOTE that DoS bugs need explicit program payout check before investing
- Source: [THN](https://thehackernews.com/2026/06/new-http2-bomb-vulnerability-allows.html), [HAProxy blog](https://www.haproxy.com/blog/haproxy-cve-2026-49975-http-2-bomb-dos)

### HIGH — WordPress Plugins (unauth disclosure/bypass wave)

- Fingerprint: WP host + `gravitysmtp` in JS (jsintel) OR `/wp-content/plugins/gravitysmtp/` accessible. Probe: `GET /wp-json/gravitysmtp/v1/settings` unauth → keys in JSON = CONFIRMED disclosure
- Unauth-verifiable: Yes — single GET. Race window closing fast (mass exploitation underway)
- **Action:** jsintel endpoints.jsonl filter for WP hosts with `gravitysmtp` in JS bundles; probe immediately
- Source: [TNW](https://thenextweb.com/news/gravity-smtp-wordpress-plugin-vulnerability-cve-2026-4020-api-keys-exploit)

- Fingerprint: `/wp-content/plugins/burst-statistics/` + MainWP integration (check for `mainwp` in JS or `/wp-json/mainwp/`). Probe with crafted header = LEAD
- Unauth-verifiable: Header-spoof probe is safe (GET with crafted Authorization). Full admin confirm = human step
- Source: [CyberSecurityNews](https://cybersecuritynews.com/wordpress-plugin-vulnerability-exposes-websites/)

**CVE-2026-8206 — Kirki Customizer: Unauthenticated Privilege Escalation (CVSS 9.8)**

### TECHNIQUE — Cache Deception URL Parsing Variant (adds to existing WCD lane)

URL delimiter confusion (`;`, `%3B`, `//` injection before static extensions like `.js`, `.css`) to flip a `Cache-Control: private` response cacheable under the path-confused variant. Targets Cloudflare + Varnish normalization behavior specifically.

- Example probe: `GET /account/profile;.js?cb=<unique>` → second request → check `CF-Cache-Status: HIT` or `Age:` header while `/account/profile` stays `DYNAMIC/private`
- Pipeline's `recon_wcd.sh` unique-cache-buster primitive is the correct harness — add `;.js`, `%3B.css`, `/.js` as delimiter variants if not already in the probe set
- Source: [jsmon.sh](https://blogs.jsmon.sh/from-cache-poisoning-to-account-takeover-a-modern-web-security-case-study/)

### VALIDATED — GraphQL IDOR via Object-Type Arg Confusion ($12,500 payout writeup)

Introspection schema reveals mutations/queries with `userId: ID!` / `accountId: ID!` scalar args. Authorization checks the outer session but not the inner object lookup → cross-account access via ID swap in GraphQL variables. Exact pattern `recon_graphql.sh` was designed to surface.

- **Edge vs crowd:** Crowd stops at "introspection enabled" (Info dup). Edge = reason over schema for ID-typed args on sensitive object types, surface as 2-account IDOR lead
- Fingerprint: introspection returns types with `id`, `userId`, `orderId`, `accountId` scalar args
- Source: [InfoSec Write-ups](https://infosecwriteups.com/graphql-security-how-i-found-and-exploited-critical-idor-and-authorization-bypass-in-a-42ab78e13642)
