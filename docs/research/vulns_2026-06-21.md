### 🔴 PRIORITY 1 — CVE-2026-42945 "NGINX Rift": Our Nginx:1.29.7 IS IN RANGE

**What:** Heap buffer overflow in `ngx_http_rewrite_module` present for 18 years.

**Affected:** NGINX Open Source **0.6.27 – 1.30.0** / NGINX Plus R32–R36.
→ **Our corpus shows Nginx:1.29.7 — confirmed in range. Patch version is 1.30.1 / 1.31.0.**

**Exploitation conditions:**
- Requires a *specific non-default configuration* (exact directive not yet publicly documented in advisories).
- **RCE**: ASLR must be disabled — unusual on modern Linux, but plausible on appliances, legacy VMs, edge/embedded devices common in BB programs.
- **DoS** (worker crash/restart): no ASLR constraint. Easier bar, still impactful.
- Public PoC released at disclosure. Active exploitation confirmed against honeypots May 16 (4 days post-disclosure).

**Detection / fingerprint for our ES:**
- `Server: nginx/1.X.Y` header where X.Y < 1.30.1 — direct version match.
- Query ES: `tech:"nginx"` + version range filter; cross-check with `jsintel` and headers in crawl data.
- `recon-nday` + `recon-mood CVE-2026-42945 --tech nginx` to pull version-matched candidates.
- Confirm: `recon-nday` version-reasons the running version; a `nginx/1.29.7` Server header is the in-range signal.

**Severity / KEV status:** Actively exploited in wild → likely in CISA KEV or imminent addition. Treat as KEV-class until confirmed otherwise.

**Action:** Run `recon-mood CVE-2026-42945` against our ES. Any host exposing `Server: nginx/1.29.7` (or < 1.30.1) with the rewrite module in a non-default config → **n-day LEAD, P1 candidate**. Worth a targeted version-proof check per asset.

Sources: [Beazley Advisory](https://beazley.security/alerts-advisories/critical-18-year-old-rce-vulnerability-in-nginx-aka-nginx-rift-cve-2026-42945) · [HiveProThreatAdvisory](https://hivepro.com/threat-advisory/critical-nginx-vulnerabilities-including-18-year-old-rce-flaw-actively-exploited/) · [The Hacker News](https://thehackernews.com/2026/05/nginx-cve-2026-42945-exploited-in-wild.html)

### 🔴 PRIORITY 2 — CVE-2026-6722: PHP SOAP Extension Use-After-Free RCE (CVSS 9.5)

**What:** Use-after-free in PHP's SOAP extension — object deduplication via `id`/`href` XML attributes fails to increment reference counts, enabling UAF → RCE when SOAP processes attacker-controlled XML.

**Affected:** All PHP versions **< 8.2.31 / 8.3.31 / 8.4.21 / 8.5.6** — patched May 12 2026.

**Exploitation conditions:**
- SOAP extension must be enabled (`extension=soap`; it is **not** default-enabled on all distros but common on WooCommerce/enterprise PHP stacks).
- Endpoint must accept unauthenticated SOAP requests — where that's true, no creds needed.
- We run PHP in our top tech → relevant surface.

**Detection / fingerprint:**
- WSDL endpoints: `?wsdl`, `?WSDL`, `/api/soap`, `/soap/`, `.asmx`, `/wsdl`.
- Response `Content-Type: text/xml` with `<soap:Envelope>` or `<definitions xmlns=` = live SOAP.
- Error on malformed SOAP body: `SoapFault`, `PHP Fatal error: Uncaught SoapFault` in response = SOAP active + likely unpatched.
- Crawl data / jsintel: grep for WSDL references in JS, look for SOAP-typed API endpoints.

**Action:** `recon-mood CVE-2026-6722 --tech php` — version-reason each PHP host. Hosts running PHP in the affected range with discoverable SOAP endpoints = **n-day LEAD**.

Sources: [SecurityOnline](https://securityonline.info/php-security-patch-rce-soap-cve-2026-6722/) · [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-6722) · [CybersecurityNews](https://cybersecuritynews.com/php-soap-extension-vulnerabilities/)

### 🟢 TECHNIQUE NOTE — GraphQL IDOR Batch Query Pattern (April 2026 Writeup)

Fresh writeup confirmed real $12,500 payout: introspection enabled → batch query processing + IDOR on financial transaction objects. Pattern we already have in our GraphQL lane, but the **batch query amplifier** is worth noting: if a `nodes(ids: [...])` or `transactions(where: {id: {_in: [...]}})` field accepts arrays, a single batch request tests multiple object IDs — no need to loop individually. Localizes well to our schema-harvested worklist.
