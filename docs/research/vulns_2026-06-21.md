### 4. GraphQL WebSocket SQLi → IDOR Chain — Fresh Technique (April 2026 writeup, $bounty)

**Pattern:** `/graphql-ws` endpoint sending keepalive `{"type":"ka"}` → hidden operations in client JS (`readDocument`/`lockDocument` by ID) → fuzz the ID param with alphanumeric + specials → **verbose PostgreSQL error discloses schema** (column names, types) → inject `email` column via type-coercion → error-based extraction of 25-digit doc IDs → feed IDs into the authorization-blind GraphQL WS operation → full IDOR.

**Why this is a dup-edge:** `/graphql-ws` is almost never tested; most scanners only hit `/graphql`. The IDOR alone was unexploitable (high-entropy IDs), but the chained SQLi unlocked it. Classic "neither bug alone = finding, together = critical."

**Hunt action for our pipeline:**
1. Jsintel + crawl for `/graphql-ws`, `/graphql/subscriptions`, `/subscriptions` paths.
2. Send a WebSocket upgrade to those paths; capture operations from JS.
3. Fuzz ID/object-ref params with `'`, `"`, alpha, special → look for PostgreSQL/MySQL error strings in response body.
4. If SQLi fires → flag as LEAD for human to chain with authorization test (2-account setup per doctrine).

Source: [Medium writeup — DarkyOS](https://medium.com/@DarkyOS/sql-injection-in-graphql-websocket-escalated-to-pii-document-leak-09ba7ad2800a)

### 5. PHP CVE-2024-4577 — Still Actively Exploited by Ransomware (2026)

Not new, but operationally live: argument injection via Windows Unicode→ANSI best-fit in PHP-CGI, CVSS 9.8, **unauthenticated RCE**. Ransomware operators are hitting unpatched installs in 2026. Fixed in PHP 8.1.29 / 8.2.20 / 8.3.8.

**Detection:** Target must be Windows + Apache + PHP-CGI mode (not PHP-FPM/mod_php). Fingerprint: `X-Powered-By: PHP/8.x` where x < 29 (8.1) / < 20 (8.2) / < 8 (8.3), combined with `Server: Apache`, and a Windows OS indicator (IIS fallback headers, or Windows path in errors). Path to trigger: `/?%ADd+allow_url_include%3D1+…` pattern from existing PoCs.

**Our surface note:** Our top tech includes PHP + Apache HTTP Server. Worth running a targeted ES query: `tech:PHP AND tech:Apache` hosts → check PHP version string in `X-Powered-By` → if Windows + old version = LEAD.

Source: [halcyon.ai](https://www.halcyon.ai/blog/ransomware-operators-exploit-critical-php-vulnerability-for-rce)
