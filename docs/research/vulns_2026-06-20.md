### TIER 1 — IN-RANGE for our top tech, actionable now

#### 1. Nginx Rewrite Module Heap Overflow — CVE-2026-42945 ⚠️
- **Affected:** nginx 0.6.27–1.30.0 and Plus R32–R36
- **Our exposure:** We have `nginx/1.29.7` in scope → **IN RANGE**
- **Attack:** Heap buffer overflow in `ngx_http_rewrite_module` via unnamed PCRE captures (`$1`, `$2`) containing `?` in rewrite rules; triggers on rewrite→rewrite/if/set chains. Unauth network, CVSS 9.2.
- **Detection fingerprint:** `Server: nginx/1.25` – `1.30` banner (version probe from Server header or `curl -I`). The rewrite gadget requires a specific config; many hosts won't be exploitable, but the version range is the filter signal.
- **n-day action:** Add `nginx_rewrite_heap_cve` to `recon_nday.sh` fingerprint: `Server: nginx/1\.(2[5-9]|30)` on any paying host → LEAD (version-reason next: confirm rewrite module active via a malformed rewrite rule triggering a distinctive error before claiming exploitable).
- **Source:** Multiple HackerNews reports; verify CVE ID at nvd.nist.gov

#### 2. PHP SOAP Extension Use-After-Free — CVE-2026-6722 ⚠️
- **Affected:** PHP 8.2.x ≤8.2.30, 8.3.x ≤8.3.30, 8.4.x ≤8.4.20, 8.5.x ≤8.5.5
- **Our exposure:** PHP in top tech
- **Attack:** Double-free in SOAP `apache:Map` duplicate key handling → UAF → RCE. Unauth, CVSS 9.8. Triggered by any SOAP endpoint accepting user XML.
- **Detection fingerprint:** Endpoint returns `text/xml` or `application/soap+xml` content-type; jsintel/params catalog any host with `/soap`, `/ws`, `/service`, `/wsdl` paths. Version: `X-Powered-By: PHP/8.2.x` or `8.3.x` headers.
- **n-day action:** `recon-mood php` → filter for PHP 8.2–8.5 via version header → check jsintel for SOAP endpoint patterns → LEAD if present.
- **Source:** monstermegs.com/blog; verify at nvd.nist.gov

#### 3. Varnish Cache Auth Bypass + Cache Poisoning — CVE-2026-34475 ⚠️
- **Affected:** Varnish Cache < 8.0.1, Enterprise < 6.0.16r12
- **Our exposure:** Varnish in top tech
- **Attack:** Mishandled URLs with path `/` in HTTP/1.1 — canonicalization-before-validation (CWE-180) allows cache poisoning + auth bypass. CVSS 9.8.
- **Detection fingerprint:** `Via: 1.1 varnish` response header present; version from `X-Varnish-Cache-Version` or banner. Affected if Varnish < 8.0.1. Many CDN-front configs reveal version via jsintel-scraped headers.
- **n-day action:** ES query: `headers_text:varnish` + `headers_text:X-Varnish-Cache-Version` for version string; LEAD for any < 8.0.1 candidate. Confirm: send URL with path `/` variations and observe cache-key divergence.
- **Source:** github.com/advisories/GHSA-m9gq-cmcj-p62x (higher confidence — GitHub advisory direct link)

#### 4. Apache HTTP Server 2.4.66 HTTP/2 Double-Free RCE — CVE-2026-23918 ⚠️
- **Affected:** Apache 2.4.66 **only** (fixed in 2.4.67, May 4 2026)
- **Our exposure:** Apache HTTP Server in top tech
- **Attack:** HTTP/2 RST_STREAM after HEADERS frame triggers double-free in `mod_http2` → worker crash / RCE. Requires multi-threaded MPM (event/worker — not prefork). Unauth.
- **Detection fingerprint:** `Server: Apache/2.4.66` banner. Very specific version = precise LEAD filter, low FP rate.
- **n-day action:** ES full-text search `"Apache/2.4.66"` in `server_header` / `headers_text` → paying in-scope → version-reason note → LEAD if HTTP/2 enabled (H2 fingerprint from jsintel headers or `curl --http2 -I`). Flag for `recon_nday.sh`.
- **Source:** hadrian.io/blog/cve-2026-23918; thehackernews.com/2026/05/critical-apache-http2-flaw

#### 5. Drupal JSON:API SQL Injection — CVE-2026-9082 ⚠️
- **Affected:** Drupal 8.9–11.3.x (broad range)
- **Our exposure:** Drupal is less prominent in our top tech, but Drupal hosts appear in scope
- **Attack:** Unauth SQLi in JSON:API filter parameter **keys** (not values). Payload: `/jsonapi/node/article?filter[key';pg_sleep(5)--]=value`. On PostgreSQL backends → data extraction, potential RCE. CVSS 9.8.
- **Detection fingerprint:** `/jsonapi/` path returns JSON with `data[]` structure; `X-Drupal-Cache` or `X-Generator: Drupal` headers; `?_format=json` on `/user/login`. Time-delay payload against a paying Drupal host is the safe confirmation primitive (boolean diff, read-only).
- **n-day action:** `recon-mood drupal` or ES: `tech_text:Drupal` + has `/jsonapi/` in jsintel endpoints → test with `?filter[';pg_sleep(2)--]=x` (safe differential) → if time delay: CONFIRMED SQLi LEAD.
- **Source:** crowdsec.net/vulntracking-report/cve-2026-9082-drupal-jsonapi-sql-injection

### TIER 2 — RELEVANT TECHNIQUE/WRITEUP (not just a CVE)

#### 6. PortSwigger "Gotta Cache 'Em All" — URL Delimiter Cache Attacks (HIGH VALUE)
- **What:** URL parser discrepancies across CDN/origin pairs let you flip cache behavior using non-standard delimiters: semicolons (Spring), dots (Rails), null bytes (OpenLiteSpeed), newlines (nginx). Enables both cache poisoning and cache deception via paths that CDN caches as static but backend treats as dynamic.
- **Why novel for us:** Different attack surface from the standard WCD path-confusion we already run. Adds delimiter-variation testing as a second probe pass. Complements `recon_wcd.sh`.
- **Detection:** Any CDN-fronted host (CloudFront/Cloudflare/Akamai/Fastly/Varnish) + known tech framework → test path with `;`, `.`, `%00`, `%0a` suffixes → observe `CF-Cache-Status`/`Age` header for cacheability flip vs base path.
- **Source:** https://portswigger.net/research/gotta-cache-em-all (**high confidence** — direct PortSwigger research URL)
- **Action:** See `kb-proposal:class-cache-deception` below.

#### 7. DOMPurify Prototype Pollution → XSS Bypass — CVE-2026-41238 ⚠️
- **Affected:** DOMPurify 3.0.1–3.3.3 (fixed 3.4.0)
- **What:** PP into `Object.prototype.tagNameCheck`/`attributeNameCheck` fully bypasses DOMPurify sanitization. If a page has both a PP vector (lodash merge, query-string spread, JSON.parse + assign) AND uses DOMPurify to "safe" render, the chain gives stored/reflected XSS.
- **Why novel:** DOMPurify was the mitigation; now it's the gadget. Most scanners won't chain PP → DOMPurify version → XSS.
- **Detection:** JS-intel: scan for `dompurify` in loaded scripts + version string. `recon-domxss` already mines PP sources; add DOMPurify version check as an amplifier signal.
- **Source:** labs.trace37.com/blog/dompurify-pp-ceh-bypass
- **Action:** See `kb-proposal:class-domxss` below.

#### 8. WordPress Plugin SQLi — Elementor Ally (CVE-2026-2413) ⚠️
- **Affected:** Elementor Ally ≤ 4.0.3, ~250k–400k installs
- **Attack:** Unauth time-based SQLi in `get_global_remediations()` — `esc_url_raw()` used instead of SQL escaping. PostgreSQL target needed for full exploit; MySQL limited to boolean/time.
- **Detection:** Wappalyzer `tech:Elementor` + jsintel for `ally` or `alliance` JS references. Plugin can be fingerprinted by `/wp-content/plugins/elementor-ally/` path.
- **Source:** bleepingcomputer.com/news/security/sqli-flaw-in-elementor-ally-plugin
- **n-day action:** ES `tech:WordPress` + `tech:Elementor` hosts → probe `/wp-content/plugins/elementor-ally/` 200 vs 404 → present → LEAD for SQLi (safe `'` differential probe via `recon-params confirm sqli`).

#### 9. Joomla JCE Extension Unauth RCE — CVE-2026-48907 (CISA KEV, high confidence)
- **Affected:** JCE editor extension ≤ 2.9.99.4 (Joomla CMS)
- **Attack:** Fake editor profile creation + import abuse → arbitrary PHP execution. Actively exploited. CVSS 10.0.
- **Relevance:** Joomla not in our top-10 tech but appears in scope hosts. Joomla is fingerprinted by `/media/jce/` paths, `X-Joomla-Session` cookie, `generator` meta tag.
- **CISA KEV:** Added June 16, 2026 — https://www.cisa.gov/news-events/alerts/2026/06/16/cisa-adds-one-known-exploited-vulnerability-catalog
- **Detection:** jsintel `/media/jce/js/` or `/administrator/` path → Joomla host → check JCE version via `/index.php?option=com_jce&format=json&task=plugin.getimageinfo` (version disclosed) → < 2.9.99.5 = LEAD.

for delim in ';' '%3b' '.' '%00' '%0a'; do
  curl -sk "https://$HOST/DYNAMIC_PATH${delim}.css?_cb=$RANDOM" \
    -H 'Cache-Control: no-cache' \
    -D - | grep -i 'cf-cache-status\|x-cache\|age:'
done
```
LEAD condition: delimiter variant returns `CF-Cache-Status: HIT` or `Age: N` where base path returns `DYNAMIC` / `no-store`.

### Safety note
Always include a unique cache-buster (`?_cb=<random>`) so you test under YOUR own cache key — never poison the shared CDN cache users hit.

### FP filter
- If base path itself caches (`CF-Cache-Status: HIT` without delimiter) → by-design static asset, not WCD.
- `Cache-Control: no-store` or `private` on BOTH base AND delimiter path → secure, not cacheable.
