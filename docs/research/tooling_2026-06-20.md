### EVALUATE — Subdominator (supplemental CT source sweep)

**https://github.com/RevoltSecurities/Subdominator** — 780 stars, v3.0.1 released 2026-05-30, actively maintained.

Async Python, 73 passive OSINT sources vs. subfinder's ~50. Key delta: covers additional threat-intel feeds and DNS dataset sources subfinder doesn't query. Disk-backed dedup cache handles 100K+ subdomain runs without memory spikes.

- Doctrine fit: fully passive read-only — clean
- Dup-resistance: additive, not a replacement; value is the ~20 source delta
- Integration: drop-in alongside subfinder, pipe output the same way

**Action:** Run as a secondary sweep on programs where surface coverage matters most (mature programs with well-established subdomains, where the marginal new host is the edge). Do NOT replace subfinder — speed and integration are unmatched. Test on one program, compare unique output vs. subfinder alone.

### EVALUATE (human-in-the-loop only) — Hadrian (GraphQL BOLA role-matrix tester)

**https://github.com/praetorian-inc/hadrian** — 65 stars, v1.0.0 2026-03-xx, Go, Apache 2.0.

Tests REST/GraphQL/gRPC for BOLA/BFLA with a 3-phase setup→attack→verify using role-pair YAML definitions. 13 GraphQL templates specifically for cross-role object access. You define "role A owns object X, role B should not access it" — it runs the matrix systematically.

- **Doctrine problem: sends mutating requests, requires auth config, does create→attack→verify cycles.** Cannot touch this autonomously against live targets.
- **Why it matters:** This IS the systematic BOLA cross-test workflow for GraphQL that we currently do manually with ad-hoc curl chains. Once we have 2 accounts on a GraphQL target and our native tool has recovered the schema + ranked the IDOR-candidate operations, Hadrian could run the full role-matrix verification against a staging environment rather than us hand-crafting every request.
- Gap it fills: our idor_candidates ranking surfaces the leads; Hadrian runs the structured proof. Nothing else open-source does this for GraphQL specifically.

**Action:** Note in class-graphql.md as the human-assisted BOLA confirmation tool. Never in the autonomous pipeline. Use when: schema recovered → sensitive object-ref mutation identified → 2 accounts available → operator runs Hadrian on staging.

### UPDATE — WCVS (latest release)

**https://github.com/Hackmanit/Web-Cache-Vulnerability-Scanner** — January 2025 release improved WCD detection to check for cacheability flip even when no cache indicator (`CF-Cache-Status`, `Age`, `X-Cache`) is present on the response.

- Before: could miss WCD on CDN configs that suppress cache headers on the base response
- After: probes cacheability directly, not just by header presence

**Action:** `pip install --upgrade wcvs` or check the release tag on the repo. Low-friction, directly improves `recon_wcd.sh` yield on CDNs that don't emit explicit cache status headers.
