# Research digest — vulns — 2026-08-15 (pass 2)

Prior passes today already covered CVE-2026-64638 (XSS2Shell) and wp2shell (CVE-2026-63030/60137, KEV-added per CISA). This pass found two genuinely new WordPress **plugin** CVEs — both unauthenticated, both CVSS 9.8, both fit our existing WP-fingerprint detection pattern (`readme.txt` Stable tag).

## 1. CVE-2026-8206 — Kirki (page builder/customizer plugin) — unauth admin takeover via password-reset email confusion ★
- **What:** `handle_forgot_password()` in the `CompLibFormHandler` class REST endpoint accepts an attacker-supplied email instead of validating against the target account's registered email — submit a crafted reset request with `{username: admin, email: attacker@...}` and the reset link goes to the attacker. Zero creds, zero interaction beyond the request.
- **Affected:** Kirki "Freeform Page Builder, Website Builder & Customizer" 6.0.0–6.0.6. (Patch version not stated in source — verify current stable before treating as fixed.)
- **Detect (unauth, in-range-verifiable):** `GET /wp-content/plugins/kirki/readme.txt` → `Stable tag`; also fingerprint via the Kirki customizer JS bundle (`kirki` string) in jsintel on any of our WordPress hosts. This clarifies/corrects the 2026-07-17 digest, which cited this same Orca URL but mislabeled its content as miniOrange — the article is actually about Kirki, not miniOrange.
- **Action:** version-match (≤6.0.6) = LEAD. The exploit itself is a live account-takeover primitive (issues a real password-reset email to an attacker-controlled address) — do NOT fire it autonomously; this needs the authed/exploit-authorization gate per doctrine before any live test.
- **Source:** [Orca Security](https://orca.security/resources/blog/kirki-wordpress-plugin-vulnerability-cve-2026-8206/)

## 2. CVE-2026-28139 — Ajax Search Lite (WordPress plugin, live-search/filter) — unauth PHP Object Injection
- **What:** Unauthenticated PHP Object Injection (PHPOI) — untrusted input reaches `unserialize()` somewhere in the plugin's request handling. Impact depends on gadget chains available in the install (core/other-plugin classes) — could range from DoS to RCE; not automatically RCE on every site.
- **Affected:** through 4.14.4. **Patched: 4.14.5**, disclosed 2026-08-04 (11 days old).
- **Detect (unauth, in-range-verifiable):** `GET /wp-content/plugins/ajax-search-lite/readme.txt` → `Stable tag`. Widely deployed live-search plugin — worth a pass over in-scope WordPress hosts (`recon-mood wordpress`) for this readme fingerprint alongside the Kirki one above.
- **Action:** version-match (<4.14.5) = LEAD. PHPOI exploitability is gadget-chain-dependent and unproven without a specific PoC chain for this codebase — do not attempt live deserialization payloads; flag as LEAD only pending a public gadget-chain writeup.
- **Sources:** [Patchstack](https://vdp.patchstack.com/database/Wordpress/Plugin/ajax-search-lite/vulnerability/wordpress-ajax-search-lite-plugin-4-13-3-php-object-injection-vulnerability), [WPScan](https://wpscan.com/plugin/ajax-search-lite/)
