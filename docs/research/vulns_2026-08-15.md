# Research digest — vulns — 2026-08-15

## 1. CVE-2026-64638 "XSS2Shell" — WordPress core pre-auth login XSS → PHP RCE chain ★ HIGH PRIORITY, directly hits our top tech
- **What:** Reflected XSS on `wp-login.php` via a `strip_tags`/KSES parser differential in the `log` (username) field — unauthenticated, no interaction beyond visiting a crafted login URL. Chained with Same-Origin Method Execution, it can escalate to PHP code execution when a logged-in **admin** clicks the link (full chain needs admin interaction + specific deployment conditions; the XSS itself is unauth and CVSS-relevant on its own).
- **Affected:** WordPress core 6.4 – 7.0.2 (very wide range — nearly every live install). **Patched: 7.0.3** (+ backports to supported branches through 4.7), released 2026-08-06.
- **Detect (unauth, in-range-verifiable):**
  - `POST /wp-login.php` with the `log` param containing URL-encoded `<` (`%3C`) — a real username never contains brackets, so this is anomalous/probe traffic, not a passive fingerprint. For version-gating: WP version from `readme.html`, `?ver=` query strings on core `wp-*.js/css`, or REST root `/wp-json/` response.
  - Escalation-stage indicators (if hunting for exploitation, not planting it): REST calls with `_jsonp=` callbacks containing dots, `_method=GET`/`_envelope=1` params, hits to `wp-admin/authorize-application.php` with an off-origin `success_url`.
- **Action:** version-range LEAD (patched 9 days ago, so unpatched instances = laggards, decent signal). Do NOT plant the XSS payload live — per doctrine XSS requires EXECUTION confirmation via dalfox against our own probe, and the admin-interaction leg is out of scope for autonomous testing. Worth a version sweep of our in-scope WordPress hosts (`recon-mood wordpress` + version fingerprint) to flag pre-7.0.3 instances as LEAD.
- **No ITW exploitation / no public PoC** as of publication (2026-08-07). Discovered by pwn.ai.
- Source: [Hadrian.io writeup](https://hadrian.io/blog/wordpress-xss2shell-unauthenticated-login-screen-xss-to-php-code-execution-cve-2026-64638), [TheHackerNews](https://thehackernews.com/2026/08/new-wordpress-pre-auth-xss-could-lead.html)

## 2. CVE-2026-28139 — Ajax Search Lite plugin, unauth PHP Object Injection, CVSS 9.8
- **What:** Unauthenticated PHP Object Injection in the popular "Ajax Search Lite" WordPress plugin (widely deployed search widget). Object injection → potential RCE if a suitable POP gadget chain exists on the target (plugin/theme dependent, standard PHP unserialize risk).
- **Affected:** ≤ 4.14.4. **Patched: 4.14.5**, published 2026-08-04.
- **Detect (unauth, in-range-verifiable):** plugin presence via `/wp-content/plugins/ajax-search-lite/readme.txt` → `Stable tag`, or the plugin's frontend JS bundle / `asl_*` AJAX action names in jsintel. Confirm version before treating as more than tech-class match.
- **Action:** version-gated LEAD; don't attempt the unserialize primitive without a confirmed gadget chain — that's an active-exploitation step requiring operator authorization per the exploit-gate doctrine.
- Source: [search aggregation](https://www.penligent.ai/hackinglabs/wordpress-vulnerabilities/) — verify against plugin changelog/wordpress.org SVN before citing further; treat CVE detail as unconfirmed-secondary until NVD record is checked.

## 3. CVE-2026-50052 — Varnish Cache HTTP/2 request smuggling (narrow, lower priority)
- **What:** Deficiency in HTTP/2 request parsing enables a backend request-desync (smuggling) attack → cache poisoning / auth bypass / info disclosure. Same class as the CVE-2026-34475 auth-bypass we flagged 2026-07-28.
- **Affected:** Varnish Cache < 9.0.3 (and Vinyl Cache fork < 9.0.1). **Only exposed when HTTP/2 is explicitly enabled** (`+http2` feature flag) — disabled by default, which meaningfully narrows real-world exposure.
- **Detect (unauth):** Varnish doesn't reliably banner version — presence via `X-Varnish`/`Via: varnish` headers only (tech-match, not version-confirmed). HTTP/2 support itself is externally observable (ALPN negotiation) and is a precondition worth checking before treating a Varnish host as in-range.
- **Action:** LEAD only, and narrower than the 07-28 Varnish item (requires non-default config). No PoC/ITW reported. Not worth an active sweep unless a Varnish host is also confirmed serving HTTP/2.
- Source: [SentinelOne CVE-2026-50052](https://www.sentinelone.com/vulnerability-database/cve-2026-50052/)
