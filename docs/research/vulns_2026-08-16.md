# Research digest — vulns — 2026-08-16

## 1. NEW — WooCommerce Subscriptions PHP Object Injection → RCE, CVE-2026-18391 — unauth, hits our top-tech (WordPress/PHP) ★
- **What:** `unserialize()` is called on user-supplied input without validation when High-Performance Order Storage (HPOS) is enabled. A crafted serialized payload triggers a gadget chain in bundled dependencies → RCE. **No authentication required.**
- **Affected:** WooCommerce Subscriptions < 9.1.0 (4.7.0 cited as an in-range example). Fixed in 9.1.0.
- **Detect (in-range-verifiable):** any WooCommerce host — check `wc-subscriptions`/`woocommerce-subscriptions` plugin readme/version string in jsintel or `/wp-content/plugins/woocommerce-subscriptions/readme.txt` `Stable tag`. Vulnerable state also needs HPOS enabled (not remotely visible) — treat plugin-version-in-range as a LEAD, HPOS status unknown until authed/behavioral check.
- **Action:** version-match = LEAD only (exploit requires crafted PHP-serialized gadget chain — not a safe unauth probe per our doctrine; don't fire). Worth a `recon-mood` sweep for WooCommerce Subscriptions on our WordPress-fingerprinted hosts.
- Source: [Freshysites bulletin](https://freshysites.com/security-bulletins/woocommerce-subscriptions-plugin-vulnerability-cve-2026-18391/)

## 2. NEW — PHP core security release (8.5.9 / 8.4.24 / 8.3.33 / 8.2.33, 2026-08-03) — 4 CVEs, top-tech version bump
| CVE | Component | Type | CVSS | Affected | Note |
|---|---|---|---|---|---|
| **CVE-2026-17543** | ext-pgsql (`pg_insert`/`pg_update`/`pg_select`/`pg_delete`) | SQLi — escaping functions don't escape backslashes, breaks out of `E'...'` literal | High | pre-8.5.9/8.4.24/8.3.33/8.2.33 | Only apps using ext-pgsql with those functions; not remotely fingerprintable beyond PHP version. Not our top-tech (MySQL dominates), low priority. |
| **CVE-2026-17544** | bcmath `bccomp()` | OOB write, stack+heap corruption | **9.8 CRIT** (CVSS v3.1) | PHP 8.4.0–8.4.23, 8.5.0–8.5.8 | Needs an app calling `bccomp()` with attacker-controlled input (money/decimal-math endpoints) — app-behavior-gated, not banner-visible. |
| CVE-2026-7260 | Phar extension | Crash via recursive symlinks | — (DoS) | pre-patch | Requires phar file processing; DoS-only, out of our safe-probe scope. |
| CVE-2026-9672 | bundled libgd | Image-processing memory corruption | — | pre-8.5.9/8.4.24 | Needs image-upload/GD-processing functionality. |
- **Detect:** PHP version via `X-Powered-By` header (often suppressed) or error banners. All four require specific app functionality (Postgres backend / bcmath calc / phar handling / image upload) beyond mere version-in-range — **version match alone is only a weak LEAD**; pair with functional-surface signal (jsintel/fulltext hits for `pg_`, decimal/money calc, `.phar`, image-upload endpoints) before treating as more than tech-class noise.
- Sources: [LinuxCompatible](https://www.linuxcompatible.org/story/php-8333-and-8424-released-critical-security-fixes-for-pgsql-sqli-and-bcmath-memory-corruption/), [NVD CVE-2026-17544](https://nvd.nist.gov/vuln/detail/CVE-2026-17544)
