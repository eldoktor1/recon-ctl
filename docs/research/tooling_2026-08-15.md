## Tooling Watch

### 1. Nosey Parker → **DEAD, confirms Titus is the right target** (update to 2026-07-19 EVALUATE)
Nosey Parker (Praetorian) — the AST/ML secret scanner we were about to evaluate as a trufflehog complement — was **archived April 24, 2026** and is officially retired in favor of its successor **Titus** (`praetorian-inc/titus`), which we already flagged EVALUATE-high-priority on 2026-07-19. No action needed beyond what's already queued — just don't waste a cycle evaluating Nosey Parker itself, it's dead. If Titus evaluation hasn't happened yet, this is a nudge to prioritize it: it's now the *only* live option in that lineage.
- Source: [praetorian-inc/noseyparker](https://github.com/praetorian-inc/noseyparker)

### 2. Subdominator (Stratus-Security) — takeover fingerprint upgrade — **EVALUATE**
`Stratus-Security/Subdominator` — 311★, actively maintained, claims 97 provider fingerprints (vs Subjack's 35 / Subdover's 80), recursive DNS + intelligent domain matching to cut FPs, and a built-in validation pass to confirm exploitability rather than just flag CNAME-dangling. Benchmarked at ~19min vs 2+hrs for Subjack/Subdover on 100k subdomains.
- **Fit:** our takeover lane already has a solid custom multi-stage NXDOMAIN+claimability primitive (the reference-pattern lane in CLAUDE.md) — this isn't a replacement for that logic, but its larger fingerprint DB could catch providers our current fingerprint set misses, feeding *more* candidates into the same confirm primitive.
- **CAUTION — naming collision:** there's a second, unrelated repo also called "Subdominator" (`RevoltSecurities/Subdominator`, also active, last release v3.0.2 Jun 2026) that does **subdomain enumeration**, not takeover detection. Don't conflate the two if adopting — the takeover one is `Stratus-Security/Subdominator`.
- **Verdict: EVALUATE** — pull its fingerprint list to enrich our existing takeover confirm primitive's provider DB; don't adopt it as a standalone scanner (our multi-stage NXDOMAIN+claimability check is already more rigorous than a fingerprint-match tool).
- Source: [Stratus-Security/Subdominator](https://github.com/Stratus-Security/Subdominator)

### 3. BurpAPISecuritySuite (Teycir) — authed-IDOR Burp extension — **SKIP (conflicts with owned-ID-only hard line)**
150★, actively developed (v1.4.15, 112 commits), Burp extension with a "Role Delta" feature that diffs guest/user/admin behavior per-endpoint to rank BOLA/BFLA suspects — same concept as Autorize (which we already use, per `reference_burp_mcp_and_automation`). Beyond that it runs "intelligent fuzzing campaigns" (15 attack types, 108+ payloads) against captured API traffic.
- **Fit problem:** automated ID/payload fuzzing against live authed endpoints risks touching non-owned object IDs — exactly what our hard line prohibits (2-owned-accounts-only, never guessed/enumerated third-party IDs). Role Delta's diff-only mode overlaps with Autorize we already run; the added fuzzing surface is the risky, non-doctrine-compliant part.
- **Verdict: SKIP** — no capability gap it fills that Autorize + our manual A/B swap flow doesn't already cover, and its extra automation mode is a doctrine risk, not a win.
- Source: [Teycir/BurpAPISecuritySuite](https://github.com/Teycir/BurpAPISecuritySuite)

No other genuinely new candidates surfaced this pass — the rest of the sweep (JSpider, generic "bug bounty recon 2026" listicles, REST-fuzzers like CATS/Schemathesis/WuppieFuzz requiring an OpenAPI spec we usually don't have) were either unmaintained solo projects, spec-dependent tools outside our unauth/blind-recon model, or repeats of prior digests.
