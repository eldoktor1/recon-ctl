#### 1. BadDNS (`blacklanternsecurity/baddns`) — Takeover Detection
**GitHub:** https://github.com/blacklanternsecurity/baddns | Stars: 441 | Last release: v2.4, **Jun 9 2026**

What it does that nuclei + our existing heuristics don't:
- **`references` module** — scans each host's HTML for third-party domains used in `<script src>`, `<link>`, CSP headers, etc., then checks if *those* external domains are takeover-vulnerable. This is **second-order takeover**: the target embeds a JS include from `cdn.abandonedservice.io` which is unclaimed — the crowd never finds these because they only scan the target's own DNS records.
- **NSEC-walking** — harvests subdomains from DNSSEC zone records (passive enumeration vector; no DNS brute-force traffic).
- **Auto-sync signatures** from nuclei-templates + dnsReaper repos via GitHub Actions pipelines — fingerprints stay current without manual updates. Fixes the stale-fingerprint problem (April 2026: nuclei removed Netlify/Shopify/Azure templates because those services now enforce TXT claim verification; BadDNS auto-pruned these already).
- **11 modules total**: CNAME, NS, MX, NSEC-walk, references, TXT, zone-transfer, DMARC, MTA-STS, wildcard, SPF.

**Verdict: ADOPT.** Wire into the post-enum host pass. Run standalone (`baddns -t <host>`) or as a BBOT module. The `references` module for second-order takeover and NSEC-walking have no equivalent in our current stack. dup-resistant by design — second-order leads are nearly uncontested.

#### 2. graphql-cop (`dolevf/graphql-cop`) — GraphQL Lane
**GitHub:** https://github.com/dolevf/graphql-cop | Stars: 672 | Last release: v1.16, **Nov 20 2025**

Tests 12 categories in a single CLI call: introspection, **field suggestions** (the clairvoyance-style guaranteed-invalid near-miss probe we currently hand-roll in `recon_graphql.sh`), alias overloading, batch queries, GET-based queries, directive overloading, CSRF vectors. GET-only safe checks; no mutations executed for the detection probes.

**Verdict: ADOPT.** Drop into `recon_graphql.sh` after the introspection gate. Automates the field-suggestion loop we currently build manually. Small Python binary, single `pip install graphql-cop`.

Also: **Clairvoyance** (`nikitastupin/clairvoyance`, v2.5.5 **Dec 2025**) — if `recon_graphql.sh` currently hand-rolls the field-suggestion loop, replace that section with clairvoyance (1.5k stars, actively maintained, JSON schema output). graphql-cop calls field-suggestions as a quick pass; clairvoyance does the deep schema reconstruction for introspection-off targets. They're complementary.

### ACTION (not a new tool — wordlist hygiene): Kiterunner + Assetnote Monthly Refresh

Fix: add a monthly cron to `recon_kr.sh` that refreshes from `wordlists.assetnote.io` before each run. The binary is fine; the wordlists are not.
