# Research digest — tooling — 2026-09-01

## Bottom line
Three concrete items this run: a JS-secret miner that directly targets our own documented 53%-FP problem, an authz/BOLA testing framework that complements the AuthProbe pick from 2026-08-15, and a new critical nginx HTTP/3 CVE worth a version-gate (no active-exploit tooling needed or wanted — it's a DoS/UAF primitive, banner-check only).

## 1. EVALUATE/ADOPT-candidate — `cc1a2b/JShunter` (533★, MIT, active 2024–2026, v0.6)
- **What it is:** Go CLI, JS endpoint extraction + secret detection. The differentiator is its **confidence pipeline**: per-rule baseline score adjusted by Shannon entropy (≥4.5) + char-class diversity (+0.05 each), vendor/chunk-bundle path penalty (-0.15), fixture-context penalty (-0.30), sourcemap-URL-marker exclusion, plus **per-provider structural validators** (AWS prefix check, Stripe key-family check, GitHub CRC32, JWT/Slack/Twilio) that run *after* the regex match — the strongest FP defense, per their own docs. v0.6 adds a **live verifier** for credential liveness (same shape as trufflehog `--only-verified`). Default `--min-confidence 0.50`, tunable to 0.80 for stricter precision.
- **Why it matters to us specifically:** our own CLAUDE.md documents `js_secret_hit` firing on **~53% of the corpus = noise** — token-shaped strings, not secrets — and our current fix is a manual exclude-list (Supabase anon/Stripe `pk_`/Firebase config/OAuth `client_id`). JShunter's scoring pipeline is a more systematic version of exactly that exclusion logic (vendor-noise denylist + fixture-context penalty + validators), and its live-verifier is redundant with trufflehog `--only-verified` rather than a replacement.
- **Doctrine fit:** unauth-safe ✅ (static JS analysis, no live requests beyond the liveness-verify step which mirrors what trufflehog already does), dup-resistant — this is an FP-*reduction* tool for a lane we already run, not new attack surface.
- **Verdict: EVALUATE** — run it head-to-head against `engine/impact.py`'s current secret-classification on a sample of the corpus that historically triggers the 53% FP rate; if its confidence scoring meaningfully cuts false `secret_leads.jsonl` volume without losing true positives, fold its scoring heuristics (not the binary itself — keep jsluice for AST `urls` extraction, which JShunter doesn't do) into `engine/impact.py::scan_secrets`.

## 2. EVALUATE — `praetorian-inc/hadrian` (75★, Apache-2.0, active, backed by Praetorian)
- **What it is:** REST/GraphQL/gRPC authorization-testing framework from Praetorian (established offensive-security firm, not a solo academic release). YAML-driven: define roles + auth per role, it **cross-tests every role combination against every endpoint** for BOLA/BFLA, using "three-phase mutation testing" (create → attempt cross-role access → verify the mutation actually occurred, not just an HTTP 200).
- **Why it matters:** complements the 2026-08-15 `AuthProbe` pick — AuthProbe is read-only diff-based BOLA-only; Hadrian adds **BFLA** (function-level, not just object-level) and gRPC, and is backed by a known security firm rather than a single academic author. Same fit as AuthProbe against our locked authed-IDOR SOP (`feedback_authed_idor_burp_flow`) — mechanizing the enumerate-then-differential step once we have 2 owned accounts.
- **Caveat — this one is NOT read-only:** docs explicitly warn it creates/modifies/deletes real resources and to test against staging first. That's a harder gate than AuthProbe: fits our `feedback_active_poc_doctrine` (own-account, minimal, non-malicious) ONLY if scoped to the researcher's own 2 accounts with `--dry-run` reviewed first — never run against a shared/production dataset, never past a minimal single-object mutation.
- **Verdict: EVALUATE**, lower priority than AuthProbe (fewer stars, destructive-by-default) — trial only after AuthProbe, on a target with an OpenAPI/GraphQL spec + 2 owned accounts, `--dry-run` first, single-mutation only.

## 3. New n-day — CVE-2026-42530: nginx HTTP/3 QPACK use-after-free (CVSS 8.1/9.2, nginx 1.31.0–1.31.1, patched 1.31.2)
- **What it is:** unauthenticated remote attacker reopens a QPACK encoder stream over HTTP/3 → UAF in the nginx worker → crash/DoS, RCE possible if ASLR is off/bypassable. Disclosed June 2026, patched in nginx 1.31.2 / 1.30.3.
- **Why it matters to us:** **Nginx and HTTP/3 are both explicitly on our in-scope top-tech list.** This is exactly the kind of KEV-tech-class match our doctrine says needs a **confirmed in-range version**, not a blind fire — and firing a UAF primitive at a live host is a DoS by construction, which our non-destructive doctrine forbids outright. No nuclei template exists publicly (searched — none found), and none should be built for the active-exploit form.
- **Action:** version-gate only, via `recon_nday.sh`'s existing banner/version-reasoning path — flag any ES host fingerprinted as nginx 1.31.0 or 1.31.1 (Server header / error-page banner) as a LEAD, never auto-probe. `Nginx:1.29.7` (our current catalogued version signal) is below the vulnerable range and not itself a match — this is a forward-looking watch for any host that has since updated into 1.31.x.
