## 1. Automatic Persisted Queries (APQ) — false sense of safety, and how to detect it (NEW section for class-graphql.md)
The doc mentions "persisted queries" once in passing but never documents that **APQ is not an allowlist**. This is a genuine operator-facing misconception worth killing: a target running Apollo-style APQ can *look* locked down (client sends only a SHA-256 hash) while still executing arbitrary operations.

- **Mechanism:** APQ is a bandwidth optimization, not a safelist. Client sends `{"extensions":{"persistedQuery":{"sha256Hash":"..."}}}` with no `query` field. If the server hasn't cached that hash, it replies `PersistedQueryNotFound`. Sending the SAME request again but **with the full `query` string attached** makes most Apollo-style servers execute it normally — and then cache it under that hash for future reference. Full introspection, aliasing, deep fragments, or brute-force mutation attempts all still work on the first request; APQ is orthogonal to authorization.
- **The real safelist is different:** Apollo GraphOS Enterprise offers a distinct feature, **Persisted Query Lists (PQL)** — a server-maintained allowlist that rejects any operation not pre-registered. Only PQL (not bare APQ) actually restricts the operation surface. Don't assume "persisted queries enabled" = locked down; confirm which of the two is in play before deprioritizing a target.
- **Detection (safe, read-only):** send a `sha256Hash` that's clearly not cached (random 64-hex) → expect `PersistedQueryNotFound`. Then resend the identical request with a full `query:"{__typename}"` attached. A 200 with data confirms APQ-not-PQL — i.e., the introspection/mutation/IDOR worklist built elsewhere in this doc still fully applies despite the client only ever sending hashes in normal traffic (so it was likely never fuzzed by scanners that only replay captured HAR traffic verbatim).
- Sources: [Apollo GraphQL Docs — Automatic Persisted Queries](https://www.apollographql.com/docs/apollo-server/performance/apq), [Apollo GraphOS — Safelisting with Persisted Queries](https://www.apollographql.com/docs/graphos/platform/security/persisted-queries), [Crawlee — Reverse engineering GraphQL persistedQuery extension](https://crawlee.dev/blog/graphql-persisted-query)
