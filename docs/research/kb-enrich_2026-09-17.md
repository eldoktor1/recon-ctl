## 1. Race conditions — lightweight detection + multi-endpoint limit-overrun chaining (`class-race-conditions`)
Burp 2026 added native parallel-request grouping in Repeater ("Send group in parallel"), giving the same single-packet/last-byte-sync mechanics as Turbo Intruder without a Jython script — lowers our tooling bar for the authed/human-in-loop race tests we already do. [hackcraft.gr](https://www.hackcraft.gr/2026/04/race-conditions-and-where-to-find-them/)

**Systematic race-spotting framework** (useful for the WSTG walk, not ad hoc): for any endpoint ask (1) is state stored server-side and persistent, (2) does the op modify vs. merely add (modifications = higher risk), (3) do concurrent requests key to the *same* resource. Common vulnerable flows: email activation, invitation acceptance, multi-step checkout. [hackcraft.gr](https://www.hackcraft.gr/2026/04/race-conditions-and-where-to-find-them/)

**Multi-endpoint chain (Nov 2025 writeup, directly maps to our own-account doctrine):** racing the free-plan *create-site* endpoint bypassed the plan's site-count check, producing extra (initially nonfunctional) site records under the researcher's OWN account. A **sibling read endpoint** (`/upstreams`) leaked paid-framework UUIDs to any caller. Deploying the race-created (owned) site IDs against those paid UUIDs unlocked paid features on a free account — full logic bypass, zero third-party data touched. This is our exact "own 2 accounts, race + ID-substitute, never guess someone else's ID" pattern — worth folding into IDOR/race combined hunting: when we see a create-then-read-elsewhere pair of endpoints, test the RACE window on create + ID reuse against the sibling endpoint, all on owned resources. [Mahmoud Gamal, Medium](https://medium.com/@mhmodgm54/race-condition-chained-with-logic-bug-leads-to-full-bypass-of-free-plan-site-limit-5825f5e2cb1c)

**Protocol gate:** single-packet attack requires HTTP/2 (`curl -s --http2 -o /dev/null -w '%{http_version}'` to confirm before attempting); HTTP/1.1 falls back to last-byte sync (µs jitter, not zero). An IP-fragmentation extension pushes past the 1500B single-packet / 65535B TCP-window ceiling — 10,000 requests landing in ~166ms — useful only for very wide batches (coupon/limit farms), not typical 2-request differential races. [PortSwigger turbo-intruder examples](https://github.com/PortSwigger/turbo-intruder/blob/master/resources/examples/race-single-packet-attack.py), [hackcraft.gr](https://www.hackcraft.gr/2026/04/race-conditions-and-where-to-find-them/)

Reference payouts to calibrate severity expectations: HackerOne #429026 (bounty-platform retest → multiple payouts), HackerOne #1913309 (Firefox Monitor email-limit bypass via concurrent registration), CVE-2022-4037 (GitLab email-verification race → account takeover). [YesWeHack race-condition guide](https://www.yeswehack.com/learn-bug-bounty/ultimate-guide-race-condition-vulnerabilities)



## 2. CDN "trusted validation path" WAF-disable pattern — generalize beyond the (now-patched) Cloudflare ACME bug (`class-cdn-origin-bypass`)
Cloudflare disclosed (Jan 21 2026, patched Oct 27 2025) that its ACME domain-validation path `/.well-known/acme-challenge/{token}` was designed to **disable WAF/edge rules entirely** before serving, because a CA validating a live cert-issuance challenge can't tolerate WAF interference. The bug: the disable happened *before* token verification, and a request bearing a token belonging to a *different* zone still slipped through to the customer's origin unfiltered — global WAF bypass to origin, ~90 days between report and public writeup. [TheHackerNews](https://thehackernews.com/2026/01/cloudflare-fixes-acme-validation-bug.html), [Security Affairs](https://securityaffairs.com/187156/security/acme-flaw-in-cloudflare-allowed-attackers-to-reach-origin-servers.html), [The Register](https://www.theregister.com/2026/01/20/cloudflare_fixes_acme_validation/)

**Don't test Cloudflare for this exact bug — it's globally patched.** The actionable takeaway is the *pattern*: every major CDN ships its own "must reach origin unfiltered" exception for domain-validation/health-check/internal paths (Cloudflare's ACME challenge path is one instance; Akamai, Fastly, CloudFront+ACM, Google Cloud CDN each have analogous well-known paths for their own DV/health-check flows). Given our top in-scope tech includes Cloudflare, CloudFront, Google Cloud CDN, and Varnish, this is worth a standing safe check per CDN vendor.
