# Research digest — vulns — 2026-09-06

## 1. NEW — CVE-2026-19632, TranslatePress — unauth admin account takeover, DIRECTLY testable (not just version-match) ★★★
- **What:** The plugin's `trp_get_translations_regular` AJAX action is registered for both authed AND unauthenticated (`nopriv`) requests, and returns translated string data without restricting access to sensitive content — including the admin's plaintext password-reset key when it has been auto-saved as a translatable string. An unauthenticated attacker calls the AJAX action, extracts the reset key, and takes over the admin account. CWE-640 (weak password recovery).
- **Trigger conditions (narrows exposure but doesn't require auth):** TranslatePress's "automatic string saving" feature enabled (**default ON**) + the admin account's locale set to a secondary, published language on the site (common on any genuinely multilingual site — the plugin's whole purpose).
- **Affected:** TranslatePress ≤ 3.3.1 (400k+ active installs). Fixed in **3.3.2** (released 2026-08-13).
- **CVSS:** 9.8.
- **Detect + CONFIRM (unauth, safe, read-only — fits our "confirm not detect" doctrine directly):** fingerprint TranslatePress via `/wp-content/plugins/translatepress-multilingual/readme.txt` `Stable tag` or `trp-` asset paths in jsintel. Then call the `trp_get_translations_regular` AJAX action unauthenticated (`/wp-admin/admin-ajax.php?action=trp_get_translations_regular`) and check whether the response leaks a password-reset-key-shaped string — this is a genuine safe unauth probe, not exploitation, and settles real-vs-LEAD without needing an authed step.
- **Action:** version-match (≤3.3.1) = LEAD; the AJAX-leak check upgrades it to CONFIRMED on any host where the key actually appears in the response (info-disclosure primitive, non-destructive — reading, not resetting, the password). Worth a `recon-mood wordpress`/`translatepress` sweep.
- **Sources:** [IONIX](https://www.ionix.io/threat-center/cve-2026-19632/), [securityonline.info](https://securityonline.info/translatepress-account-takeover-vulnerability/)

## 2. NEW — CVE-2026-19598, Everest Forms — unauth arbitrary file upload → RCE, continues the Aug file-upload-bypass run ★★
- **What:** `EVF_Form_Fields_Upload` class does inadequate file-type/path validation on the plugin's form file-upload field, letting an unauthenticated visitor upload a `.php` webshell through any published form with a file-upload field. Same bug family as Elementor Pro / Forminator (2026-08-20/22 digests) — this is now the fourth WP file-upload-bypass CVE this month.
- **Affected:** Everest Forms < 3.0.9.5 (100k+ active installs). Fixed in **3.0.9.5**.
- **CVSS:** 9.8. **Prerequisite:** site has a published Everest Forms form with a file-upload field (visible in rendered DOM, no probe needed).
- **Detect (unauth, in-range-verifiable):** `/wp-content/plugins/everest-forms/readme.txt` → `Stable tag`; `everest-forms`/`evf-` strings in jsintel bundles.
- **Action:** version-match (<3.0.9.5) + form-with-upload-field present = LEAD (same tier as Elementor Pro/Forminator). Don't fire the upload autonomously. Add to `recon-mood wordpress` sweep.
- **Sources:** [cybersecuritynews.com](https://cybersecuritynews.com/wordpress-everest-forms-plugin-flaw/)
