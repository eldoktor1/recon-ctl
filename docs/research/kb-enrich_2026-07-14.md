# Research digest — kb-enrich — 2026-07-14

## Research Digest — kb-enrich (2026-07-14)

Two of our highest-EV money-pillar docs (GraphQL, IDOR/BAC) have concrete, unauth-safe additions from 2023-2025 research that we don't yet capture. Both fit our existing confirm-primitive discipline (read-only, LEAD-not-P0, human-confirms-impact).

### 1. GraphQL batching/aliasing as a **rate-limit-bypass detector** (`recon_graphql.sh` extension)
PortSwigger's "GraphQL batching & aliases" research (popularized 2023, still the dominant technique driving 2024-2025 bounty payouts per Checkmarx/Wallarm writeups) shows query batching lets a single HTTP request execute hundreds of GraphQL operations — server-side rate limiters that count HTTP requests (not operations) miss this entirely. This is directly testable **unauth and read-only**: send N aliased copies of a cheap, side-effect-free query (e.g. `{__typename}` or a public query already in our allowlist) in one POST and diff the response count against N single requests — if all N execute where individual-request rate limiting would have blocked after M<N, that's a LEAD (`graphql:ratelimit-bypass`) worth flagging for a human to try against a real target (login/OTP/password-reset mutation, NOT tested by us directly — those are mutations, stays human-owned). Nested-field authorization gaps (top-level query authorized, nested resolver fields not) are the companion finding pattern.

### 2. IDOR/BAC — parameter-pollution & array-wrapping bypass forms (`recon_idor_candidates.py` scoring + `class-idor.md`)
Recent writeups (2024-2025 Medium case studies, OWASP A01:2025) document that when a direct ID-swap IDOR is blocked/validated, these payload SHAPES routinely bypass the same check because backend frameworks auto-coerce them:
- Duplicate param (HPP): `user_id=<mine>&user_id=<victim>` (last-wins in most frameworks, first-wins in some — try both orders)
- Array wrap: `{"user_id":[<victim>]}` or `{"user_id":[<mine>,<victim>]}`
- Nested-object wrap: `{"user":{"id":<victim>}}`
- Type-juggle: numeric ID sent as string or vice versa
Also flagged: **mass assignment** (auto-binding request JSON onto backend models — a client can add an unexpected field like `role` or `is_admin` if the endpoint doesn't allowlist bindable fields) is a documented adjacent BAC class with active 2024-2025 academic tooling (arXiv 2405.01111, 2301.01261) and a fresh fuzzing paper specifically on broken access control (arXiv:2507.15984, "BACFuzz", July 2025).

These are all HUMAN-confirmed-with-2-owned-accounts per our hard line — the addition is to the *worklist/testing checklist* a human runs when a direct-swap IDOR 403s, not a new autonomous probe.
