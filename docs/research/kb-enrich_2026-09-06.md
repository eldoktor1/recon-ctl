## 1. Argo CD — three new 2026 CVEs deepen `tech-argocd.md` (unauth full-takeover + authed secret-extraction)

Our doc only had CVE-2025-55190 (authed token → repo creds). Three more landed since, one of which is a genuine **unauthenticated** critical:

- **CVE-2026-82456 (CVSS 10, argocd-mcp 0.8.0, unauth):** the `argocd-mcp` MCP-server sidecar binds its HTTP transport to *all* interfaces and accepts MCP sessions with **zero credential check** whenever `ARGOCD_API_TOKEN` is configured — any network-reachable attacker gets full use of the operator's stored token (create apps, force syncs, mutate resources). Fingerprint: MCP-server port reachable pre-auth alongside an Argo CD instance. Distinct product from argocd core — worth a dedicated unauth check if we see an MCP listener near an Argo CD host.
- **CVE-2026-42880 / CVE-2026-43824 (CVSS 9.6, same root cause — likely duplicate/renumbered, reconcile before citing one over the other):** Argo CD masks `Secret` data on every state-returning endpoint via `hideSecretData()` **except** `ServerSideDiff`. A **read-only** account with only `applications get` RBAC (the default role every authenticated user gets) can pull cleartext K8s Secret values through the ServerSideDiff dry-run path, on an Application annotated `compare-options: IncludeMutationWebhook=true`. Affected: `>=3.2.0 <3.2.11` and `>=3.3.0 <3.3.9`; fixed 3.2.11/3.3.9. Exact endpoint path withheld by disclosers (responsible-disclosure redaction) — version-gate + note as authed-LEAD (needs an operator-held low-priv token) per our KEV-clamp rule, don't assume the exact request shape.
- **Low-effort bonus check (old but cheap, 2024 CVE GHSA-87p9-x75h-p4j2):** unauth `GET /api/v1/settings` disclosed config on `>=2.9.3,<2.9.17 / <2.10.12 / <2.11.3` — almost certainly patched everywhere now, but a one-request freebie to fold into the existing `/api/version` fingerprint pass since it costs nothing.

Sources: [thehackerwire.com — argocd-mcp](https://www.thehackerwire.com/argocd-mcp-critical-auth-bypass-resource-control/) · [cybersecuritynews.com — ServerSideDiff](https://cybersecuritynews.com/argo-cds-serversidediff-vulnerability/) · [endorlabs.com CVE-2026-42880](https://www.endorlabs.com/vulnerability/cve-2026-42880) · [bugzilla.redhat.com CVE-2026-43824](https://bugzilla.redhat.com/show_bug.cgi?id=2464613) · [GHSA-87p9-x75h-p4j2](https://github.com/argoproj/argo-cd/security/advisories/GHSA-87p9-x75h-p4j2)
