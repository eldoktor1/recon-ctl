## 1. WordPress wp2shell — KEV status update: BOTH CVEs now KEV, deadline set
Previously flagged 2026-07-19 (CVE-2026-63030 REST batch confusion + CVE-2026-60137 SQLi). New since then: **CVE-2026-60137 (SQL injection in `WP_Query`) was added to CISA KEV on 2026-07-21** alongside 63030 — this is no longer just the RCE chain, the SQLi component is independently KEV-listed and exploitable standalone (data read/write without auth) even without the RCE chain. BOD 26-04 deadlines: 63030 by 2026-07-24 (passed), 60137 by 2026-08-04. Wiz/Patchstack confirm active ITW webshell deployment.
- Affected: WP core 6.8.0–6.8.5 (SQLi only), 6.9.0–6.9.4 + 7.0.0–7.0.1 (full chain). Fixed: 6.8.6 / 6.9.5 / 7.0.2 / 7.1 Beta 2.
- Detect (unauth): `/wp-json/batch/v1` reachability (or `?rest_route=/batch/v1`) + core version via `readme.html`/`?ver=` script query strings. Version-in-range = confirmed LEAD per doctrine; both CVEs are KEV so treat as high-priority sweep on any in-scope+paying WordPress host.
- Action: rerun `recon-nday` against WP hosts in ES — this now clears the KEV bar on the SQLi alone, not just the harder-to-fingerprint RCE chain.
- Sources: [Help Net Security](https://www.helpnetsecurity.com/2026/07/18/wordpress-vulnerabilities-wp2shell-cve-2026-60137-cve-2026-60137/), [Wiz](https://www.wiz.io/blog/wp2shell-cve-2026-63030-cve-2026-60137), [Tenable FAQ](https://www.tenable.com/blog/wp2shell-cve-2026-63030-cve-2026-60137-frequently-asked-questions-about-remote-code-execution)

## 2. Varnish Cache — CVE-2026-34475 auth-bypass/cache-poisoning: full detail (prior digest was cut off)
- **What:** CWE-180 (validate-before-canonicalize failure) in HTTP/1.1 absolute-form URI parsing. `req.url` VCL var gets passed unchecked to a backend that accepts absolute-form URIs — attacker-controlled root-path (`/`) requests can poison the cache or bypass auth. **Attack surface limited to root URLs (`https://host/`) — deeper paths (`https://host/whatever`) are NOT affected.**
- **Affected:** Varnish Cache ≤ 8.0.0, 6.0 LTS ≤ 6.0.16; Varnish Enterprise ≤ 6.0.16r11. Fixed: Varnish Cache 8.0.1 / 6.0.17, Enterprise 6.0.16r12+.
- **Detect (unauth, safe):** `Via: 1.1 varnish` / `X-Varnish` response headers give presence; version is rarely banner-exposed, so treat any Varnish-fingerprinted host as version-unknown → LEAD, not confirmed-in-range (matches Varnish already on our top-tech list).
- **Relevance:** directly extends `recon_wcd.sh` — this is a root-path-specific WCD/WCP variant with a named CVE, not just a generic cache-key confusion. Worth a root-path-only probe variant in the WCD lane (our cache-buster-per-probe safety primitive still applies).
- Sources: [SentinelOne](https://www.sentinelone.com/vulnerability-database/cve-2026-34475/), [GitHub Advisory GHSA-m9gq-cmcj-p62x](https://github.com/advisories/ghsa-m9gq-cmcj-p62x), [Varnish VSV00018](https://vinyl-cache.org/security/VSV00018.html)

## 3. PHP SOAP extension — CVE-2026-6722, use-after-free RCE (CVSS 9.5) — narrow but critical if present
- **What:** Use-after-free in SOAP's object-deduplication map: a crafted SOAP body with duplicate `apache:Map` keys frees a PHP object while a stale pointer remains referenced; attacker reclaims freed memory via string allocation → RCE.
- **Affected:** Any PHP < 8.2.31 / 8.3.31 / 8.4.21 / 8.5.6 **that actually processes SOAP requests** (extension must be loaded and app must expose a SOAP endpoint — this is the real gate, not just "PHP present"). Patched across all branches 2026-05-12.
- **Detect (unauth):** look for WSDL endpoints (`?wsdl`, `.wsdl` paths) or SOAP `Content-Type: text/xml`/`application/soap+xml` handling in jsintel/fulltext ES — a much narrower fingerprint than our blanket PHP tech-tag. Without a live SOAP endpoint this CVE is inapplicable, so don't blanket-flag PHP hosts.
- **Action:** worth one targeted ES full-text query for WSDL/SOAP endpoint strings across in-scope PHP hosts; if any surface, they're a confirmed-in-range LEAD (patched in May, so any hit is stale software).
- Sources: [SentinelOne](https://www.sentinelone.com/vulnerability-database/cve-2026-6722/), [Pinaka](https://pinaka.sh/blog/cve-2026-6722-php-soap-use-after-free-rce/), [Security Online](https://securityonline.info/php-security-patch-rce-soap-cve-2026-6722/)
