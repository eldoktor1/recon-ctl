## Bottom line
No genuine new-tool ADOPT this pass. Raw GitHub search for "2026 bug bounty tool" is now heavily polluted with single-author/AI-slop repos (0–3 stars, one commit, no forks) — worth a standing note to prefer curated sources (vendor blogs, Bug Bytes, official org repos) over star-count GitHub search, and to demand real commit/contributor history before considering anything found that way.

## Checked, no action needed
- **AuthProbe** (jbarach2012/AuthProbe) — unchanged since the 2026-08-15 digest (still 145 stars, still 5 commits, no new releases visible). Stays **EVALUATE-pending** trial on one host with 2 owned accounts + a real OpenAPI spec; nothing to update yet.
- **PortSwigger/graphql-security-tester** (official PortSwigger org, Burp extension, "Montoya AI"-generated GraphQL attack queries) — official backing but essentially unused: 3 stars, 0 forks, gated behind Burp AI credits. **SKIP** — too immature to trust, and it duplicates what `recon-graphql` + `graphw00f` (already in our `class-graphql.md`) already cover for free.
- **turbo-intruder** and **graphw00f** — both surfaced again in this pass's searches (race-condition and GraphQL-fingerprinting respectively) but both are already documented in `class-race-conditions.md` / `class-graphql.md`. No new capability found.
- **CLTEcho** (AI-hyped request-smuggling suite, claimed July 2026 update) — could not verify: the repo URL from search results 404'd, and no legitimate mirror found. Treat as unverified noise, not a candidate.

## Worth flagging (not a new tool, a build-note)
`class-request-smuggling.md` already picked up an empirical entry from an 2026-08-16 sweep (15 hosts / 8 front-end stacks, zero desync) plus a sharp FP-pattern writeup ("self-pipelining" — `CL:0`+trailing-bytes on one socket looks like desync but is just RFC pipelining answering its own next request). The real discriminator it documents — **count `HTTP/1.1 ` response lines per single isolated probe; 1→2 with no follow-up sent = signal, content-inspection ≠ signal** — is exactly the confirm-primitive logic the still-unimplemented Smugglex lane (ADOPT'd 2026-07-28, no `recon_smuggling.sh` exists yet) will need to get right, or it'll reproduce the same FP the manual sweep just burned an evening on. If/when that lane gets built, wire its confirm step around that discriminator rather than re-deriving it.

No kb-new or kb-proposal this run — nothing surfaced met the bar for a durable addition beyond what's already recorded.
