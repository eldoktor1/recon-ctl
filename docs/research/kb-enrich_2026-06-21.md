## KB Enrichment Digest — 2026-06-21

### Topic 1: GraphQL WebSocket Subscriptions — Uncovered Attack Surface

Recent April 2026 disclosed reports confirm GraphQL-over-WebSocket (`graphql-ws` protocol) carries two high-value vulnerability classes our current lane completely misses:

1. **Token-only-on-connect gap** (Shopify disclosed): the WS transport validates the JWT once at `connection_init`, then never revalidates per-message. A user whose role was revoked mid-session, or who logs out, retains a live subscription window that still executes queries/mutations. The gap was confirmed on Shopify's GraphQL subscription endpoint.
2. **IDOR→SQLi escalation via WS** (April 2026 writeup, fintech target): a high-entropy 25-digit document ID was treated as "safe from brute force." Researcher fuzzed the WS parameter with `||'|'||` PostgreSQL concatenation → verbose error-based SQLi → leaked the high-entropy IDs → fed those back into the original WS IDOR endpoint. The chain bypasses entropy-based "this ID is unguessable" logic entirely.
3. **Hidden undocumented ops**: keep-alive WS connections (`{"type": "ka"}`) often wrap undocumented internal operations that never appear in the REST surface or the introspection schema. Reverse-engineering `main.js` for `graphql-ws` invocations is the discovery vector.

### Topic 2: IDOR — Authorization Bypass Techniques Not in Current Doc

The IDOR checklist and recent H1 disclosures surface a cluster of bypass patterns we don't have in `class-idor.md`:

- **Outdated API version** — `/v1/` endpoint may lack authz enforced on `/v2/`: swap the version in the path when a 403 blocks the current version.
- **Array/JSON-type coercion** — some authz middleware checks `id === req.userId` but `[123] !== 123`, so wrapping the id in an array `{"id": [123]}` bypasses the strict comparison.
- **Filter-object IDOR** — REST and GraphQL APIs often expose `filter: { userId: "X" }` or `?accountId=X` buried in a POST body or nested JSON; the outer endpoint appears self-scoped but the filter bypasses it.
- **High-entropy UUID ≠ unexploitable** — the April 2026 chain proves this: if ANY adjacent endpoint on the same resource leaks IDs (SQLi, verbose error, referrer, postMessage), entropy is irrelevant. Don't mark UUID-IDOR as "needs-harvest/known-issue" without also checking for injection on the same path.
- **Content-type switching** — changing `application/json` → `application/xml` or `text/plain` sometimes routes through a different middleware stack that skips authz validation.

**Source:** https://ahmed-tarek.gitbook.io/security-notes/owsap-top-10-2025/a01-broken-access-control/checklists/idor-checklist  
**Source:** https://hackerone.com/reports/3382343
