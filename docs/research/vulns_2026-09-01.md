## 1. CVE-2026-72898 — Metabase unauth SQLi → admin takeover, CVSS 10.0, KEV + actively exploited (confirmed real-world victims) ★★
- **What:** `POST /api/session/reset_password` builds SQL from unsanitized input in the password-reset flow (CWE-89) → unauthenticated remote attacker injects SQL into the app DB → full admin takeover of the Metabase instance. Zero auth, zero interaction, network-reachable.
- **Affected:** 0.58.0–0.58.23 / 0.59.0–0.59.20 / 0.60.0–0.60.16 / 0.61.0–0.61.10 / 0.62.0–0.62.8 / 0.63.0–0.63.4 (Enterprise builds are the matching 1.x line). Fixed: 0.58.24, 0.59.21, 0.60.17, 0.61.11, 0.62.9, 0.63.5. Added to **CISA KEV 2026-08-11**; confirmed pre-patch victims include Framework, Anaconda, n8n (Metabase Cloud tenants) per Dataminr.
- **Detect (unauth, SAFE — no injection needed):** Metabase leaks version info on the unauthenticated `GET /api/session/properties` endpoint (`"version":{"tag":"v0.6x.y"}`) and via `window.MetabaseBootstrap = ` embedded in the raw page body — both fingerprint-only, no exploitation. This is a genuine safe version-in-range primitive, not a KEV-tech-class-without-version situation — treat version-in-range as a strong LEAD per doctrine (the actual injection is a live SQLi exploit, still needs authorized-testing gate before firing per our confirm-primitive rule — the `'` vs `''` differential on this specific endpoint would work but touches the app DB and a live-exploited-in-the-wild CVE, so this is n-day-race territory, not autonomous-fire).
- **Action:** run a `recon-mood metabase` / fingerprint sweep for any in-scope host serving Metabase; version-match ≤ the ranges above = strong same-class LEAD (real fingerprint, not tech-class guess) for the operator to confirm-then-stop. ~11,000 internet-facing self-hosted instances found scanning, 4,309 potentially vulnerable, 97%+ of matched-branch hosts still unpatched as of the runZero scan — this is a wide, live n-day window.
- **Sources:** [IONIX](https://www.ionix.io/threat-center/cve-2026-72898/), [Offsec](https://www.offsec.com/blog/cve-2026-72898-2/), [runZero](https://www.runzero.com/blog/metabase/), [Dataminr](https://www.dataminr.com/resources/intel-brief/cve-2026-72898-exposes-thousands-of-self-hosted-instances/)

## 2. WATCH (low priority) — CVE-2026-40175, Axios CRLF header injection → claimed AWS IMDSv2/cloud-metadata compromise chain, CVSS 9.9
- **What:** Axios fails to reject CRLF in outgoing header values; chained with a *separate* prototype-pollution bug in another dependency, this could become header injection → request smuggling/SSRF → IMDSv2 bypass → cloud credential theft. Fixed in axios 1.15.0/0.3.1.
- **Why downgraded:** independent analysis (Aikido) found it **not realistically exploitable** in standard Node.js — Node's built-in header validation blocks the CRLF injection in normal setups; the vector needs a non-standard Axios transport AND a separate prototype-pollution vuln already present. Not a standalone unauth primitive we could ever safely fire externally, and not remotely fingerprintable as "vulnerable" vs "not" from outside.
- **Action:** no action — flagging only because it touches our top-tech AWS/cloud-metadata surface; don't add to any worklist.
- **Sources:** [GitHub Advisory GHSA-fvcv-3m26-pcqx](https://github.com/advisories/GHSA-fvcv-3m26-pcqx), [Aikido](https://www.aikido.dev/blog/axios-cve-2026-40175-a-critical-bug-thats-not-exploitable)
