This pass found one genuinely new item hitting our top-tech list (Apache HTTP Server) plus two NGINX HTTP/3 CVEs worth a version note (our detected in-scope build, 1.29.7, is confirmed OUT of range for both — recorded so future rescans don't re-flag it).

## 1. CVE-2026-23918 — Apache HTTP Server mod_http2 double-free → unauth RCE, CVSS 8.8 ★
- **What:** Double-free in `mod_http2` stream-cleanup logic. Attacker sends crafted HTTP/2 HEADERS frames followed by an early `RST_STREAM` with a non-zero error code → heap corruption → crash, potentially RCE. Zero auth, zero interaction, network-reachable.
- **Affected:** Apache HTTP Server **2.4.66 only** (very narrow window). Fixed in **2.4.67**.
- **Detect (unauth, in-range-verifiable):** `Server:` header exact-version string (only leaks if `ServerTokens Full`/default — many hardened configs suppress this) or jsintel/Wappalyzer version fingerprint. No public PoC/IOC yet per sources.
- **Action:** version-match (exactly 2.4.66) = LEAD. Exploit itself is a crash/RCE primitive — do NOT fire (destructive, not a safe unauth confirm). Worth a one-off `recon-mood apache` sweep for the `Server: Apache/2.4.66` string; given the narrow single-version window, hit rate will likely be low but cheap to check.
- **Sources:** [Orca Security](https://orca.security/resources/blog/apache-http-server-http2-vulnerability-cve-2026-23918/), [Berkeley ISO](https://security.berkeley.edu/news/critical-apache-2466-http2-flaw-allows-rce-dos-cve-2026-23918)

## 2. WATCH — NGINX HTTP/3 pair, CVE-2026-42530 + CVE-2026-40460 — our detected version (1.29.7) is confirmed NOT in range
- **CVE-2026-42530** — use-after-free in `ngx_http_v3_module` via a crafted HTTP/3 session that reopens a QPACK encoder stream → worker crash / possible RCE if ASLR bypassed. **Affected: NGINX Open Source 1.31.0–1.31.1 only**, fixed in 1.31.2. Requires HTTP/3 QUIC explicitly enabled in config (not default). **Our fingerprinted in-scope Nginx build is 1.29.7 — confirmed OUT of this range**, so no action against current corpus; only relevant if a rescan turns up a host on 1.31.x.
- **CVE-2026-40460** — QUIC lacks a TCP-style handshake; NGINX's HTTP/3 handling can propagate attacker-forged source IPs into request logic, bypassing IP allow/deny rules, `limit_req`, and `geo` module ACLs. Affected version range and fix version were not confirmed by available sources (F5 KB article gated) — treat as unconfirmed until a primary advisory is found. Also config-dependent (target must rely on IP-based ACLs over HTTP/3).
- **Action:** no probe — both require HTTP/3 enabled (not remotely confirmable without an ALPN/protocol check) and neither has a safe unauth confirm primitive. Recorded so the nginx KB doesn't re-research this on the next pass; re-check if `recon-mood nginx` ever surfaces a 1.31.x host.
- **Sources:** [SOCPrime](https://socprime.com/blog/cve-2026-42530-critical-nginx-http-3-flaw-can-trigger-dos-and-possible-rce/), [SentinelOne](https://www.sentinelone.com/vulnerability-database/cve-2026-40460/)
