# Research digest — vulns — 2026-09-01 (pass 4)

Prior passes today covered GiveWP, Avada theme, Metabase (CVE-2026-72898), Apache mod_http2 (CVE-2026-23918), and the NGINX HTTP/3 pair (confirmed out-of-range for our 1.29.7). This pass found the highest-value item of the day: two **unauthenticated Critical RCEs in the same Next.js security release** (Aug 25, 2026) — one of them hits an endpoint (`/_next/image`) that is near-universal on Next.js sites and directly overlaps our WCD lane's existing awareness of that path.

## 1. NEW — Next.js August 2026 security release: 2 unauth Critical RCEs, one broadly exposed ★★★

### 1a. Image Optimization API AVIF → unauth RCE (libheif heap overflow), GHSA-2xp9-vwfh-vxw4 / upstream GHSA-g89c-p67h-r497
- **What:** The `sharp` image library's bundled `libheif` has a heap overflow when decoding a malicious AVIF file. Next.js's built-in Image Optimization API (`/_next/image?url=...`) decodes attacker-supplied images server-side — point it at (or upload/reference) a crafted AVIF and the decode triggers RCE on the Next.js server. **Zero auth.**
- **Affected:** Next.js **10.0.0 – 15.5.23** and **all 16.x through 16.3.2** — i.e. effectively every actively-run version. Fixed in **15.5.24** / **16.3.3** (Aug 25, 2026); the patch's actual fix is to **disable AVIF optimization** pending an upstream libheif fix (not a code fix in Next.js itself).
- **CVSS:** 9.5 (v4).
- **Who's exposed:** Self-hosted (Docker/Node/PaaS) Next.js deployments using the default Image Optimization loader with default `images.formats` (AVIF negotiation is automatic based on the requester's `Accept` header — no special config needed to be exposed). **Vercel-hosted apps were already protected platform-side** before the public release — so this only matters for our self-hosted targets, which is most of them.
- **Detect (unauth, in-range-verifiable):** confirm the host is Next.js (build-id/`x-powered-by`/jsintel `_next/static` bundle) + version < the fixed builds, AND confirm `/_next/image?url=<same-origin-or-allowed-remote>&w=...&q=...` actually responds with a transcoded image (proves Image Optimization is live, not disabled). This is exactly the endpoint our `class-cache-deception.md` doctrine already flags as a "PRODUCT-CLASS dup-magnet" for WCD — now it's also an RCE surface on unpatched versions.
- **Action — DO NOT PROBE with a real malicious AVIF** (crafting the heap-overflow trigger is exploitation/destructive, out of our safe-unauth-primitive doctrine). Version-match + live `/_next/image` endpoint = strong LEAD; hand to operator for confirm-then-stop on any in-scope self-hosted Next.js target. Given the near-universal affected range, a `recon-mood nextjs` sweep is worth running.
- **Sources:** [Next.js official advisory](https://nextjs.org/blog/august-2026-security-release), [GitHub advisory](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4), [The Hacker News](https://thehackernews.com/2026/08/nextjs-patches-critical-avif-and.html)

### 1b. Windows-hosted path traversal → unauth RCE, CVE-2026-75604
- **What:** Apps using **both** the Pages Router and App Router **without Cache Components**, on a **Windows-hosted** server, let attacker-controlled path input in request handling escape the app root → filesystem access outside the app → RCE. No known workaround short of patching.
- **Affected:** Next.js **13.4.0 – 15.5.23** and **16.0.0 – 16.3.2**, **Windows only** (Linux/macOS not affected). Fixed in 15.5.24 / 16.3.3.
- **CVSS:** 9.0. Public PoC exists: [rafabd1/CVE-2026-75604-poc](https://github.com/rafabd1/CVE-2026-75604-poc).
- **Detect:** same version-fingerprint as above, but only relevant if the target is Windows-hosted (check response headers/timing/IIS-front signatures — most of our in-scope Next.js hosts are Linux/container-hosted, so this narrows hit-rate hard on our corpus vs. 1a).
- **Action:** LEAD only, same non-probe rule (public PoC exists but it's a live RCE — exploitation, not a safe unauth primitive). Low priority relative to 1a given our corpus skews Linux-hosted.
- **Sources:** [Next.js official advisory](https://nextjs.org/blog/august-2026-security-release), [GitHub advisory](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36)

## 2. NOTED, deprioritized — CVE-2026-65640 WordPress 7.0.4 (Imagick/Ghostscript RCE via malicious PNG)
Initial search framing suggested unauthenticated; **it is not** — requires an **Author-level+ authenticated account** to upload the malicious Postscript-in-PNG payload, and only affects installs using Imagick+Ghostscript. Doesn't fit our unauth-first doctrine or human-in-the-loop authed-IDOR lane. CVSS 8.8, fixed in WordPress 7.0.4 (Aug 12, 2026), backported to all branches ≥4.7. Skipping further action — noted only so a future pass doesn't re-surface it as new. [SecurityWeek](https://www.securityweek.com/wordpress-7-0-4-patches-remote-code-execution-vulnerability/amp/)
