# Research digest — vulns — 2026-09-01

## 1. NEW — CVE-2026-82222, GiveWP (WordPress donation plugin) unauth PHP Object Injection → RCE, CVSS **10.0** ★★
- **What:** `safeUnserialize()` helper is broken — the donation front-end flow feeds attacker-controlled serialized data straight into it, which deserializes into a gadget chain GiveWP itself ships (no external plugin needed for the gadget). Requesting any front-end page after submitting the crafted donation triggers unserialize → command execution. **Fully unauthenticated.**
- **Affected:** GiveWP ≤ 4.16.7.1. Fixed in **4.16.7.2** (released 2026-08-27; publicly disclosed 2026-08-28 — this is a live same-week n-day window).
- **Prerequisite:** site needs **one published donation form + one active payment gateway** (visible in rendered page, no probe needed).
- **Detect (unauth, in-range-verifiable):** `/wp-content/plugins/give/readme.txt` → `Stable tag`, or `give`/`givewp` string in jsintel JS bundles. Version ≤4.16.7.1 + live donation form = strong LEAD.
- **Action:** don't fire the actual unserialize payload autonomously (crosses into exploitation/RCE). Flag for `recon-mood wordpress`/`givewp` sweep on our WP-fingerprinted hosts, hand to operator.
- **Pattern note:** third unauth-unserialize/gadget-chain WP bug flagged in 3 weeks (WooCommerce Subscriptions 2026-08-16, this one) — worth a standing `recon-mood` alias for "wordpress unserialize" fingerprinting, not just one-off version checks.
- **Sources:** [Patchstack](https://patchstack.com/articles/unauthenticated-php-object-injection-to-remote-code-execution-on-givewp/), [BleepingComputer](https://www.bleepingcomputer.com/news/security/givewp-wordpress-donation-plugin-flaw-lets-hackers-execute-server-commands/), [IONIX](https://www.ionix.io/threat-center/cve-2026-82222/)

## 2. WATCH — CVE-2026-18431, Avada theme + Fusion Builder — zero-click chain to RCE, details embargoed
- **What:** 6-weakness chain (auth-bypass + input-validation + trust-boundary + file-handling) → attacker-controlled file write → PHP execution. Wordfence is deliberately withholding technical detail (exploit specifics not yet public) to give admins time to patch.
- **Affected:** Avada theme ≤7.16, Fusion Builder ≤3.16 (Fusion Builder is a mandatory dependency, so every Avada site is in-range). Fixed: Avada 7.16.1 / Fusion Builder 3.16.1, released **2026-08-26** — 6 days old.
- **Detect:** no public fingerprint/endpoint yet (details withheld). Avada is high-install-base (1M+ sales) — worth a version-string watch (theme `style.css` header / jsintel) on WP hosts now, re-check once a technical writeup drops (expect one within 1-2 weeks per typical Wordfence embargo pattern).
- **Action:** LEAD-only, nothing to probe yet. Re-check this CVE in next week's digest for exploit details.
- **Source:** [BleepingComputer](https://www.bleepingcomputer.com/news/security/critical-avada-wordpress-theme-flaw-enables-zero-click-rce/)
