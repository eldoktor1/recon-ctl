# Research digest — vulns — 2026-07-28

## 1. NEW — PHP core: two coordinated CVEs across all 4 supported branches (CVSS 8.2 + 4.8) — hits our top-tech PHP directly
- **CVE-2026-12184** (CVSS 8.2): HTTP stream-wrapper handling of a failed TLS handshake frees the stream object but a cleanup routine keeps operating on it — remote server can crash the entire PHP-FPM pool (DoS, not RCE). Any PHP code making outbound HTTPS requests (`file_get_contents`, `SoapClient`, webhooks, SSRF-adjacent code) is exposed to a malicious/MITM'd remote server.
  - **Affected:** PHP < 8.3.32, < 8.4.21, < 8.5.6 (8.2.x unaffected per PHP's own advisory).
  - **Detect:** version via `X-Powered-By`/error banners/`phpinfo` leaks; this is a **server-initiates-outbound** bug, not directly remotely triggerable against us — relevant mainly if we control an SSRF/webhook target that a PHP backend calls, or for our own probe-safety awareness (a target's outbound TLS to an interactsh canary won't crash it, so no conflict with our SSRF lane).
- **CVE-2026-14355** (CVSS 4.8): heap corruption in `openssl_encrypt()` with AES-WRAP-PAD cipher mode. Affected < 8.2.32, < 8.3.32, < 8.4.23, < 8.5.8. Narrow — only apps explicitly using AES-WRAP-PAD; low direct value for unauth recon, noted for completeness.
- **In-range-verifiable unauth:** version-only (LEAD per doctrine); CVE-2026-12184 has no safe unauth remote trigger against a target from our side (it's the *target* acting as TLS client) — treat as inventory/patch-lag signal, not a probe target.
- **Sources:** [securityonline.info](https://securityonline.info/php-remote-dos-cve-2026-12184/), [josephcharnin.com deep-dive](https://www.josephcharnin.com/cybersecurity/php-fpm-tls-handshake-dos-cve-2026-12184/), [cybersecuritynews.com](https://cybersecuritynews.com/multiple-php-vulnerabilities-dos/)

## 2. NEW — two more NGINX CVEs land on our fingerprinted `nginx:1.29.7` (module-gated, narrower than 42533/42945)
- **CVE-2026-60005** (CVSS v4 8.8): uninitialized-memory disclosure in `ngx_http_slice_module` — leaks worker process memory when `slice` is combined with unnamed regex captures, or during a background cache-update. **Requires `--with-http_slice_module` build flag** (not default) — narrows applicability vs. the earlier 42533/42945 items.
- **CVE-2026-56434** (CVSS v4 8.3): use-after-free in `ngx_http_ssi_module`, triggered when SSI is enabled + `proxy_pass` + `proxy_buffering off`, and an attacker can manipulate the upstream response (MITM-ish precondition) — narrow deployment pattern, no workaround besides upgrade.
- **Both**: vulnerable 0.8.11/1.15.8 – 1.31.2 → our `nginx:1.29.7` fingerprint stays in-range for both. Fixed 1.30.4 / 1.31.3 / NGINX Plus 37.0.3.1 (**same patch train as CVE-2026-42533** — a host patched for one is patched for all three).
- **Correction/escalation on CVE-2026-42533**: multiple new sources now describe exploitation as "confirmed practical, and in some cases already observed in the wild" (up from our earlier "no known ITW, version-LEAD-only" framing) — bump urgency on any in-scope host still reporting `nginx` < 1.30.4/1.31.3, but per doctrine this remains a **version-range LEAD, never a live trigger** (still no safe external unauth confirmation primitive beyond the `Server:` banner).
- **In-range-verifiable unauth:** version-banner only (both module-gated, not remotely fingerprintable beyond version) — LEAD, same handling as the rest of the nginx CVE table.
- **Sources:** [Orca Security](https://orca.security/resources/blog/cve-2026-42533-nginx-heap-buffer-overflow/), [Beazley Security](https://beazley.security/alerts-advisories/critical-memory-corruption-vulnerabilities-in-nginx-cve-2026-42533-cve-2026--56434-cve-2026-60005), [nginx.org security advisories](https://nginx.org/en/security_advisories.html)
