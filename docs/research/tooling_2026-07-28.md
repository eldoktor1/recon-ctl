# Research digest — tooling — 2026-07-28

## Tooling Watch — 2026-07-28

Checked: bug-bounty recon tool sweep, HTTP smuggling, race conditions, JS secrets, API endpoint discovery, GraphQL scanners. **Nothing cleared the bar for ADOPT or EVALUATE this run** — every candidate found is either lower-signal than what we already run, or unverifiable.

### SKIP — PacketSprinter (richeeta/PacketSprinter)
Burp extension wrapping James Kettle's HTTP/2 single-packet-attack technique for race conditions. 3 stars, not in BApp Store (manual JAR install only), 7 commits. `docs/knowledge/class-race-conditions.md` already documents the same single-packet technique via a working Turbo Intruder script — PacketSprinter is just a UI wrapper around the identical primitive, with far less adoption/vetting. No upgrade.

### SKIP — CLTEcho (HTTP request smuggling)
Marketed as "AI-powered / ML-based anomaly detection" smuggling scanner, updated Jul 16 2026. `class-request-smuggling.md` already standardizes on `HTTP Request Smuggler v3.0` (PortSwigger/Kettle's own Burp ext, three-layer parser-discrepancy detection) — the gold standard for this class. No indication CLTEcho beats it; "AI-powered" smuggling detection is a red flag for marketing-over-substance, not a real technique upgrade.

### SKIP — graphql-scanner (davidfortytwo)
11 stars. Does introspection exposure + resource-pressure probes (alias overloading ~50, fragment explosion ~50, batching ~12) with reproducible curl per finding — genuinely matches our safe/non-destructive doctrine on paper. But `class-graphql.md` already covers this exact ground via **graphql-cop** (`alias_overloading`, `batch_query`, `circular_query_introspection`, depth/cost-limit probes) which we already run in the pipeline. graphql-scanner adds nothing graphql-cop doesn't already give us, at 1/10th the community validation.

### SKIP — unverifiable / low-signal
- **MELTOR** ("crawler + JS-AST parser + fuzzer + endpoint validator") — no confirmed GitHub repo, star count, or maintenance signal surfaced; likely a listicle mention, not a real vetted project. Not actionable without a working repo link.
- **js-snitch** (vavkamil) — remote-JS secret scanner that's just trufflehog+semgrep glued together; we already run trufflehog directly on jsluice-mined JS. No net-new detection capability.
- **Dons JS Scanner** — regex-only JS secret grep with Discord webhook alerting; regresses vs. our trufflehog `--only-verified` + jsluice `secrets` AST-candidate split (this is the exact 53%-FP token-shaped-noise problem our design already solved).

### Noted but not actionable
- Burp Suite Pro's native Repeater **"Send group in parallel"** (recent versions) reportedly does single-packet-style race grouping without any extension. Since we already drive Burp Pro on Windows for authed testing (`reference_burp_pro_interface.md`), this is worth the operator spot-checking next time race-condition testing comes up — but it's a Burp feature-awareness item, not a new tool, so not filed as a KB proposal without hands-on confirmation of the exact PortSwigger version behavior.

No kb-new or kb-proposal this run — nothing surveyed exceeded what's already documented.
