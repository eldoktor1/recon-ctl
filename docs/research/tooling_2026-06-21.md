### EVALUATE — jsluice (BishopFox)

**Repo:** `github.com/BishopFox/jsluice` — Go, actively maintained by BishopFox.

**What it does:** Static JS analysis using an AST parser (not regex). Extracts URLs, endpoint paths, and secrets from JS with semantic understanding — handles template literals, nested object keys, computed paths that regex-based extractors miss.

**Does it beat what we have?** Complementary, not a replacement. `recon_jsintel.sh` likely uses regex-based endpoint extraction + trufflehog for secrets. jsluice's AST pass extracts structurally-embedded paths that regex patterns skip. Running both in parallel widens the endpoint yield with no overlap in false positives.

**Doctrine fit:** Static analysis only — reads already-fetched JS files. Unauth-safe, non-destructive, zero target traffic. Outputs structured JSON (`jsluice urls <file.js>`).

**Verdict: EVALUATE.** Bolt onto `recon_jsintel.sh` as a second-pass extractor after the existing regex/trufflehog pass. Expected gain: deeper endpoint surface from minified/complex JS files, feeding the IDOR candidate ranker with more object-ref routes.

### EVALUATE — x8 (Sh1Yo)

**Repo:** `github.com/Sh1Yo/x8` — Rust, well-regarded in 2025 methodology posts.

**What it does:** Hidden parameter discovery — same job as arjun but in Rust. Differentiator: response diffing is smarter (length + content + structural changes), handles multiple injection points simultaneously, significantly faster.

**Does it beat what we have?** Potentially yes on speed and diffing accuracy. Arjun is Python and can miss params on endpoints where the response variation is subtle. x8's multi-dimensional diffing catches params that only change a small part of a large response.

**Doctrine fit:** GET requests observing response deltas — same safety profile as arjun. Unauth-safe. Check it respects `-t1 --rate-limit` style controls before swapping in.

**Verdict: EVALUATE** as a drop-in replacement or parallel runner for `recon-params arjun`. If rate-control parity confirmed, consider replacing arjun outright (faster + better diffing = strictly better).

### EVALUATE — BadDNS (PortSwigger)

**Repo:** `github.com/PortSwigger/baddns` — Python, featured in Help Net Security Feb 2025 ([source](https://www.helpnetsecurity.com/2025/02/03/baddns-open-source-tool-check-domain-subdomain-takeover/)).

**What it does:** DNS auditing for ALL dangling records — including cases where no takeover fingerprint exists yet. Current nuclei takeover templates are fingerprint-gated (known provider signatures). BadDNS catches CNAME/A/NS dangling to decommissioned infra before the community has written a fingerprint for it.

**Does it beat what we have?** Fills a real gap. Our pipeline surfaces `cname-lead` → provider fingerprint match → nuclei confirms. BadDNS adds a pre-fingerprint layer: "this DNS record points nowhere" even when the destination isn't a known takeover-prone service. That's the novel-takeover class most pipelines miss entirely.

**Doctrine fit:** DNS queries only — zero target HTTP traffic. Unauth-safe, non-destructive.

**Verdict: EVALUATE.** Add as a post-subfinder pass on fresh hosts. Output feeds `takeover:cname-lead` candidates for manual review; never auto-claims confirmed. The gap it fills is small but genuine — novel provider takeovers are the ones nobody files a dup on.
