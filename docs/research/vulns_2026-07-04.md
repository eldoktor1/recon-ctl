# Research digest — vulns — 2026-07-04

Three additional items from the third search pass worth noting:

---

**CVE-2026-42530 — Nginx HTTP/3 Use-After-Free** (new, not in digest above)
- Use-after-free in `ngx_http_v3_module` → worker crash / conditional RCE (ASLR-off)
- Detection: any host responding with `Alt-Svc: h3` or advertising QUIC support
- Our ES shows `HTTP/3` as top-5 in-scope tech — this hits a real slice of surface
- Source: [NVD CVE-2026-42530](https://nvd.nist.gov/vuln/detail/CVE-2026-42530)

**CVE-2026-3300 — WordPress Everest Forms Pro ≤ 1.9.12** (KEV-active as of April 2026)
- Unauth PHP code injection → RCE (CVSS 9.8), actively exploited
- Detection: `POST /wp-admin/admin-ajax.php` with Everest Forms action; version via `/wp-content/plugins/everest-forms-pro/readme.txt`
- Source: [CybersecurityNews](https://cybersecuritynews.com/wordpress-plugin-vulnerability-exploit/)

**CVE-2025-1974 — Ingress-NGINX (Kubernetes)** — PoC published 2026
- Unauth RCE from pod network → cluster takeover. Requires pod-network access (not internet-facing direct exploit), but relevant if we have k8s-hosted targets
- Detection: admission webhook port 8443 reachable; `app.kubernetes.io/name: ingress-nginx` in headers; `/nginx-status` exposed
- Source: [Kudelski Research](https://kudelskisecurity.com/research/critical-unauthenticated-remote-code-execution-vulnerabilities-iningress-nginx)

Also: the third agent confirms **Nginx 1.29.7 (our top in-scope version) is within the CVE-2026-42945 vulnerable range** — patched version is ≥ 1.30.1, not 1.31.x as initially stated. Any in-scope host returning `Server: nginx/1.29.7` is a confirmed-in-range LEAD for the n-day lane.
