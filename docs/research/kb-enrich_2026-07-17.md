# Research Digest — kb-enrich (2026-07-17)

Focus: `class-sqli.md` was the thinnest of the money-class docs (21 lines, no WAF-bypass/ORM/second-order/JSON coverage, last touched 2026-07-03) while `class-idor`/`class-graphql`/`class-ssrf` all already have entries dated 2026-07-14 — so this run concentrates depth on SQLi instead of re-covering ground those three got three days ago.

## 1. WAF-bypass encodings (new — the doc had zero evasion content)
Concrete payload-level bypasses, useful before invoking sqlmap tamper scripts:
- Inline comment splitting: `SELECT/**/password/**/FROM/**/users` — defeats regex WAFs anchored on `\s+`.
- Parenthesis-as-delimiter: `SELECT(password)FROM(users)` — rarely fingerprinted.
- URL-encoded newline: `SELECT%0apassword%0aFROM%0ausers` — survives a single WAF decode pass that doesn't match DB-side normalization.
- Case randomization (`uNiOn SeLeCt`) + double URL-encoding (`%2555NION`) still work against naive signature matchers.
- sqlmap: `--tamper=space2comment,randomcase` as a starting combo; 50+ tampers exist, pick per-WAF (Cloudflare/AWS WAF/ModSecurity each favor different ones).

## 2. ORM escape-hatch injection (new class of finding to look for)
Every ORM has a raw-query escape hatch that reintroduces classic string-concat SQLi — worth grepping jsintel-mined JS/backend hints for:
- Django `.raw(f"... WHERE username = '{username}'")`
- SQLAlchemy `db.execute(text(f"... WHERE name = '{name}'"))`
- Any endpoint whose behavior differs from the rest of the app's parameterized ORM calls (inconsistent error format, no framework-level escaping) is a signal a raw-query path exists underneath.

## 3. Second-order / stored SQLi (new — currently entirely missing from the doc)
Payload stored harmlessly at one endpoint (e.g. `admin'--` as a registration username), fires later when reused unparameterized in a different query (password reset, admin lookup, audit log render). Automated single-request scanners (including our own `'` vs `''` differential) miss this entirely — requires manually tracing a stored value across endpoints. Worth flagging as a manual-follow-up whenever a text field (username, display name, address line) accepts SQL metacharacters without rejection at write time.

## 4. JSON-context bypass payloads (new)
For JSON-body APIs where classic `1=1` literals get WAF-fingerprinted:
- PostgreSQL JSON containment: `'/*/OR/*/'{"a":1}'::jsonb @> '{"a":1}'::jsonb--` (rewrites `OR 1=1` as a JSONB containment check).
- MySQL: `'/*/OR/*/JSON_EXTRACT('{"a":1}','$.a')=1--` (numeric-equality bypass avoiding `1=1`).
Both avoid the literal token patterns legacy WAF signatures match on.

## 5. NoSQL/MongoDB operator injection (adjacent — worth a short section since JSON-API targets can be Mongo-backed)
- Auth-bypass: `{"username":"admin","password":{"$ne":null}}` — replaces password with an operator, matches any non-null hash.
- `$where` JS-eval injection: `'; return true; //` closes the literal inside a `$where` clause, Mongo evaluates as JS → every doc matches. `sleep()` inside `$where` gives a time-based oracle equivalent to `SLEEP()`.
- Detection signal: a JSON body field that normally takes a string/number returns different behavior when sent as a nested object (`{"$gt":""}` etc.) — classic sign the backend passes JSON straight into a query filter.

## 6. Timing-oracle alternatives when `SLEEP()`/`pg_sleep()` is revoked (new)
If DB-level sleep functions are locked down (increasingly common hardening), alternate CPU/memory-burn timing channels still work as blind oracles: `generate_series(1,10000000)` (CPU burn), `repeat('a',1<<27)` (memory pressure), or a recursive CTE counting to ~5e7 — all produce a measurable delay without needing the sleep grant.

## 7. Fresh CVEs — ⚠️ UNVERIFIED, do not act without NVD/version confirmation
- **CVE-2025-1094** — libpq encoding-confusion (BIG5 client / EUC_TW server mismatch defeats `PQescapeLiteral` quote neutralization); reportedly patched Feb 2025 across PostgreSQL 13.19–17.3. If real and in-range, this is a genuine escaping-bypass class worth version-checking any PostgreSQL target on.
- **CVE-2026-42208** — claimed pre-auth SQLi in a LiteLLM-style AI-gateway, reportedly exploited ~26h post-advisory. Flag: LLM-gateway/AI-infra proxies are an emerging under-tested SQLi surface class generally, independent of whether this specific CVE ID is real.
- **CVE-2026-40906** — claimed injection in an ElectricSQL-style Postgres replication-sync API (`/v1/shape`). Flag: replication/sync APIs (CDC endpoints, logical-replication HTTP shims) are a fresh, rarely-tested injection surface worth remembering as a class even if this specific CVE doesn't verify.

These three CVE numbers must be NVD/vendor-advisory verified before minting anything — treat as LEAD-class awareness only, same as every other KEV/CVE hallucination-risk item in our doctrine.
