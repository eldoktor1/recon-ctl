# Research digest — vulns — 2026-08-22

## 1. NEW — Forminator (WordPress plugin) CVE-2026-15748 — unauth arbitrary file upload → RCE, published TODAY-ish (Aug 17) ★★
- **What:** `handle_file_upload()` blocklist does exact-key matching on file extensions/MIME types, bypassed with pipe-alternative MIME-type keys; combined with the public form-submission handler trusting attacker-controlled upload-field config, this lets an unauthenticated visitor upload an arbitrary (`.php`) file → RCE. Same bug family as Elementor Pro (2026-08-20 digest) — extension-blocklist-bypass-via-upload is now a recurring WP pattern this month, worth treating as a class, not a one-off.
- **Affected:** Forminator ≤ 1.56.1. Fixed in **1.56.2** (released 2026-07-31); CVE published 2026-08-17 — patch has been out ~2.5 weeks, so unpatched sites are laggards but this is still a live n-day window (300k+ active installs per SecurityWeek).
- **CVSS:** 9.8. **Prerequisite:** the site's Forminator form must contain both a **File Upload field** and a **Select field** — not universal, but common on WP contact/application forms.
- **Detect (unauth, in-range-verifiable):** `/wp-content/plugins/forminator/readme.txt` → `Stable tag`; also fingerprint via `forminator` string in jsintel JS bundles. Then check the rendered form DOM for a file-upload + select-field pair (no probe needed, visible in page source).
- **Action:** version-match (≤1.56.1) + form-with-upload+select present = strong LEAD, same tier as Elementor Pro. Don't fire the MIME-bypass upload autonomously (crosses into exploitation) — flag for `recon-mood wordpress`/`forminator` sweep, hand to operator for confirm-then-stop.
- **Sources:** [The Hacker News](https://thehackernews.com/2026/08/forminator-wordpress-flaw-can-enable.html), [SecurityWeek](https://www.securityweek.com/300000-wordpress-sites-potentially-exposed-to-hacking-due-to-form-plugin-flaw/)
