# Recon Pipeline Recovery - 2026-05-07

## Issue
After migrating the recon system into a Git repository, the Discord bot and live recon supervisor flow stopped working.

## Root Cause
The repo migration kept the newer helper scripts but missed several required runtime scripts, including:
- recon_discord_bot.sh
- recon_discovery.sh
- recon_validate.sh
- recon_hot_seed.sh
- recon_scope_watch.sh
- recon_takeover_hunter.sh

The daemon in the repo also did not launch the Discord bot or the newer V2.1/schedule loops.

## Recovery Applied
Used recon_recovery_pack to safely restore missing scripts into scripts/ and recreate compatibility symlinks in the home directory.

The restore script backed up replaced files under:
.recovery_backups/<timestamp>/

## Validation
- Bash syntax checks passed for all scripts.
- recon_ctl stop/mode/start/health completed successfully.
- Daemon launched validator, discovery, hot-seed, scope-watch, takeover hunter, schedule, CVE, nuclei, and Discord bot loops.
- Discord bot started and detected the !health command.
- Elasticsearch health was green with existing recon_alive data intact.

## Notes
Do not remove the home-directory compatibility symlinks yet. Multiple scripts still expect ~/recon_*.sh paths.
