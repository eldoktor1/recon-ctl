## 🔴 BROKEN

### B1 — Re-judged FPs cannot be retracted once `reported` → 6 known false positives stranded in the submit queue · APPLIED
- **Where:** `engine/state.py` `record_ai_verdict()` (was line 349).
- **Wrong:** an `fp` verdict dismissed only via `transition(..., "dismissed", expect="confirmed")`.
  The optimistic lock `expect="confirmed"` makes the dismiss a silent no-op for any finding
  already advanced to `reported` — even though `EDGES` (state.py:32) explicitly permits
  `reported -> dismissed`.
- **Evidence:** live DB `~/recon/v3/findings.db` — 6 of 7 rows in state `reported` carry
  `ai_verdict='fp'` (ids 3,4,5,6,7,14, all takeover re-audits killed by the 99%-FP takeover
  gates); only id 28 (graphql introspection) is genuinely `real`. All 6 remained in
  `~/recon/v3/reports/review_queue.jsonl` + `.md` report files presented as "HUMAN review +
  submit." A re-judged FP must be pulled from the review queue, not just from `confirmed`.
- **Fix applied:** dismiss from whatever non-terminal state the finding is in
  (`expect=row["state"]` when state ∈ {confirmed, reported}); guarded against terminal states.
  This stops recurrence. Compiles; `state.py ai-accuracy` still runs (reviewed_total=40).
- **Follow-up (REC):** the 6 already-stranded rows + their `review_queue.jsonl` entries / report
  `.md` files need a one-time prune (re-run the verdict, or delete the dismissed rows from the
  queue artifact). The reporter is append-only and won't retract them on its own.

### B2 — `recon-ai monitor` read a file nothing writes anymore · APPLIED
- **Where:** `scripts/recon_ctl.sh` `cmd_ai` `monitor|health)` case (was lines 1210-1220) + its
  help line (was 1268).
- **Wrong:** read `${AI_MONITOR_OUT:-$BASE_DIR/state/ai_monitor_latest.json}`. That JSON is only
  ever written by the deleted `recon_ai_monitor.sh`; `AI_MONITOR_OUT` is set nowhere. The
  subcommand always printed "(no assessment yet)".
- **Evidence:** grep across scripts/+tools/ = zero writers of `ai_monitor_latest.json`; the
  MONITOR role moved to the 2IC routine (posts to `#ops` on trouble only).
- **Fix applied:** removed the `monitor|health)` case + its help line; the `recon-ai` status line
  no longer implies a daemon "batch/cycle" (clarified it as on-demand verify + 2IC).
